# CAT独立運転操作とHUD

## 目的

CATはCreate標準の運転台操作・表示とは独立した、高性能運転台としての操作系とHUDを提供する。
これは将来のCAT Controller BlockをCreate標準の運転台に代わる運転席として扱う設計方針に沿う。
CATが追加するこの独自ブロックの名称は**マスコン**とする。

## 確定要件

- 前進と後進は、ユーザーが設定画面で割り当てられるCAT専用キーにより切り替える。
- CAT独立操作が当該列車の操作入力を受け付ける間、従来のCreate運転操作である`W`/`S`による
  前進・後進指令は無効とする。単にCAT入力を追加して両方の指令を競合させてはならない。
- CATはCreate標準HUD・開発用Debug HUDとは別に、独立した運転HUDを提供する。操作と表示は一体の
  CAT運転体験として設計し、Create標準のHUDが存在することを前提に必要情報を省略してはならない。
- キー割当の初期値、操作権限を得る正確な条件、入力競合時の優先順位、HUDの最終レイアウトと表示項目は
  未確定である。実装担当はこれらを推測して決めてはならない。

## Phase 9の駅距離表示方針

Phase 9の独立HUDは、単一のNavigation destinationだけを「駅までの距離」として表示する方式を採らない。
進行可能な近傍駅をおおむね4駅まで提示し、各駅への距離を示す方向で設計する。手動運転時に単一destinationの
距離が未取得となる現在の問題は、この方式の要件定義と共に扱う。

おおむね4駅という数は画面設計の目安であり、探索深さ・分岐処理・到達可能性・駅名の取得・ソート規則・
欠損時表示はPhase 9の未解決事項である。

## 責務境界

```text
Client: CAT専用キー入力 / 独立HUD
             ↓ 意図だけを送る
Server: 列車単位の操作権限確認 / TrainController状態更新 / 安全制約
             ↓
Create標準のtargetSpeed追従経路
```

Clientは物理値・`Train.speed`・安全制約を直接変更しない。Serverが列車単位で入力を検証し、通常CAT制御と
同じ`Train.targetSpeed`経路へ統合する。実際のpacket、キー登録、画面、権限判定の設計はPhase 9で確定する。

## 非対象

- 現時点でのJava実装
- Create標準の全キーバインドをゲーム全体で無効化すること
- 開発用Debug HUDを最終HUDとして流用すること
- BrakingCurve、ATO、TASC、EBの挙動決定

## 計算エラー状態

BrakingCurve等のCAT制御計算が、有限で検証可能な値を得られない場合、列車単位のCATエラー状態へ入る。
停止点が前方にないことはエラーではない。対象となるのは、NaN/無限大、単位不明、基準加速度・Profile・
反復上限などが成立しない計算不能状態である。

- マスコンは原因を識別できる`エラー状態`を表示し、ユーザーへ通知する。
- 自動運転は停止し、CATは新たな力行・常用制動の指令を出さず、列車は惰性運行へ移る。
- エラー原因が解消されても自動復帰してはならない。
- 復帰操作はレンチ使用だけとする。処理順は、レンチ使用、回復条件検証、条件を満たす場合だけエラー解除、
  満たさない場合は解除不能理由の通知、とする。

CAT中立ノッチNは、`targetSpeed = 0`かつ製品版NotchControllerが`accelerationMod = 0`を返す状態とする。
Create 6.0.8では`targetSpeed = 0`だけなら標準減速になるため、この二つを同じtickで適用しなければならない。
製品版ノッチ制御はPhase 6で実装する。`Train.speed`を直接変更してはならない。
