# 制動モデル

## 目的

BrakingCurveは、停止点までの残距離と利用可能な制動性能から、常用制動で安全に
停止するための**最大許容速度**を計算する。BrakingCurve自身は最終targetSpeed、
ノッチ選択、停止位置の決定を担当しない。

## 確定している原則

- 常用制動とEBは、Createの `train.acceleration()` を基準値として構築する。
- 制動応答時間は10 tick（0.5秒）とする。
- 安全性は距離余裕と減速度安全係数の両方で扱う。
- 減速度は固定値ではなく、速度依存のテーブル `a = f(v)` とする。
- 常用制動とEBは別の制動性能テーブルを持つ。
- テーブル区間の補間は線形補間とする。
- 勾配・重量・編成長は将来入力として拡張できる構造を確保するが、V1の実効計算値は未決定。

## 設計中の性能モデル

日本の電車の常用制動を基本思想とし、B1〜B7は等間隔の比例関係を基本案とする。
将来的にはB7の速度依存基準曲線へノッチ倍率と個別補正を掛けるハイブリッド方式を
許容する。

具体的なB1〜B7倍率、B7・EB性能、速度点、低速域特性は試走データで決めるため、
現時点では正式値として固定しない。

最終B1〜B7は、B1のCreate強制停車を含む停止距離から個別に決めない。B2〜B7の定常減速度を
主な測定根拠とし、各速度点で等間隔系列を当てはめてB1を外挿する。制動の大きさを正値
`d_n(v) = -a_Bn(v)`とすると、最終系列は次で表す。

```text
d_n(v) = d_1(v) + (n - 1) × Δ(v)    (n = 1 .. 7)
```

各速度点でB2〜B7の測定値へ上式を最小二乗で当てはめ、`d_1(v)`と`Δ(v)`を求める。同じ二値から
B1〜B7全てを再構成することで、測定誤差による不均一をProfileへ残さない。B1の実測は応答・
定常減速度と外挿結果の妥当性確認に用いるが、B2〜B7を当てはめる最終Profile導出の入力にはしない。
特にCreate強制停車を含むB1停止距離はフィット入力にしない。

## ノッチ制御の責務分離

常用制動を自動で選択・適用する仕組みは必要である。ただし、離散的なノッチの性能、
ノッチを選ぶ判断、Createへ制動能力を反映する境界処理を一つのクラスまたは一つの
数式に混在させない。

| 要素 | 責務 | 行ってはならないこと |
| --- | --- | --- |
| `NotchProfile` | 各BノッチとEBについて、速度から利用可能な加減速度を返す。速度依存表、補間、倍率、個別補正を保持する。 | 停止点や信号を見てノッチを決定すること。 |
| `NotchSelector` | ATO等から受けた走行意図と制約を基に、要求ノッチ（`commandedNotch`）を決定する。 | ノッチごとの物理性能を独自に計算・複製すること。 |
| `NotchResponseModel` | 要求ノッチのProfile値へ実効加減速度を変化させる応答を管理する。最後に遷移が完了した離散ノッチを`appliedNotch`として保持し、制動応答時間10 tickをこの境界で扱う。 | 制動距離・最大許容速度の計算を持つこと。 |
| Create境界の適用部 | `effectiveAcceleration`を、Create標準の速度追従経路へ渡す。 | `Train.speed`を直接変更すること、CAT側でCreateの加速度値を直接書き換えること。 |

`BrakingCurve`は残距離とProfileから最大許容速度を求める数学部品であり、上表の
`NotchSelector`の代わりにはならない。ATOは最大許容速度などの制約を用いて目標の
走行状態を決め、`NotchSelector`がその実現に必要なノッチを選ぶ。

現在のCreate連携では、通常制御の速度変更は`Train.targetSpeed`とCreate本来の
速度追従経路を通す。不変条件として、ノッチ機構は`Train.speed`を直接変更しない。
Createの加速度修飾を渡す正確な箇所・単位・適用順は、Java実装を依頼する時点で
Create 6.0.8実ソースにより確認する。

### Phase 5Aの試験と自動選択の順序

Phase 5Aの目的は、各ノッチの実測性能を取得し、Profileを確定することである。
この段階の試験運転では、同じ初速・同じ線路条件でB1〜B7（および必要ならEB）を
**固定指定**できなければならない。自動選択だけで走らせると、選択判断とノッチ性能を
分離して評価できないためである。

そのため、試験用のノッチ機構は次の二つの選択モードを区別する。

| モード | 用途 | Phase 5Aでの扱い |
| --- | --- | --- |
| `FIXED_FOR_TEST` | 指定したノッチを維持し、速度別の減速度・応答・停止距離を測る。 | 必須。 |
| `AUTO` | ATOの制約・速度差・残距離に応じて要求ノッチを選ぶ。 | Profileと選択規則が確定してから検証する。 |

この区別は試験のための設計上のモードであり、最終的なユーザー設定や操作UIの仕様を
先取りして決めるものではない。Phase 5Aで得るログには、少なくとも指定ノッチ、
`commandedNotch`、`appliedNotch`、Profileが返した加減速度、実測速度、実測加速度、
残距離、経過tickを対応付けて記録する。既存の独立したTrainDataDebuggerへCAT制御依存を
追加するのではなく、Phase 5Aの制御試験記録として別途扱う。

### 試験用の持続制動と本実装の停止制御は別物

Create標準Navigationは自身の`train.acceleration()`を前提に制動距離を再計算するため、
Phase 5AでB7のような強い外部制動だけを追加すると、Navigationが再加速要求を出して固定ノッチの
性能を連続測定できない。この問題を分離する目的で、将来必要なら「減速開始後はtarget 0を停止まで
保持する」試験専用治具を設けられる。ただしこれはProfileの素の性能を測るためだけの候補であり、
製品版のATO/TASC/駅停止制御の動作ではない。採用には別途の明示承認を要する。

本実装はtarget 0を一律に保持しない。BrakingCurveが残距離・応答時間・速度依存制動性能・安全余裕から
最大許容速度を返し、上位のTargetSpeedResolverが信号・路線・駅停止などの制約と統合して、毎tickの
最終許容targetSpeedを決める。NotchSelectorは、その速度軌道へ追従するために必要な減速度を基に
B1〜B7を切り替える。したがって一般には、停止開始で強いBノッチを選び、残距離・速度・応答状態に
応じて弱いBノッチやCOASTへ遷移し、TASCが低速・停止位置付近を担当する。B7でも安全に停止できない
とBrakingCurve/上位統合が判定する場合だけEBへ渡す。

最終的な停車精度、ノッチ切替閾値、速度依存Profile、安全余裕、低速/クリープの具体値は実測後に
確定する。よって本書は「動的な軌道追従で安全に停車させる」という責務境界を確定し、未測定の数値を
保証値として固定しない。

### 確定：10 tickの線形応答

ノッチ要求を受けた時点から、実効加減速度を10 tick（0.5秒）かけて目標ノッチの
Profile値へ**線形に遷移**させる。この方式はPhase 5Aの試験用挙動だけでなく、
本実装にも用いる。10 tickの不感時間後に一括で切り替える方式は採用しない。

遷移開始時の実効加減速度を `aStart`、Profileが現在速度で返す目標加減速度を
`aTarget`、遷移開始からのtick数を `t` とすると、実効加減速度は次式の形で扱う。

```text
effectiveAcceleration(t) = aStart + (aTarget - aStart) × clamp(t / 10, 0, 1)
```

これはBノッチ間の変更だけでなく、力行から制動、制動から力行への変更にも同じ応答則を
適用する。符号の異なるノッチへ移る場合は、実効加減速度が連続的に0を通過する。

`appliedNotch`は最後に遷移が完了した離散ノッチとして保持する。遷移中は、目標である
`commandedNotch`、`appliedNotch`、`effectiveAcceleration`、進捗tickを併せて記録し、
中間の加減速度を架空の離散ノッチとして扱わない。

ノッチ変更中に新しい要求が到着した場合は、切替直前の
`effectiveAcceleration(t)` を新しい遷移の `aStart'` とし、要求された新ノッチの
`aTarget'` へ、改めて10 tickで線形に遷移する。以前の遷移を完走させたり、開始時の
加減速度へ戻したりしてはならない。この規則により、連続するノッチ要求でも実効加減速度の
不連続を生じさせない。

`aTarget` は毎tick、現在速度でProfileを再評価する。ノッチ要求によって始まった遷移中は、
同じ遷移開始時刻と `aStart` を保持したまま、そのtickの `aTarget(currentSpeed)` を線形式へ
用いる。単なる速度変化では遷移を最初から始め直さない。10 tick経過後は、そのtickの
`aTarget(currentSpeed)` を実効加減速度として追従する。新しいノッチ要求だけが、上記の
再遷移規則に従って `aStart` と10 tickの計時を更新する。

停止距離計算は、この線形応答と毎tick再評価されるProfileを前提に含めなければならない。

## 実在鉄道の快適停車を参照する原則

2026-09-10に行った実在鉄道・ATOの公開資料調査を、将来の自動停車時の
`NotchSelector` とTASCの設計判断に用いる。これは**数値・切替順を確定する仕様ではなく、
測定と承認を経るまでの設計原則**である。調査の詳細と出典は
`docs/research/EXPERIMENTS.md` の第19節を正本とする。

- 実車ではブレーキ指令は離散ノッチであっても、同じノッチに対する実減速度は荷重、
  粘着、天候などで変動する。したがって、停止制御は固定の時刻表的ノッチ列ではなく、
  実測速度・減速度と予測停止位置を用いるフィードバックを基本とする。
- 乗り心地は減速度だけでなく、加速度変化率（ジャーク）に影響される。既決の10 tick
  線形応答は不連続な加減速度を避ける基盤であるが、それだけで快適性を保証するものではない。
- 停車へ向かう制御は、必要な制動を十分早く立ち上げた後、停止位置・実減速度の予測に
  応じて制動を段階的に弱める（緩める）方向を基本候補とする。必要な安全制動を削ることや、
  目標を外れた際の再制動を禁止する意味ではない。
- したがって、最終的な自動選択を `B7 → B6 → … → B1` のような固定列として決めない。
  要求減速度、予測停止誤差、実効加減速度の遷移中状態、速度域、および安全制約から、
  その時点で必要なノッチを選ぶ。
- 停止直前に強いノッチを追加して誤差を取り戻すと衝撃を増やし得るため、通常制動では
  早期の予測補正と段階的な緩和を優先する。ただし、停止信号・衝突回避等の安全制約を
  満たせない場合は、快適性よりEBを含む安全側の制動を優先する。

未確定のまま残す項目は、ノッチ切替のヒステリシス／デッドバンド、許容ジャーク、
停止予測誤差の閾値、低速域での最終緩和規則、およびTASCとの引継ぎ条件である。これらは
Phase 5AのProfile・制動数学・走行試験の結果を用いて別途承認する。

## 数学上の未確定事項

速度依存減速度では単純な `v² / 2a` だけで制動距離を確定できない。応答時間、
速度ごとの減速度、距離余裕、安全係数を含めた停止距離の計算と、残距離から最大許容速度を
求める数値逆算は、Phase 5の仕様として確定が必要である。

Create標準走行の観測値は `docs/reference/logs/`、計測仕様は
`docs/research/EXPERIMENTS.md` を参照する。
