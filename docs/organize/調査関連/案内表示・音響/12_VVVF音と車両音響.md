# 12 VVVF音と車両音響の調査

- 対象：検討一覧の12「VVVF音・モーター音」。電力・M/T・走行性能そのものの採用判断とは分ける。
- 調査日：2026-10-22（JST）。CAT照合基準：[整理3.md](../../整理3.md)の2026-10-21保存版。
- 対象：鉄道メーカー・電機メーカーの公開資料、Create 6.0.8の提供ソース、Create: VVVF-Simulator作者の公開説明、2026-10-21の類似MOD調査報告。
- 検証範囲：公開文書・ローカルコードの静的確認。音の実測、聴取比較、Minecraft起動、外部MODのソース／JAR解析、CAT実装はしていない。

## 1. 要点・凡例

VVVFは可変電圧・可変周波数の制御を意味する。一般にいう「VVVF音」は鉄道車両の音の一部分であり、車輪・レール、送風装置等を含む車両の走行音全体と同一ではない。主電動機等の電磁音にはインバータのスイッチング・変調が関係する。[R1,R2]

CATに音を加える場合、実際の主回路・電磁力まで解く方式に限定する必要はない。速度と制御状態に連動する音響表現、電気的な波形合成、実車音源の再生を比較し、走行性能を決める処理と音を生成する処理の責任を明確にする。

- **確認事実**：出典が支持する内容。**考察／提案**：未承認の選択肢。**不明**：確認できなかった内容。
- **[再調査:CAT]**：車両性能・M/T・電力・制御状態・音の対象範囲が変われば再照合。
- **[再調査:依存版]**：Createや音響MOD・ライブラリの版変更時に再確認。
- **[再調査:実機]**：音質・連続性・負荷・同期・同時発音の確認が残る。

## 2. 実鉄道・音の原理についての確認事実

### 2.1 VVVFが表すもの

富士電機の解説はVVVFを電圧・周波数を変化させる方式と説明し、スイッチングによるPWMの概略を示す。これは電力変換の説明であり、特定の鉄道車種の音やノッチ性能を規定するものではない。[R1]

### 2.2 音源と制御方式は一対一の名前ではない

東芝の鉄道車両用電力変換装置の技術報告は、車両騒音として車輪・レール、風切り、モータ・変圧器、送風機等を挙げ、インバータのスイッチングに伴う電磁音とPWM変調による低騒音化を説明する。[R2]

**考察**：同じ速度で走っていても、力行・回生・惰行、変調方式、電動機・車体の音響条件が異なれば、同じ音とは限らない。従って「速度だけで一つの録音のピッチを変える」方式はゲーム向けの簡略化候補であり、実車音の完全再現を保証しない。

**不明**：E235系等の対象車種の全速度域・全ノッチ・力行回生別の正確な変調パラメーター、電磁音の伝達特性、車内外の録音条件は本調査では取得していない。特定車種の周波数遷移表を推測で作らない。

## 3. 既存MOD・Createの確認範囲 [再調査:依存版]

### 3.1 Create: VVVF-Simulator

作者のModrinth説明は、列車音の調整、録音済み音源によらないリアルタイムVVVF波形シミュレーション、遠距離・ディメンション間での速度連続性を保つためのサーバー側設定配信を機能として挙げる。[M1]

ここで確認したのは**作者による機能説明**であり、CATの指定ノッチ・実効指令・独自速度制御へ実際に追従することや、計算負荷が許容範囲であることの独立検証ではない。

2026-10-21のローカル調査報告N05にはForge 1.2.1の配布確認がある。一方、今回その版のModrinthページと公開メタデータ取得は失敗したため、**対象版1.2.1の詳細は既存報告の参照であり、今回の独立再確認ではない**。一般説明ページの機能をすべて1.2.1の実装済み機能へ移し替えない。[M2]

同MODと必要な音響ライブラリのソースは手元にないため、入力速度の取得箇所、ノッチ連動、波形・ミキサー・同期の内部方式、CATから利用できる公式な拡張点、対象Create版との正確な互換範囲は**不明**。既存MODがあることはCATへの連携完成や、独自機能の不要を意味しない。

### 3.2 Create 6.0.8の車両音

`CarriageSounds.tick()`は車両の前回位置との差から移動量を求め、距離・接近方向・着席状態等を使って音量の変化を計算する。台車のスタイルから音イベントを選ぶ経路があり、ループ音の再生、移動に応じたピッチ変更、車内外の音量切替が実装されている。[L1]

編成内で音量情報を共有する処理と、`stop()`で継続音を止める処理も存在する。従って新しい音を単に各車両へ加える際には、既存の共有音・台車音を残すか、置換するかを確認する必要がある。[L1]

**限定**：これらは標準Createの車両音処理の静的事実である。この処理がVVVFの電磁音を物理的に計算しているという根拠ではない。また、車両位置差はCATの実効ノッチ・回生状態を直接表す情報ではない。

## 4. 現行CATとの照合 [再調査:CAT]

整理3.md第4章では、指定ノッチと実効指令を分離し、力行は速度依存曲線、ATO・TASCは性能範囲内の連続的要求を用いる。力行・自然抵抗・勾配等の数理モデルや具体値は未決定である。第13.11節ではパンタグラフ・電力は検討段階で、電力の採用を前提にしない。[C1]

そのため、次の区別が必要になる。

| 接続候補 | 現行方針から生じる注意 |
|---|---|
| 指定ノッチ | 保存Pでも安全介入中は実効EB等になり得る。指定位置だけで力行音を決めると実際の制御と食い違う |
| 実効指令 | ATO・TASCでは連続値があり、必ずP1等の離散段へ落ちるとは限らない |
| 実際の加速度 | 坂道や抵抗も含み得るため、加速していることだけでモータ力行と断定しない |
| 車両性能プロファイル | 音源の形式・制御方式・車両ごとの音を同じ設定へ組み込むかは未決定 |
| M/T・電力 | 採用前は電動車単位発音や停電時音変化を確定仕様にしない |

**考察**：車上の有効な駆動／制動状態から音響用の状態を作り、音が走行指令を変更しない構成は候補になる。ただし必要情報が現行CATでまだ定義されていないなら、音側だけで「実際の電流」を創作しない。

## 5. 再現方式の比較 [再調査:CAT]

以下は独自の**方式比較・提案**であり、実装性能の測定結果ではない。

| 方式候補 | 特徴 | Minecraftでの兼ね合い |
|---|---|---|
| 単一・少数録音のピッチ／音量変化 | 構成を小さくしやすい。素材の質に依存 | 変調の切替や力行／回生差を簡略化。広い速度域で違和感が出る可能性 |
| 速度域・運転状態別の録音＋クロスフェード | 特定車両らしい変化を表現する候補 | 素材数・境界・ループ位置・音量整合・配布容量が増える |
| パラメーターによる音響合成 | 連続変化と利用者調整の自由度が高い候補 | 波形と聴こえる音は同一ではない。共鳴・フィルター・ノイズ等の範囲を決める |
| 電気・機械の詳細モデルと連動 | 電流・回転数等と整合する可能性 | 計算量と必要データが大きい。CATが主回路まで再現する根拠は現時点でない |
| 既存VVVF音MODと連携 | 音響機能の重複開発を抑えられる候補 | 対象版の内部入力・拡張点・依存ライブラリ・配布条件の確認が必要 |

### 5.1 音へ渡す状態の候補

速度、走行方向、力行／惰行／電気制動／空気制動の区別、出力の相対値、車両・駆動装置の音設定、音源位置、状態の生成時刻・有効性が候補になる。ただし電気／空気制動の分離がCAT未採用なら、まず表示上の近似状態として扱うかを決める。

回転数を計算する場合は車輪径・歯車比・すべり等の前提が必要になる。速度から回転数を一意に推定できると無条件にはしない。入力としての実回転数を持たない段階で、合成音の周波数を計測済み実車値と表示しない。

### 5.2 ゲームtickと音声波形の時間軸

**考察**：運行状態の更新頻度と音声サンプル生成の頻度は別に扱う必要がある。仮に20tick/sと48,000sample/sを採る説明例なら、1tickに2,400サンプル相当がある。これは単位換算の例であり、Minecraft・既存MODの実際の音声サンプルレートを確認した値ではない。

ノッチや速度の変化を毎tickで不連続に音へ反映すると、音切れや段差が出る可能性がある。一方、音側の補間を実速度や制動へ逆流させてはならない。状態更新が途切れたとき、最終値を短時間保持する、惰行へ遷移する、消音する等の扱いは仕様判断である。

### 5.3 音源数・定位・標準音との併用

列車全体で一つ、車両ごと、台車ごとでは、音の位置感と負荷が異なる。M/Tを採用した場合にM車だけ発音するか、駆動装置を別単位とするかも選択肢になる。Create標準の音量共有処理を踏まえ、同じ走行音を二重に鳴らすかどうかを決める。[L1]

遠距離では発音数を減らす、同一車両の詳細音をまとめるなどの候補があるが、具体的な距離・同時発音上限・負荷削減効果は未測定である。

### 5.4 同期とゲームの境界 [再調査:実機]

確認対象は、力行開始・惰行・再力行・回生開始・低速停止、急なノッチ変更、勾配、後退、低TPS、途中参加、未読込、ディメンション移動、連結分離、音設定変更である。実効指令と音の切替が一致するか、音の停止漏れ・同一音の重複・波形位相の飛び・遅延がないかを確認する。

音を止められない状態が列車の走行制御を止めるかどうかも別に決める。音響計算の失敗を無条件に駆動故障へ変換する方針は採用されていない。

## 6. 不明点と必要な追加資料

- 目標とする車種・駆動装置・音の忠実度、車内／車外の優先、既存標準音を残す範囲は未決定。
- 対象車両の音源・周波数資料・録音条件・利用条件が未確定。録音の存在だけでは再配布できると扱わない。
- Create: VVVF-Simulatorの対象Forge版と、同版が要求するVVVF-Simulator-Libraryのソースが未提供。CATとの接続点を実装レベルで確定するには、対象版を指定した提供が必要。
- 既存MODの依存条件、実際の音声生成方式の詳細、同時発音数、計算・メモリ負荷、Create 6.0.8との併用挙動は未検証。
- M/T・電気ブレーキ・電力供給をCATが採用しない場合でも音響表現は検討できるが、電気的な状態を実計算していると誤認させない表示・説明が必要。
