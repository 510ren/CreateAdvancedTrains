## 4. 記録方法

- ケースIDは形状候補に固定し、試行をC001-T01等で識別する。条件変更で比較する新ケースは別IDにし、親ケースと変更点を記録する。
- 端点は置いた線路ブロックの座標を記録する。実際の接続点座標とは区別する。座標の根拠がない場合は推定せず未確認にする。
- 座標はMinecraftのX・Y・Z。相対位置では始点Aを基準にする。X+＝東、Z+＝南。線路の軸と、接続したい側へ向く矢印を分ける。矢印は列車の一方通行指定ではない。
- 高低差ΔYはBの線路ブロックY−Aの線路ブロックY。端点高低差・水平隔たりから線路全体の一定勾配や最大局所勾配を算出しない。
- 成功：配置後の全景、端点・継ぎ目が分かる画像、実際に生成された形を記録。プレビューだけでは成功にしない。
- 拒否：両端配置、プレビュー、エラー原文、拒否された操作段階を記録。プレビュー時点の拒否と、確定操作時の拒否を分ける。
- 未試行：準備前・操作不能・画像のみの希望等の理由を併記。操作方法がない形を敷設拒否と混同しない。
- 画像はケースIDと内容を対応付ける。元画像と描き込みを区別し、描き込みは希望形状として扱う。保存できた実ファイルだけリンクする。チャット画像のみなら受領順・説明を記録し、未保存と明記する。
- エラーが見えない場合は「なし」と断定せず「未確認」。不足資料だけを追加で依頼し、同じ実験をむやみに繰り返さない。
- 「標準Createで可能／拒否」は対象版・設定付きの結果。アドオン・CAT導入下のCreate線路の観察は、その環境の結果として記録し、標準Create単体にも同じとは断定しない。

以下の寸法は実験条件であり、CATの上限値・半径・接続線路長の提案ではない。最初はENV-001で2件を提示し、その後の利用者指定によりENV-002（128）へ変更した。C001／C002は同設定での成功例を受領した。ただし正確な方角は未確認のため、高さだけを変えた厳密な比較が成立したとは扱わない。

### 初回2件の共通手順・報告内容

1. 接続を妨げる既設線路や障害物のない場所を使う。端点線路は水平に置き、傾斜線路にしない。Aの実座標を控える。
2. A→Bの順で、普段のCreate接続操作を使う。接続したい側はAの東側・Bの北側。初回はShift等の補助キーを押さない。操作ができなければできない段階を報告し、別条件へ変えない。
3. プレビューを撮影し、配置できそうなら確定を試す。成功なら配置全景と端点、拒否ならプレビューとエラーを残す。C002では側面の高さ関係も撮影する。
4. C001の配置を残すなら、C002は離れた空き場所で同じ相対位置・支持条件を再現する。C001の接続が残る端点をそのまま使わない。別の場所を使った場合はそれぞれのA実座標を記録する。
5. 報告はケースID、成功／拒否／未試行、A実座標、指定との差、補助キーの有無、画像・エラー。B実座標も分かれば併記する。指定との一致が報告された相対座標と、個別に測った絶対座標は区別して記録する。

X・Zの12は座標差12 blockを意味する。同じYで座標差12の端点間には11個のブロック座標が入る。端点支持ブロックの座標ではなく、線路ブロック自体の座標を使う。
