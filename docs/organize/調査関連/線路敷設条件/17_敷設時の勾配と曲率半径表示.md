# 17. 線路敷設時の勾配・曲率半径表示の調査

調査日：2026-10-22（日本時間）  
対象：提供Create 6.0.8／Minecraft 1.20.1、整理3.md、線形の数理。  
検証：ソースの静的確認と独立した数値計算。実際の敷設・描画・走行・処理負荷は未検証。CATへの実装・許容線形の採否は行っていない。

## 1. 要点と分類

敷設予定線形の情報はCreateのプレビュー処理に存在する。ただし、`BezierConnection.getRadius()` の値は曲線生成用の幾何量であり、全点の曲率半径や最小半径を測定した値ではない。勾配も端点間の高低差だけでは局所的な急勾配を見落とす。表示値の定義を先に分ければ、線路等級や敷設制限が変わっても計算の基礎は使える。[C1,C2]

- **ソース事実**：提供版のコードから直接確認。
- **数理導出**：本書に置いた定義・仮定から計算。Minecraft実測値ではない。
- **考察／候補**：CAT向けの未承認の方式比較。
- **[再調査:CAT]**：尺度・許容形状・表示要件などが変われば再照合。
- **[再調査:依存版]**：Createや線路アドオンの版変更でコードを再確認。
- **[再調査:実機]**：ゲーム上の形状・表示・負荷の検証が残る。

## 2. Create 6.0.8で確認できたこと [再調査:依存版]

### 2.1 プレビューのデータ

`TrackPlacement.PlacementInfo` は `curve`、可否、端点側の延長量、端点、軸、法線等を持つ。`tryConnect()` は端点側の直線延長を求め、その後に `BezierConnection` を作る。`clientTick()` はこの結果から接続可否等を表示し、曲線プレビューも描画する。[C1]

**考察**：予定線形を別の近似形へ作り直すより、実際の敷設候補を計測する接続が候補になる。ただし `curve` 等はpackage-privateであり、「そのまま公開APIで取得できる」とは言えない。公開アクセサの追加・アクセス方法・互換負担は別の設計事項。

また、`curve == null` は無条件にエラーを意味しない。直線側の延長だけで構成される経路もあるため、曲線だけを集計すると敷設全体を表せない。[C1]

### 2.2 半径の既存値

`getRadius()` はRuntimeの `radius` を返す。`determineHandles()` は初期値を0にし、端点軸等の平面上の交点から条件に応じて値を設定する。角度0や交点を得られない分岐では0のまま戻り、ハンドル長だけが決まる場合がある。[C2]

この0は「実際の線路が半径0で曲がる」という証拠ではない。また、処理は曲線上の各点を走査して最小半径を返す構造ではない。したがって値を無加工で「最小R」と表示する根拠はない。[C2]

### 2.3 長さと補間

`getPosition(t)` は3次ベジェの位置を返す。Runtimeは全長を16分割した点間距離の和で近似し、別途stepLUTを作る。曲線パラメーターtが0.5だから弧長のちょうど半分、とは一般には言えない。[C2]

接続確定後には `TrackBlockEntity` のtiltによるsmoothing適用が呼ばれる。プレビュー候補と確定後の見た目・接続部の評価が全条件で一致するかは、smoothingを含めた追加確認が必要である。[C1]

## 3. 仕様変更に依存しない数理の整理

以下は一般の正則な曲線を対象とした数理導出であり、Createの現行表示値やCATの採用式ではない。yを鉛直、x-zを水平面とする。

### 3.1 局所勾配

線形を p(t) = (x(t), y(t), z(t)) とする。水平投影の微小長さは

\[
ds_h=\sqrt{x'(t)^2+z'(t)^2}\,dt
\]

なので、進行方向をtの増加側に取った勾配は

\[
i(t)=\frac{y'(t)}{\sqrt{x'(t)^2+z'(t)^2}},\qquad
i_{\text{‰}}(t)=1000i(t),\qquad
\theta(t)=\arctan i(t).
\]

端点の高低差を水平経路長で割る平均勾配と、局所勾配は別である。水平投影が折れ曲がる場合、端点間の直線距離で平均を出すこととも区別する。水平成分が0なら、この形式の勾配は有限値として定義できない。

**計算例**：水平に1 block進み高さ1 block上がる直線は、勾配1000‰、角度45°。これは説明用の計算であり、鉄道として許容する値ではない。1000‰と1000%を混同しない。

### 3.2 水平曲率と空間曲率

通常の平面上の曲がりを表示したい場合は、水平投影の曲率

\[
\kappa_h(t)=\frac{|x'(t)z''(t)-z'(t)x''(t)|}
{(x'(t)^2+z'(t)^2)^{3/2}},\qquad R_h(t)=1/\kappa_h(t)
\]

を候補として定義できる。一方、空間曲率は

\[
\kappa_{3D}(t)=\frac{\|p'(t)\times p''(t)\|}{\|p'(t)\|^3}
\]

である。上り下りの変化だけでも空間曲率は生じるため、両者を同じ「曲線R」と表示すると意味が曖昧になる。鉛直線形の評価も、単に空間曲率を水平Rへ置換せず別項目として定義する。

正則な直線部分は曲率0・半径無限大。速度ベクトルp'自体が0となる退化点は「直線」ではなく、上記式で未定義になる。接続点で接線が不連続な場合も、左右の値と接続角を別に評価する。

### 3.3 3次ベジェの微分と計算確認

制御点をP0～P3とした標準の3次ベジェ式を微分すると、

\[
p'(t)=3(1-t)^2(P_1-P_0)+6(1-t)t(P_2-P_1)+3t^2(P_3-P_2)
\]

\[
p''(t)=6(1-t)(P_2-2P_1+P_0)+6t(P_3-2P_2+P_1)
\]

となり、上の勾配・曲率へ代入できる。Createでは端点と軸・ハンドル長から制御点を得る構造を確認した。[C2]

**独立計算例**：半径16の四分円を近似する平面3次ベジェを置く。k = (4/3)tan(π/8)、P0=(16,0,0)、P1=(16,0,16k)、P2=(16k,0,16)、P3=(0,0,16)とした。倍精度の直接計算では以下となった。

| t | 局所的な水平曲率半径［block］ |
|---:|---:|
| 0 | 約16.3507 |
| 0.25 | 約15.9012 |
| 0.5 | 約16.1005 |
| 0.75 | 約15.9012 |
| 1 | 約16.3507 |

これは「円弧を意図して作ったベジェでも局所Rが一定ではない」という数理例。Minecraft上の実測ではなく、この5点から区間の厳密な最小値を求めたものでもない。Create内部のfloat丸めやsmoothingを完全に再現した計算ではない。

### 3.4 尺度

等方的に1 block = s mと換算するなら、半径と長さはs倍、勾配比は変わらない。高さと水平距離に別尺度を使うならこの結論は使えない。ゲーム内の勾配表示から現実の登坂・制動性能まで決めるには、重力・質量・速度・加速度の単位を別途整合させる必要がある。

## 4. 現行CATとの照合 [再調査:CAT]

整理3.md第13.4節は、長区間の平均だけで短い急曲線・急勾配を見落とさないこと、CATが予定形状・曲率・勾配・厳しさ・可否を算定する方向を記す。第13.11節の1block長さ設定は、表示だけか物理計算も変えるか未決定。線路形状の個別採否は引き続き保留である。[D1]

したがって、勾配・Rの測定表示は既存の方向と接続できるが、どの値をHUDに出すか、表示精度、敷設拒否の閾値は未決定。本調査は敷設許容値の採用ではない。

## 5. Minecraftでの表示・計算の考察 [再調査:CAT]

| 論点 | 比較・検討する内容 |
|---|---|
| 表示値 | 全候補の最大上り／最大下り勾配と最小水平R、注目点の局所値を分ける。「平均」「最小」「概算」を明記する候補 |
| 直線・異常 | 直線は「直線／R=∞」、計算不能は「不明」、拒否形状は拒否理由。すべてをR=0へまとめない |
| 敷設候補全体 | ベジェだけでなく両端の直線延長、接続前後、smoothingによる変化を評価対象に含めるかを決める |
| 最大・最小の精度 | 固定点サンプリングは局所極値の取り逃しがある。解析的な極値探索・適応分割・保守的誤差幅を比較する。表示丸めした値を敷設判定へ逆利用しない |
| 処理負荷 | 形状・端点・設定が変わった時の再計算と描画の更新を分ける候補。未完成候補・退化形状を短絡処理する |
| サーバー整合 | クライアントのプレビュー値を配置許可として信用せず、確定時は最新設定・接続先で評価する。これは整理3.md第13.5節にも接続する |
| 見やすさ | 勾配‰と角度°を混ぜず、半径の単位をblock／mのどちらか明記。画面倍率や他の敷設案内との重なりを確認する |

既存Createの接続可否とCATの性能上の可否は別である。「Createで置けた」「Rを算出できた」「CAT基準で走れる」を同じ合格にしない。

- 不明：smoothing、他アドオン独自線路、混合軌間で、プレビューと確定後の評価対象形状がどこまで同一か。対象方式決定後に該当提供ソースを絞る。
- 不明：適応分割等の必要精度・最大負荷、GUIの表示位置。今回の計算例は実装方式の採用根拠を完結させない。
- [再調査:実機] 最初は水平直線と既知端点の平面曲線の2ケースで表示・向き・単位を確認し、その後、一定勾配・頂上／谷・S字・曲線勾配・確定後smoothingへ広げる。未実施。
- 追加資料：選択する敷設拡張MODがある場合はその対象版ソース、実際に検証する端点座標・向き・設定値。旧観測の敷設成功は半径や安全走行の測定ではない。
