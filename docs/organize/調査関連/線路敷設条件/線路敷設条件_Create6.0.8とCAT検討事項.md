## 2. 線形・位置情報（項目22）

### 2.1 ソースから確認できる事実

- C01の `isTurn()` はベジェ接続の有無を判定する。平面の円曲線だけの分類ではない。長さは異次元接続で0、ベジェでは接続の近似長、その他はノード間の三次元距離。
- C02の `getPosition(t)` は端点とハンドルから三次ベジェ座標を求める。`getNormal(t)` は端点法線を補間し、接線に直交する向きを求める。
- C02の `getRadius()` はハンドル算定中に求めた `radius` を返す。水平投影の軸交点が得られない場合や平行軸の処理では0のままになる経路がある。**曲線全体の局所最小半径や、0なら半径ゼロの急曲線という意味ではない。**
- C02は長さを16分割の折線から近似し、その後の描画等の分割・LUTを作る。パラメータ `t` の等間隔と実際の距離の等間隔は同じではない。
- C01は傾斜接続の補正が必要な直線で隣接ベジェ端を参照する。グラフを渡すかどうかで補正座標が変わり得る。ノード間の端点だけを結んだ形を、常に走行で使う形と一致させない。
- C08の `TravellingPoint.getPositionWithOffset()` はエッジ座標に法線方向の±1 blockを加える。得た座標をレール面中心と見なして、重心高・障害物隙間・勾配を算定しない。
- C03の上り形状AN/AS/AE/AWには高さ1・水平1の方向がある。共通長さ尺度の純粋な幾何換算では1:1＝1000‰となり、実鉄道の25‰・35‰にそのまま当てると大きな差が生じる。これをCATの禁止勾配と決定していない。
- C07の `smoothingAngle` は前後の上り下り接続を滑らかにする処理に使う。左右レールの高低差である実鉄道のカント値と同一のフィールドではない。任意の他アドオンでカントがないことまでは確認していない。

### 2.2 半径・勾配を求める場合の導出案

以下は数学的導出であり、Createが既にこの計算を行うという事実ではない。三次ベジェを次のように置く。

`r(t)=(1-t)^3 P0+3(1-t)^2 t P1+3(1-t)t² P2+t³ P3`、`0≤t≤1`。

C02での対応はP0＝最初のstart、P1＝finish1、P2＝finish2、P3＝次のstart。パラメータは無次元、座標はblock。

水平投影 `x(t),z(t)` の曲率は、

`κh(t)=|x' z''-z' x''|/(x'²+z'²)^(3/2)`、`Rh=1/κh`。

κhの単位は1/block、Rhはblock。水平接線が0に近い箇所は分母が特異になり、未知・不正形状として別評価が必要。κhが0の正則な直線と、計算不能な点を区別する。三次元曲率 `|r'×r''|/|r'|³` は上下の曲がりも含むため、平面曲線半径の代わりにはしない。

局所勾配の幾何定義は `i(t)=1000 y'/sqrt(x'²+z'²)`（‰）。向きを逆転すると符号が反転する。両端高低差／両端水平距離だけでは、途中の急な勾配や凸凹を見落とし得る。

カントを法線から評価する案には、接線に直交する基準上方向と実法線のなすロール角を用いる余地がある。ただし、法線の取得・正規化・符号、裏返り、接触点距離、左右レールの意味が必要。小角度の近似 `C≈Gφ` を使う場合もCとGは同じ長さ単位、φはrad。単なる斜面のピッチをカントに換算しない。物理カントを持たせるか、評価用パラメータだけを持たせるかは未決定。

**精度上の論点**：有限個のサンプルの最小値は、曲線全体の真の最小半径を保証しない。サンプル密度・誤差上限、極値探索、端点近傍、S字の反曲点、隣接エッジの接線／曲率不連続を検討する。強化条件の許容境界付近では誤差を隠さない。弧長を使う先読みと、Create内部のエッジ位置・ベジェパラメータの変換も区別する。

### 2.3 配置制約と走行制約

C04はS字の上り、斜面での曲がり、急な接続などに配置エラーを返す。内部の `minTurnSize` は90度等の分岐で7／3.25という値を使うが、**これは曲線半径mではない**。単位と定義を変えずに「最小半径7 m」と紹介しない。

C11の設定初期値は通常最高速度28 block/s、曲がり14 block/s、加速度3 block/s²。燃料ありの設定は40／20／3。C09は速度を20、加速度を400で割って内部単位にする。これらは設定初期値で、調査対象ワールドの実設定値は未確認。

C10は曲線探索で、水平軸が反対向きの緩い直線勾配を除外する処理を持つ。それ以外では `min(topSpeed,maxTurnSpeed)` と制動距離を使う。**この経路には局所半径・カントに応じた連続的な許容速度算定はない。**曲線制限の全てが半径比例であるとは紹介しない。C09の目標速度への更新は設定加速度を使い、ここを読むだけで車重・粘着・勾配抵抗を含む実鉄道モデルがあると断定しない。

### 2.4 分岐・交差・異次元接続

C03の複数軸を持つ形状は交差を含む。交差点に見える場所で全ての経路間へ転線できるとは限らない。C05は同じ接続に往復の有向エッジを作り、他の曲線との交差情報も登録する。実際の接続・選択進路と、画面上で線路が重なったことを区別する。

C01の異次元エッジ長0に、半径・勾配・距離の通常式を適用しない。ワールドのx/zが近い別ディメンションを同じ物理区間にしない。分岐経路ごとの制約、交差の通過許可と幾何通過性能の違いは、CATで定義する必要がある。

## 4. 既存CATの制約との接続（項目23）

### 4.1 現在の文書で決定されていること

2026-10-11に読んだ `整理3.md` 第9.2・9.3・11.11節：

- 標識の物理速度制限は現在の区間・実走行方向から取得する。次の制限／解除で切替え、分岐・合流の規則を持つ。境界の車体基準点は未決定。
- 標識の物理制限超過は列車側の脱線系耐久値の減少原因。信号・車内信号・ATOSの制限や車両最高速度を、この原因へ自動流用しない。
- 手動安全装置OFFでは装置による速度切詰めを行わないが、物理的故障は独立する。ATO／有効な安全装置の担当範囲と、物理的超過の結果を区別する。
- 不明・古い・未取得と、設備不存在／指定なしを区別する。物理制限不明時は脱線系減少・回復を両方保留し、情報回復後に過去分を加算しない。
- 物理制限の低下＝制限強化では、既に対象区間にいる列車の減少量を一定期間1/2にする。ただし判定・制御は直ちに最新制限、期間再付与・延長なし。残りtickと対象を保存する。期間長・識別等の詳細は未決定。
- 耐久残量・故障状態は列車側に保存し、HUD開閉・再読込等で回復させない。発動後は明示復旧が必要。

これらの既存決定は今回の調査で書き換えていない。線路強化という新機能による算定限界を、この「物理制限」に統合するかは未決定。

### 4.2 接続時に確認すべき条件

| 制約の候補 | 表すもの | 未決定・注意点 |
|---|---|---|
| 線形・カント由来 | 曲線速度・遷移条件等 | 車両条件込みの算定か、線路固有の基礎値か |
| 荷重・構造由来 | 軸重・橋梁容量・現在の状態等 | 超過時に速度低下で解決するものと、進入自体が不適合なもの |
| 物理標識 | 指定方向・区間の物理制限 | 線路強化で標識を自動書換えするかは未承認 |
| 信号・ATOS等 | 運転許可・停止・運用制約 | 線路の性能を上げても制約が自動消去されない |
| 車両制約 | 最高速度・通過形状・質量・制動 | 車両最高速度を脱線原因へ自動流用しない既存決定を維持 |
| 不明な情報 | 必要根拠を取得・確認できない | 「制約なし」の最大値へ置換しない |

複数の**有効な速度上限**を制御へ渡す場合、最小値を使うのは算術上の整理案である。進入許可、停止要求、荷重不適合、未知状態まで同じ速度数値に押し込めるものではない。出典・理由・有効範囲を残さなければ、HUDや耐久判定がどの原因を扱うか分からなくなる。

例：標識80 km/h、ATOS30 km/h、現在50 km/hなら、現行文書ではATOS違反だけで脱線系を減らさない。線路算定40 km/hを新たに得たとして、それを脱線原因へ含めるかは追加決定が必要。今回の調査では独断で含めていない。

線路性能を上げる「線路強化」と、許容速度を下げる「制限強化」を混同しない。強化の撤去・交換で物理上限が下がる場合も、既存の半減措置へ接続するか、対象・通知・適用時点を別途定義する必要がある。

## 6. 単位・簡略化・根拠追跡（項目25）

### 6.1 単位対応を決める前に

共通の長さ尺度を `λ[m/block]`、内部速度を `u[block/tick]`、内部加速度を `a[block/tick²]`、公称20 tick/sと仮定した**導出**：

- `L[m]=λ L[block]`、`R[m]=λ R[block]`。
- `v[km/h]=3.6×20×λ×u=72λu`。
- `a[m/s²]=400λa[block/tick²]`。
- カントをblockで持つなら `C[mm]=1000λC[block]`。
- 同じ尺度で水平・高さを換算すると勾配比は変わらない。λを大きくしても1:1の坂は1000‰のまま。
- 高さと水平で別尺度を採ると勾配や曲率が変わる。これはゲーム上の独自換算として明記し、実寸再現と呼ばない。

公称tick換算と実際の処理遅延は別。20 TPS未満での実時間とゲーム時間のどちらを耐久・工事等に使うかは未決定。実鉄道の低速・停止保持や緩和曲線長と、Createの配置可能サイズの差を、無説明の一つの係数に隠さない。

### 6.2 記録する根拠の単位

算定パラメータごとに、資料ID、区分、版・ページ、原式・原単位、適用条件、除外・例外、対象車両、ゲーム変換、簡略化、決定状況を残す案。例えば「不足カント60」ではmmなのか、想定通勤車なのか、全国規則なのか分からない。

N02のカントは軌間mm・平均速度km/h、B01は接触点距離m・最高速度km/hを使う箇所がある。N02の緩和曲線式はカントm、B01の表はカントmm。変数名が同じでも原資料を跨いでそのまま代入しない。

### 6.3 情報状態の整理案

`有効値あり`、`指定なしを確認`、`未取得`、`古く利用不能`、`対象不適合／計算不能`を区別する案。形状不明、未読込、ゼロ長ポータル、数値異常を無制限・半径無限大へ変換しない。現行の第9.3節の基本方針を守り、線路強化データの有効性・回復処理の具体仕様は新たに決める。

## 8. 未確認・未決定の区別

**未確認の外部挙動**：他アドオンの軌間・カント・特殊分岐、実ワールドの設定、チャンク未読込・グラフ再編時の実機挙動、全パケット到達順・他modによる変更。必要になった対象版のソースは利用者にvendorへ提供を依頼する。今回の基礎調査は提供済みCreateで実施できたため、追加取得依頼は行っていない。

**未決定のCAT仕様**：ゲームの尺度、強化対象・効果、車両質量モデル、線路算定値を物理標識と統合するか、境界の車体基準点、情報有効性、キャッシュ・同期・保存方式、操作資源・権限・UI、数式係数、脱線後処理・復旧の接続。

現行の決定を検証できる箇所は整理3の現在の本文で確認した。旧CAT実装や過去提案を現在の採用仕様として扱っていない。
