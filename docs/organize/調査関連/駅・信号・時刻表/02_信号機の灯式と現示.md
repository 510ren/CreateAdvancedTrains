# 信号機の灯式と現示の調査

- 対象：調査一覧 **2「3灯式・4灯式・5灯式などの信号機」**。
- 調査日：2026-10-22（日本時間）。
- 範囲：日本の鉄道事業者・行政・機器メーカーの公開資料、手元のCreate 6.0.8ソース、整理3.md（2026-10-21版）。実装・ゲーム試験は未実施。
- **事実／考察・提案／不明**を分離する。事業者の具体例を日本全体の統一仕様と扱わない。
- マーク：`[再調査:CAT]`＝CAT仕様変更時の再照合、`[再調査:依存版]`＝依存MODの版変更、`[再調査:実機]`＝未実施の実動作検証。無印の史実・資料内容も対象と年代を限定する。

## 1. 調査結果の要点

**3灯式を加えることは、外観モデルを小さくするだけでは終わらない。** 信号機が表示できる現示集合、現示を選ぶ論理、車上側が解釈する制約、表示不能・異常時の扱いを対応させる必要がある。

実在する3・4・5現示の具体例は阪急電鉄の公式解説で確認できる。[R1] 一方、今回の資料からJR各線を含む全灯器の縦配置・点灯位置を一律に確定することはできない。

## 2. 実鉄道で確認できた事実

### 2.1 現示と灯数を分ける

阪急電鉄の説明では、3現示は停止・注意・進行、4現示には警戒を加える例と減速を加える例があり、5現示ではその両方を扱う。信号間隔や見通しの条件に応じて使い分けると説明される。[R1]

| 阪急公式解説で確認した例 | 表示する現示 |
|---|---|
| 3現示 | 停止、注意、進行 |
| 4現示の例 | 上記に警戒、または減速を加える |
| 5現示 | 停止、警戒、注意、減速、進行 |

この表は当該事業者の解説範囲であり、灯数だけで全国共通の機能表が一意に決まるという主張ではない。数値速度のCATへの転用もしない。

### 2.2 色の組合せ

国土交通省の解釈基準には、場内・出発・閉そく信号機の色灯式として、停止R、注意Y、進行Gに加え、警戒YY、減速YG等の現示方法が示される。YYは上位・下位とも橙黄色、YGは上位橙黄色・下位緑色である。抑速・高速進行も別の現示として掲載されている。[R2]

**「三位式」は灯器が3個という意味として読まない。** 同資料の三位式色灯式の欄にYY・YG等も列挙されているため、方式分類と灯器数の混同を避ける。[R2からの読解]

京三製作所の製品資料には多灯形色灯信号機の5現示構成例、主信号機用と中継・入換用途の機器が別に掲載されている。[R3] 実際の製品外観・灯器構成を選ぶ場合は、対象図面と使用条件をさらに確認する。

## 3. Create 6.0.8の静的確認 [再調査:依存版]

- `SignalState` は `RED / YELLOW / GREEN / INVALID`。`INVALID` の描画判定は短時間赤点灯となる周期を持つ。これは標準Createの状態・描画規則であり、実鉄道の警戒やCATの異常灯式ではない。[L1] 36–49行
- `SignalBoundary.resolveSignalChain` は先の経路の状態を集約して黄を返す場合がある。したがって、標準黄をそのままCATの注意速度と扱うと意味が変わる。[L2] 223–258行
- `SignalBoundary` は方向側ごとに状態と種類を持ち、保存も両側を区別する。灯式追加時に、同じ地点の反対向き信号まで同じ現示へ上書きする構成は、この情報構造と合わない。[L2] 34–46、278–319行。後半は設計上の含意。

## 4. 現在のCATとの照合 [再調査:CAT]

第9.1節は5灯式表示とinvalidの具体点灯を未決定としている。3灯式等の追加可否まで確定した記述ではない。現示切替遅延、実信号・HUD・車上参照情報の一致、再読込時の有効性確認は既定方針である。[C1]

第13.11・13.13節の中継・誘導・入換信号は、それぞれの用途を持つ追加予定である。「通常信号機を3灯にする」ことと、それらの信号機を代用することは同じ判断ではない。[C1]

## 5. CATで検討すること・Minecraftとの兼ね合い（未承認） [再調査:CAT]

| 論点 | 考察・選択肢 |
|---|---|
| 表示能力 | 灯式ごとの対応現示を明示する。たとえば3灯式がYYを表示できないなら、存在しない2灯目を点灯する処理で済ませない。 |
| 表示できない現示 | 設置条件を制限する、より厳しい表示へ落とす、路線設定の現示集合を調整する等が候補。単純な色変換は制動距離や処理容量を変えるため、01の検討と合わせる。 |
| 同じ線区での混在 | 3灯→5灯、5灯→3灯の境界で、列車が前方の制約を必要距離だけ先読みできるかを確認する。全信号を同じ灯式に強制するかは未決定。 |
| invalid・消灯・故障 | 情報未取得、グラフ不整合、通常停止、演出としての球切れを分ける。見た目だけ消灯して制御には古い進行を残すような不一致を防ぐ必要がある。 |
| 操作性 | 外観モデルの選択と現示速度・路線用途の設定を分ける案。配置画面で使用可能現示を示せば、見た目による能力の誤認を減らせる。 |
| 視認性 | 遠距離でYYとY、YGとGが潰れない寸法・明度・発光表現、色覚差への補助表示を検討する。描画距離外はサーバー情報によるHUDが補助する。 |
| ゲーム規模 | 5灯の細分化は短い駅構内を作りやすくする可能性があるが、灯数だけで高速進入を許せるわけではない。3灯を「低性能版」と固定する必要もない。 |

## 6. 不明点と追加資料 [再調査:実機]

- JR東日本等の特定路線を再現する場合の正確な灯器縦順、使わない灯位置、4灯の型別構成、速度値と適用範囲は未確定。再現対象路線・年代、公式機器図や明確な写真があると絞れる。
- CATの現示集合と、表示不能時の扱いは未承認。実鉄道の数値をMinecraftの縮尺へどう移すかも別判断。
- 今後のゲーム確認候補：各灯式の全状態・遷移、逆方向信号、混在区間、同期遅延、再読込、描画距離・GUI倍率・シェーダー。今回は実施していない。
