# 信号間距離と現示系列の調査

- 対象：調査一覧 **1「信号間距離に応じた現示の重複」**。
- 調査日：2026-10-22（日本時間）。
- 範囲：実鉄道の公開一次資料、手元のCreate 6.0.8ソースの静的確認、整理3.md（2026-10-21版）との照合。CAT実装・Minecraft実行・安全性試験は行っていない。
- 区分：**事実**＝引用元に確認できる内容、**導出**＝明示した仮定による計算、**考察／提案**＝CATへの未承認案、**不明**＝今回確認できないこと。
- 再調査マーク：`[再調査:CAT]` はCAT仕様変更時の再照合、`[再調査:依存版]` はCreate等の版変更時の再確認、`[再調査:実機]` は未実施のゲーム検証を表す。無印の実鉄道の説明も、すべての事業者・年代への一般化を意味しない。

## 1. 調査結果の要点

**信号機の個数だけを数えて現示を決めても、減速距離は保証できない。** 必要なのは、現示に従って進んだ列車が次の制約地点までに減速できるかという確認である。同一現示の連続を許すことは設計手段になり得るが、それ単独を停止保証と扱うことはできない。

実鉄道側では信号機配置、現示の変化、列車性能、運転時隔を組み合わせた検討が行われる。[R1][R2] 一方、CATで地上現示を列車別に変えず、性能差を車上側で扱う方針は既にある。固定の現示配列は未確定である。[C1]

## 2. 実鉄道について確認できた事実

1. 鉄道総研のSPEEDY閉そく割り検討機能は、信号機の配置案から現示系統と運転時隔を評価する。閉そく長を、現示変化に応じて減速できるよう設定する必要があると説明している。[R1]
2. 同研究所の2019年度成果では、信号機間の減速距離を計算し、信号現示系統と運転時隔を評価する。減速距離が長くなる条件で運転曲線を作成する点も明示する。[R2]
3. これらは「距離・性能を含めて現示系統を評価する」根拠である。**任意に短い閉そくを配置し、同じ現示を必要数繰り返すだけで成立するという規則の根拠ではない。** 同一現示連続の具体的な採用線区、標準算定式、最小間隔は今回の一次資料では確定できなかった。

## 3. 距離不足の数理的な説明（独自導出）

平坦、初速 `v₀`、目標速度 `v₁`、一定減速度の大きさ `a > 0`、制動開始まで速度が変わらない遅れ `τ` を仮定すると、必要距離は次の形になる。

```text
D = v₀ τ + (v₀² − v₁²) / (2a)       （v₀ ≥ v₁）
```

第1項は遅れ中の移動、第2項は一定減速度での減速距離である。実車性能値・CAT採用式ではない。制動力の立上がり、勾配、速度依存、離散更新、測距誤差を含めれば、そのモデルに従って再計算する。

説明用に `v₀=60 km/h=16.666… m/s`、`v₁=0`、`a=1 m/s²`、`τ=1 s` と置くと `D≈155.6 m`。1 blockを `s m` と扱うなら `D/s blocks` となる。この仮定では、1 m/blockで10 blocksの予告距離は足りない。数値は問題の構造を示す例であり、CATの性能・縮尺を指定していない。

**考察：** 停止位置直前の1 block区間を注意現示にしたまま、その手前の注意現示を増やしても、「直前の信号を注意の許容速度で通過してよい」という解釈では最後の停止距離不足が残る。遠方の停止目標に向けた継続減速、各地点の許容速度、警戒・停止の配置を合わせて定義する必要がある。これは上式からの設計上の推論であり、特定の実鉄道の取扱規則ではない。

## 4. Create 6.0.8の静的確認 [再調査:依存版]

| 確認した事実 | 根拠 | CATへの含意（推論） |
|---|---|---|
| `Navigation.tick` は `speed²/(2×acceleration)` で停止距離を計算し、経路上の信号探索に距離を使う。 | [L1] 100–147行 | 標準処理も個数だけではない。ただしCATの移行時間付きモデルを満たす保証はない。 |
| 同探索には `TravellingPoint.travel` の不正確さに対応して探索距離に50を加える旨のコメントがある。 | [L1] 141–143行 | 50をCATの安全余裕として流用しない。計算誤差の性質と対象経路を確認する。 |
| `SignalBoundary.tickState` は占有・予約等から赤を決め、連鎖信号では先の信号状態を集約する。黄は経路ごとの開通状態が混在した結果として返される。 | [L2] 185–258行、[L3] 49–72行 | Createの黄を実鉄道の注意速度へそのまま対応付けられない。 |
| 線路グラフ上の距離情報と、描画画面で見える直線距離は同じものではない。`Navigation` は経路に従う探索を使用する。 | [L1] 129–144行、353行以降 | 分岐・ループ・曲線は経路単位で扱う候補となる。 |

確認したのは上記コードの処理であり、短い信号間隔での実走行精度や他アドオンとの共存は未検証。

## 5. 現在のCATとの照合 [再調査:CAT]

- 第9章：地上現示は列車共通、性能ごとの減速開始・介入は車上側。区間占有・進路予約と実距離・性能を併用する案は検討中。[C1]
- 第9.1節：厳しい現示への変更も共通tick遅延の対象。地上表示・HUD・地上現示由来の制御は遅延後の実現示を共用する。計算上の停止だけを車上へ先行適用する案は現決定と合わない。[C1]
- 第11.7節：HUDの次信号は各候補経路の最初の1基まで。これは制動計算の内部先読み範囲を1基に限定する決定ではない。[C1]
- 第4章・第4.3節：通常／EB移行を停止予測へ含める必要があり、最終常用とEBを切り替えただけで制動能力が増える前提を置かない。[C1]

## 6. CATで検討すること・Minecraftとの兼ね合い（未承認） [再調査:CAT]

| 検討事項 | 選択肢・兼ね合い |
|---|---|
| 共通現示の基準 | 路線で受け入れる基準車両性能を使う方式、地上は共通の進路条件を示して車上が距離制約を補う方式等を比較する。車上装置なし・OFFの列車の扱いも必要。 |
| 短い区間の表現 | 同一現示を連続させる、短区間を現示計算上まとめる、敷設時に不足を警告する等。物理的な信号機の数と占有区間を不用意に同一化しない。 |
| 許容速度の量子化 | 距離から求めた許容上限を有限の現示へ落とす場合、上限を超える側へ丸めない案が考えられる。どの性能・勾配・遅延に対する上限かを明示する。 |
| 急な変化 | 信号新設、線路破壊、無許可侵入、進路変更等で、既に必要距離内へ入っている場合は事後に停止保証を作れない。通常運行の成立条件と異常時を分ける。 |
| 更新負荷 | 全信号から毎tick全経路を探索すると信号密度と分岐で負荷が増える。経路変更時の再計算・キャッシュは候補だが、古い進行情報の失効条件が必要。 |
| 時間と縮尺 | tick遅延と物理計算の時間軸を統一する。block長さ設定が表示だけか物理全体かで必要距離が変わる。 |

## 7. 不明点・追加検証 [再調査:実機]

- 同一現示連続の具体的な実線区・信号配置表と、事業者の現示系統算定基準は未取得。対象路線が決まれば、その資料があると調査精度が上がる。
- CATの許容車両性能、勾配・抵抗モデル、現示速度、表示遅延、情報有効期限は未確定。
- 実機確認候補は、①同じ総距離で信号数だけを変える、②同じ信号数で区間長を変える、③短長区間混在、④曲線・分岐・ループ、⑤低TPS・情報欠損。停止位置・介入時点・探索距離を記録する。今回は実施していない。
