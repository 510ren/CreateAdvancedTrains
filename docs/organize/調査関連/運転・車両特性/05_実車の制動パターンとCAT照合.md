# 実車の制動パターン・運転支援と現在のCAT仕様の照合

- 対象：調査一覧の **5. 実車の制動パターン等**
- 調査日：2026-10-22（日本時間）
- 対象：JR東日本の公開一次資料、Create 6.0.8提供ソース、整理3.md（2026-10-21保存版）。
- 検証範囲：方式の公開説明と静的コード確認。メーカー内部の完全な制御仕様、車種別定数、実車・Minecraft実測は得ていない。
- 調査結果とCAT採用判断を分離する。以下の案は未承認である。

## 1. 要点

**「パターン」は一つの共通制御器の名前ではない。** 停止・速度超過を防ぐ照査、許容速度に沿う制動制御、駅の定位置停止、駅間の自動運転では目的・入力・介入・終了条件が異なる。[R1–R5]

実車の概念をCATへ使う場合も、同じ減速曲線を描けることだけで同じ機能と判定しない。停止目標、情報の有効性、制動能力、介入の保持・解除、運転士の役割まで比較する必要がある。[再調査:CAT]

## 3. 実車側の調査結果

### 3.1 方式別に確認できる責任

|---|---|---|---|
| ATS-P：JR東日本の2005年説明 | 地上子から受ける停止信号までの距離等 | 車上で連続して速度を照査し、パターン速度超過時に常用ブレーキを動作させる。[R1] | 路線・車種別の全パターン、解除閾値、信号直下・故障時を含む全復帰手順。 |
| D-ATC：2003年技術解説 | 地上からの停止区間、自列車位置・速度、車上データベース | 条件に対応する照査パターンを検索し、許容速度と実速度からブレーキを制御する。[R2] | 現行全線区の実装、すべての介入優先順位、ノッチ換算・故障時の全条件。 |
| ATACS：仙石線導入を扱う2013年資料 | 車上で検知した位置、無線で受ける停止限界、勾配・速度制限 | 車上でパターンを作り速度照査・ブレーキ制御を行う。[R3] | 埼京線等の後年導入との差、通信断・後退・モード移行の全詳細。 |
| TASC：山手線ホーム柵導入時の2008年説明 | 次駅の停止位置までの距離 | 停止用パターンへ接近すると制動を開始し、パターンに沿って定位置停止させる。[R4] | E235系各版の内部制御、手動補助の上下限式、CATのモード切替と一致するか。 |
| ATO：横浜線E233系への導入説明（2025年） | 出発操作、線路・速度制限、次駅の停止位置 | 駅間の加速・惰行・減速・定位置停止を行う。ATCによる速度保護とは分けて説明される。[R5] | CATの無人運転・自動再開・手順スキップ等に対応する実車規則。 |

### 3.2 特に混同しやすい点

**ATS-PとATS-Ps**：R1は、ATS-Pのパターン超過を常用ブレーキ、ATS-Psを非常ブレーキとして対比している。同じ「パターン式ATS」という呼び方から、同じ介入・復旧へまとめない。

**D-ATCの「一段ブレーキ」**：R2の車上制御は、従来の区間ごとの多段減速と対比される。単に一つの固定減速度を停止まで掛け続ける意味として読むのは不適切である。同資料には実速度との比較、必要ブレーキ力の計算、作用・緩解時の衝動低減の説明がある。

**ATACSの位置・制約**：R3では車上位置検知と地上・車上の双方向通信が核になっている。CATの地上信号との独自併用を、そのまま実在ATACSの定義にしない。

**TASCとATO**：停止位置制御が共通しても、TASCが駅間の力行や次駅への発車まで担当するとは限らない。R4とR5は別の機能説明であり、CATの内部構造をどちらかの図へ機械的に合わせる必要はない。

## 4. 仕様変更後も使える数理・情報の整理

### 4.1 理想的な減速曲線と実際の保護条件

**導出**：平坦、一定の有効減速度\(b>0\)、応答遅れなしで、残距離\(d\)の先の目標速度\(v_t\)まで減速する条件は、運動学から

\[
v_{\mathrm{lim}}(d)=\sqrt{v_t^2+2bd}
\]

となる。単位は速度［m/s］、距離［m］、減速度［m/s²］でそろえる。これは実車ATS-P・ATACSの完全なパターン式ではない。実車の係数や安全余裕を推定した式でもない。

CATの通常／EB移行、勾配、M/T・荷重、回生失効等がある場合、単一の\(b\)だけでは不足し得る。応答遅れ中の走行距離、移行中の減速度、低速域までの残距離を、実速度更新と同じ前提で積分する方法が候補になる。[再調査:CAT]

**考察**：速度制限の集合を扱うときは、同じ位置・同じ適用範囲に対する各制限からその地点の上限を比較する。遠方の停止目標の「0」を現在位置の即時速度0へ置き換えない。分岐先の別経路の制約を、自列車が選択した経路の制約と混ぜない。

### 4.2 パターンごとに残す情報の候補 [再調査:CAT]

| 情報 | 分ける理由 |
|---|---|
| 原因・出典（信号、先行列車、標識、駅等） | 一つが解除されても別の原因を消さないため。 |
| 適用経路・方向・区間、目標位置・目標速度 | 分岐・折返し・制限解除で対象を取り違えないため。 |
| 取得時点・有効性・再確認中 | 古い進行情報を最新扱いしないため。 |
| 使用した列車性能・版・制動応答 | 編成変更や性能変更後に古い停止予測を使わないため。 |
| 接近、通常介入、非常、復旧待ち | 表示・音・指令・保持を区別するため。 |

これはデータ設計の候補であり、クラス名・保存形式・APIの決定ではない。

## 5. Create 6.0.8の接続上の事実 [再調査:依存版]

`Navigation.tick()` 100–101行は`Train.acceleration()`を用いて停止距離を計算する。235–289行には信号／目的地までの距離選択、近距離での直接速度補正、目標速度設定、`approachTargetSpeed(1)`呼出しがある。[L1]

`Train.acceleration()` 1128–1130行は燃料状態により設定値を選び400で割って返す。[L2] この標準経路にCATの移行時間や性能プロファイルが自動的に反映されると考える根拠はない。

**考察**：標準停止処理を残してCATのパターン制動も追加すると、表示したパターンとは別の直接速度補正が働く可能性がある。どの通常制御を置換し、移動・占有・駅到達更新のどこを維持するかを切り分ける必要がある。完全な介入点の設計は未完了である。[再調査:CAT]

## 7. Minecraftで再現する上での考察 [再調査:CAT]

### 7.1 距離・時間・速度の単位

1blockの換算長、tick、km/h、m/sを統一する必要がある。例えば20tick/sを基準にする設計でも、低TPS時に実時間が伸びたとき、物理計算・通信の鮮度・警報の時間をどの時計で扱うかは別の判断である。表示換算だけ変え、停止距離側が旧単位のままになる状態を避ける。

### 7.2 自由な線路と後から変化する環境

実車の公開説明では路線データ・位置補正を前提にするものがあるが、Minecraftでは設置・破壊・分岐変更が起きる。経路変更後も古いパターンを保持できる範囲と、破棄・再計算・確認待ちへ移る条件を区別する案が必要である。路線を固定データベースにするか、グラフから動的に求めるかは未決定。

### 7.3 正確さと処理負荷

毎tick全路線を調べる方式だけが選択肢ではない。選択経路と停止に必要な範囲を探索し、グラフ更新・制約変更で再計算する案を比較できる。ただし探索上限より停止距離が長いときに何をするか、未読込情報をどこまで使えるかは先に仕様化する必要がある。

### 7.4 同時介入と操作感

安全装置の速度上限・必要制動の下限とTASCの「手前停止を避けるためブレーキを弱める」要求は、単純な平均では調整できない。INTEROSで確定する前に各要求の種類・適用範囲を残す案が適する。音やHUDは判断を知らせる役割であり、再生完了を待ってブレーキを遅らせない。

## 8. 不明点・追加資料・検証候補

- 各実車装置の全状態遷移、介入・解除閾値、時定数、故障時の処理を網羅する一次仕様書は未入手。公開説明の範囲を越えて推定で補っていない。
- E235系の対象番台・実車装置の版と、CATがどこまで同じ操作を目指すかは未決定。具体車種へ合わせる場合は対象を絞る必要がある。
- JR EAST Train Simulatorの挙動は参考にできるが、公開実車資料と別の観察記録として残す。本調査ではシミュレーターを実行していない。
- `[再調査:実機]` 検証候補：短閉塞連続、長い曲線、下り勾配、制限重複、進路変更、目標消失、保存再開、低TPS、性能の異なる列車。停止位置・実速度・要求／実効制動・原因・情報有効性を同時に比較する。
