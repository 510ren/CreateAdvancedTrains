## 8. ATOSの権限・制限速度・時刻表編集

<!-- source:s-8:end -->

<a id="s-8-1"></a>

<!-- source:s-8-1:start -->
### 8.1 指令と車上判断（決定）

- ATOSの運行上の要求はATOの通常運転判断より優先する。
- 有効な安全制約やEB解除条件はATOSでも上書きしない。
- 現時点ではATOSがノッチを指定したり、進行方向を直接操作したりする設計にはしない。将来必要になれば再検討する。
- 車上の担当機能が要求の実行可否を判断し、INTEROS経由で結果と理由をATOSへ返す。
- 目標喪失エラーからの再発車承認と基本的な時刻表編集は[第7.15・8.6・8.7節](分割記録/節の対応表.md#s-7-15)で範囲を決定した。その他の要求一覧・全受付条件は未確定。

<!-- source:s-8-1:end -->

<a id="s-8-2"></a>

<!-- source:s-8-2:start -->
### 8.2 手動運転での速度制限（決定）

- 制限速度は運転上の基準であり、それだけで手動ノッチの加速を強制的に抑えない。
- 安全装置OFFなら、制限を超えてもPノッチを続ければ列車の性能限界まで加速できる。基準まで減速するかは運転者の判断。
- 安全装置ONなら、各機能が自分の責任に従って警告・運転入力の一時無効化・制動等へ介入する。具体的な介入条件は未決定。
- ATOSの制限速度も有効な安全機能が介入判断に使う入力へ含める。[第3.1節](信号と安全装置と進路.md#s-3-1)の選択方式の内部構成・具体的担当は別途整理し、旧ATACSの内部構成を自動継承しない。
- 同じ場所・時点に適用される有効な速度制限は最小値を採用する。一つを緩和しても、他の制限は残る。
- 性能限界、運転基準の制限速度、安全装置の介入条件を混同しない。
- 先の地点の制限と、現在地点へ換算した減速制約は区別する。先の低い速度を即座に現在の速度へ代入する決定ではない。

<!-- source:s-8-2:end -->

<a id="s-8-3"></a>

<!-- source:s-8-3:start -->
### 8.3 適用範囲と永続化（決定）

- 初期段階のATOS制限は列車単位で管理できればよい。
- 将来は区間・エリア単位へ拡張できるよう、大幅な変更を必要としない構造にする。
- 明示的な変更・解除まで制限を保持する。ATO／手動の切替、保存・再読込でも維持する。
- 設計案：制限の発生元・適用対象・値・識別子を持ち、適用判定と最小値統合を分離する。具体的な型やAPIは未決定。

<!-- source:s-8-3:end -->

<a id="s-8-4"></a>

<!-- source:s-8-4:start -->
### 8.4 列車からのATOS制限解除要求（決定）

1. マスコンからINTEROSを通じて、対象のATOS制限の解除を要求する。
2. 要求中は制限を維持する。
3. ATOS側操作者が承認または却下する。
4. 承認時は要求対象と現在の制限を照合し、一致するものだけ解除する。
5. 結果をマスコンへ返す。他のATOS制限や信号等の制限は変更しない。

- 各要求と対象制限を確実に識別する。要求中に対象が変更・置換・解除されていたら、解除処理を行わない。
- 同じ数値へ戻った場合でも、別の更新であることを検出できる必要がある。
- 要求ID・制限ID・版の組合せは提案された実現方法。識別保証が要件であり、具体的なデータ形式は未確定。
- 要求が古くなった場合のUI文言、再要求、重複承認、期限、要求者・承認者の権限は未決定。
- この要求機能はATOS速度制限の解除であり、EB解除要求とは別の機能。

<!-- source:s-8-4:end -->

<a id="s-8-5"></a>

<!-- source:s-8-5:start -->
### 8.5 常時稼働と自動操作の範囲（決定）

- ATOSは導入あり／なしで動作を切り替える機能ではなく、常時動作する。プレイヤーが遠隔操作設備・画面を利用していなくても本体は動作する。
- 情報の集約・共有と操作要求の伝達は常にINTEROS経由とする。ATOSから車上の各機能へ直接操作する経路を設けない。
- 運行ダイヤ・全体の運行情報の管理主体はATOS。駅掲示板はATOS側情報を参照する。車内LCDは列車INTEROSを参照し、INTEROSが実際の列車情報とATOS情報を照合して提供状態を決める（[第13.17節](LCDと旅客案内.md#s-13-17)）。表示機器自体に運行判断を分散させない。
- 現段階ではATOSが自分の判断で速度調整、臨時制限、発車時刻変更などの運行操作を行わない。遠隔操作要求はプレイヤーの操作に基づく。
- ATOの自動運転、安全装置の介入、共通の進路管理による許可判定は各機能が担う。ATOSによる自律操作とは区別する。
- 遠隔操作がないことは、既に設定済みの制限を消す意味ではない。[第8.3節](ATOSと遠隔操作と延発.md#s-8-3)の保持規則を維持する。
- 将来の拡張候補：遅延時の発車時刻・停車時間などの自動調整。初期実装には含めず、何をどの条件で短縮・変更するか、権限、適用範囲は未決定。
- プレイヤーが事前登録した変更予約・終着時切替の条件成立時の自動実行は対応する。ATOSが自分でダイヤを最適化する自律機能とは区別する。
- 手動で設定した延発指示・予約の適用／期限終了（[第8.30節](ATOSと遠隔操作と延発.md#s-8-30)）も、自律的なダイヤ調整とは区別する。

### 8.16 ATOSの閲覧・操作権限（決定）

- 現在情報・設定内容の閲覧は全プレイヤーへ開放する。操作権限のない項目はグレーアウトし理由を表示する。
- 遠隔操作の要求権限はサーバー側で決める。「制限なし／指定プレイヤーのみ／サーバー管理者のみ」を選択でき、既定はサーバー管理者のみ。管理者判定・許可者登録の具体方式は要設計。
- 遠隔要求、変更予約、一括更新、終着時切替設定、包含・除外フィルター・優先順位などの作成・変更・削除は、初期段階では共通の操作権限で扱う。列車別所有権や路線別担当権限をここで追加しない。
- ATOS保存ダイヤの原本管理もこの共通権限を使用し、作成者本人に限定しない。閲覧・列車側管理・確定時の再確認・原本だけの走行中管理は[第8.29節](時刻表と保存ダイヤ.md#s-8-29)による。
- キー所持・列車組立者であることだけでは権限を得ない。安全制約・停止条件・解除条件は権限によって上書きできない。
- ATOSの実操作には権限に加え、ATOS操作用ブロックまたはアイテムを使う。両方を用意するか・具体形態／操作範囲は未決定。表示器・HUDで指示を閲覧できることだけでは変更・解除できない。保存ダイヤのATOS側保存入口はATOS関連アイテム（[第8.29節](時刻表と保存ダイヤ.md#s-8-29)）とする。
- サーバーが要求・変更を受け付ける時点で権限を確認する。GUIを開けた時点では許可されていても、確定時に失っていれば拒否する。
- 受付済みの予約・設定は、登録者のログアウト・権限喪失だけでは無効にしない。明示取消はその時点の権限保有者が行う。通常の適用・破棄・失効条件は引き続き有効。

### 8.30 出発時機表示器・ATOSの延発指示（決定／表示・同時処理等は未決定）

**目的・操作権と基本動作**

- 運転手向けに延発等の運行指示を表示する出発時機表示器を追加する。ATOS管轄の手動ダイヤ調整機能であり、自律的なダイヤ調整の追加ではない。延発以外の指示種類は未決定。
- 設定・予約・変更・解除にはサーバー側のATOS操作権とATOS操作用ブロック／アイテムの使用を必要とする。作成者本人に限定せず、同じ操作権を持つ他者も管理できる。
- 運転手／車掌権限だけでは解除できない。別途ATOS操作権を持ち操作用機器を使う場合は可能。閲覧は従来どおり全員に開放し、表示器・HUDは閲覧できるだけで操作機器の代用にはならない。
- 操作画面を閉じる、ログアウト、機器の撤去／アイテム喪失だけでは確定指示・予約を解除しない。ATOSが保持して終了条件に従う。
- 手動運転では指示を表示・通知するが、その指示だけで力行を禁止しない。ATOでは有効な指示がある間は発車待機する。解除／期限終了は進行許可ではなく、時刻表・閉扉・信号・進路許可等を別途満たす必要がある。
- ATO→手動でも指示は維持し案内へ切替。手動→ATOで同じ停車回の指示が有効なら待機する。ATO解除の通常引継ぎ条件を省略しない。手動発車で終了した指示を、後のATO有効化で駅間に復活させない。

**対象・1件管理・予約**

- 対象は「列車＋ホーム（駅）＋1回の停車」。適用中指示はホームごとに最大1件とし、複数指示を積み重ねて全解除を待つ案は採用しない。
- 既存指示への操作は追加でなく変更・解除。別列車／停車回へ変更する場合は、旧対象の延発が解除される旨を示し確認する。他者が先に変更したら古い画面のまま上書きせず最新内容で再確認する。
- 到着前から対象停車回への指示を設定でき、停車中も設定・変更できる。発車後の終了済み停車回への指示は受け付けず、駅間で止めたり呼び戻したりしない。
- 将来の停車回への予約は適用中と別枠で複数登録できる。同じホーム・列車・停車回には重複予約を作らず編集として扱う。
- 予約は対象列車の対象ホームへの停車を確認し、ATOの発車可否判断より前に適用する。ATOS画面では適用中と予約を区別し、予約だけで現在の別列車への指示を変更しない。
- 対象列車の発車でその停車回の指示・予約・競合待ちを終了し、次の周回・後続へ持ち越さない。対象停車予定の削除／喪失を確認した場合も終了・取消して設定者へ通知する。
- 新規選択は駅名・サジェストを使えるが、確定後は選んだホームと列車・停車回を識別する。改名後も同じ対象を維持できれば表示名を更新して継続し、予定が失われれば終了する。同名新設駅へ自動で付け替えない。具体的IDと判定方法は要調査。
- 延発予約と時刻表変更予約は別種。延発の「対象喪失で取消」を、[第8.11節](時刻表と保存ダイヤ.md#s-8-11)の「一致駅なしでも名前条件を保持する」時刻表変更予約へ流用しない。

**終了条件・時刻変更**

- 「明示解除まで」と「指定時刻まで」の2種類を用意し、どちらも途中で権限者が解除できる。
- 時刻指定はワールド内の「日＋時刻」で特定する。画面では時・分を基本に対象停車回に対応する終了日時を確認できるようにする。過ぎた時刻を自動で翌日へ繰り越さず、翌日なら明示指定する。
- 終了日時を過ぎてから対象列車が到着した予約は期限切れ終了とし、新しい延発・競合待機を発生させない。到着から同じ延発時間を数え直さない。
- 睡眠・コマンド等で時刻が進み終了日時を越えたら次の判定で終了する。時刻が戻っても終了日時は変えず、有効な指示はその日時まで維持する。待機が延びる旨をATOS操作画面で知らせる。
- 終了済み指示・予約は時刻が戻っても復活しない。「明示解除まで」は時刻変更で解除しない。
- [第8.19節](時刻表と保存ダイヤ.md#s-8-19)のCreate標準の周期／成立窓とは別の期限判定であり、標準時刻待機を今回の方式へ変更しない。

**予約適用時の競合と選択期限**

- 別の適用中指示が残っている場合、予約を自動上書き／重ね適用せず競合として通知する。権限者が「既存指示維持」「予約指示へ置換」を選ぶ。
- 競合解消まではATOの対象列車を発車待機させる。これは2件の延発適用ではなく指示確定待ち。手動では通知のみとし力行禁止にしない。
- 時刻指定同士の選択期限は最も遅い延発終了日時。競合発生から延発時間を数え直さない。未選択で期限に達したら対象停車回の期限切れ指示・予約と競合待機を終了し、その旨を通知する。
- 他の列車・停車回の指示を、この期限処理で勝手に解除しない。「長い方を自動採用して上書き」する方式でもない。
- 「明示解除まで」が競合に含まれる場合は自動終了させず、長時間放置を通知する。この場合は有限の選択期限を設けない。
- 正常な発車／対象喪失で旧指示が終了することを前提に、実際に競合が生じる条件、維持／置換を選んだ後の予約処理、異なる対象間の解除責任と同時処理は詳細化が必要。

**表示器・HUD**

- 1台の表示器は1つの駅ブロック（ホーム）に関連付ける。同じホームへ複数設置でき、同じATOS指示を参照する。複数ホームを束ねるワイルドカード指定は使わない。
- 指示の管理主体はATOSであり、表示器の追加・撤去・破壊で指示を増減・解除しない。
- 表示器は現在そのホームに停車する列車の対象停車回、HUDは自列車の対象停車回に一致する指示だけを表示する。後続予約を現在の列車への延発として表示しない。
- 有効指示なし／時刻指定延発／明示解除待ち／競合の選択待ち／情報確認不能を区別し、不明を指示なしに見せない。
- マスコンHUDの通知領域にも併記し、操作を妨げるオーバーレイにしない。解除も知らせるが「出発可能」と断定しない。
- 文字・配置・点灯方式・消灯の意味等の具体レイアウトは実画像確認後に決める。会話中の「延発」「指示確認待ち」等は意味の例であり、文言・外観を確定しない。

**保存・残課題**

- 適用中指示、予約、対象列車／ホーム／停車回、終了日時、競合待ちを保存する。再起動後は対象と時刻を再確認し、有効なら継続、期限後なら終了する。選択期限を数え直さず、明示解除指示も再起動だけで解除しない。
- 対象情報が未取得なら消失と推測せず確認待ち。停車回の削除・終了を確認してから終了し、別対象へ付け替えない。操縦権・ATOの復帰条件とは別に扱う。
- 連結／分離時の識別継承、時刻表の変更・使用終了と対象停車回、指示設定と発車の同時処理、延発中の時刻表待機の計測、状態不明時の詳細、予約受付の範囲・期限更新・通知の宛先／間隔は今後確認する。既存の安全制約を上書きしない。
