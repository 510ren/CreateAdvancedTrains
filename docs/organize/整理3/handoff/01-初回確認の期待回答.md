## 1. 作業境界と通常の担当・設備条件

根拠：[ドア11.19](../乗務員とドアと停車保持.md#normal-duty-change)、[HUD11.9](../マスコン操作とHUD.md#s-11-9)・[11.32](../マスコン操作とHUD.md#s-11-32)、[01の保存区分](01-handoff.md#current-state)。

- 作業場所はC:\Products\Minecraft-CreateAddons\CreateAdvancedTrains。要件整理段階で、詳細は分野本文。事項1～59と訂正は保存済み、事項60はA推奨・未回答。拡張範囲・全状態表・技術検証は未完了。
- 車掌の交代・同一人の設備移動とも、旧利用を終了して占有・役割を解放し、車掌不在を経て移動先で明示取得。自動移譲・移動中の権限保持をしない。車掌専任の交代自体は走行中も可能だが、開扉・選択値手動変更・運転担当を兼ねるHUD全体終了等の個別条件を省略しない。受付済み開閉・保護・保持は離脱だけで取消さない。
- 統合ワンマンの初回通常開始は両権限一括。車掌機能不要の標準のみワンマンは運転だけ。既存の兼任者はHUD・運転手／ATO担当を維持して車掌だけを解除・再取得でき、再取得失敗で運転側を失わせず、兼任台の前を後へ上書きしない。ワンマンのまま別人の車掌取得は不可、ツーマンの同一人兼任も不可。
- 共通キーはアイテムのマスコンキー。車掌設備・統合の車掌専任では不要。運転・兼任ではServer Configの既存条件に従う。運転用キーの抜去条件を変更せず、キーを本人確認の代用にしない。
- 通常の形態変更は完全停止中の現運転手／ATO担当による明示要求。反映直前に現在の使用台・方向・必要設備・権限・切替ロック等を再検証。不足・確認不能なら理由を分けて拒否し、旧形態・旧権限を維持、予約・自動再試行なし。成功時は形態・役割変更を一体反映し、必要な車掌は明示取得。ATO ONでも可能だが、それだけで発車しない。
- 組立40-Aは少なくとも一方向で必要設備が揃うことを必要とし、担当不在を設備不足にしない。設備の寸法・認識・設置判定は未決。42-Aの運用中の物理喪失は成立経路確認後に専用処理を判断し、未読込・情報取得失敗・担当喪失と区別する。未決であることを運転継続の許可にしない。

## 2. ドア対象・操作・競合

根拠：[ドア11.20](../乗務員とドアと停車保持.md#s-11-20)・[11.21](../乗務員とドアと停車保持.md#s-11-21)・[11.23](../乗務員とドアと停車保持.md#s-11-23)・[11.26](../乗務員とドアと停車保持.md#s-11-26)・[11.28](../乗務員とドアと停車保持.md#s-11-28)・[11.29](../乗務員とドアと停車保持.md#s-11-29)・[11.31](../乗務員とドアと停車保持.md#s-11-31)、[保持3.4](../乗務員とドアと停車保持.md#s-3-4)。

- 初期対象は標準Createスライドドア。Create単体は全て対象、個別除外不可。Steam ’n’ Rails併用ではnormal・specialが対象、manualが対象外、special_invertedは初期対応外で組立前の変更を案内。黙って安全集計から除外しない。除外にSnRのmanual設定が必要というWiki案内は今後。初期は標準の通行・当たり判定を使い独自挟み込み検知／再開扉を追加しないが、実機で支障なしと検証済みではない。
- 直接クリック許可は対象となるCreate単体／normalについて、停止中・権限者の有効開扉で実際に開きロック解除された側に限る。要求待機だけでは不可。specialへ直接操作を追加しない。正式閉扉受付・移動・編成変更による失効を維持する。
- 自動開扉・閉扉は初期OFF、解体再組立も初期値。列車単位で現運転手・ATO担当・車掌が個別変更可。ATO ON/OFFと独立し、標準の駅到着自動開閉は独立実行させずCAT判断へ一本化する。役割の優先順位でなく先に成立した設定変更を維持し、古い表示からの反対変更を拒否して現在値を示す。
- 新規開扉は指定側の必要情報を確認するまで開始しない。手動は拒否・予約なし、自動は待機。開始済みの開閉は、不明になったことだけで取消・停止・反転・再送しない。確認不能のまま全開／全閉・正式閉扉ロックの完了とせず、回復後に現在実状態で判定。力行禁止・Configに応じたドア保持、成立済み要復旧、他理由を維持する。通知まで安全制御を待たせない。
- 未開始の手動／自動閉扉は動作を一回に統合しても由来を保持する。自動閉扉OFFで自動由来だけを取消し、手動由来は維持。明示再開では未開始手動閉扉の取消・通知と現在指示の再評価を行い、動作中・不明時の再開受付条件を迂回しない。進行中・全閉確認待ちを再開だけで取消・反転・完了させない。
- 実際の編成・権限更新中は新規開閉等を処理中の理由で拒否し予約しない。受付済み動作は元対象で継続し、新結合ドアへ拡張しない。再読込は現在状態を確認し、保存済みというだけで警告解除・自動ロック・失効許可復活をしない。厳密な処理順・保存同期は調査待ち。

## 3. 連結後の終了と不明記録

根拠：[HUD43～50](../マスコン操作とHUD.md#coupling-duty-end)、[列車2.4](../列車構成とプロファイル.md#s-2-4)、[ドア不明記録](../乗務員とドアと停車保持.md#unknown-door-record)、[ドア11.20](../乗務員とドアと停車保持.md#s-11-20)・[11.30](../乗務員とドアと停車保持.md#s-11-30)、[非常6.6](../非常制御と故障復旧.md#s-6-6)、[通知8.15](../共通方針と責任分担.md#s-8-15)。

- 非継続側の手動運転・車掌は通常操作を止め終了専用とし、必要工程を経て利用・占有を解放する。連結成功だけで手動利用を自動終了しない。非継続側ATOは必要な保持・旧台終了条件を確認して自動終了し、現地担当者の終了操作を必須にしない。確認不能・条件不足では保持・理由表示を続ける。
- 継続側の手動台・車掌設備が中間台なら旧設備で終了・解放し、適格な外端で明示取得。移動中の本人予約・他方への自動移譲なし。運行継続側の時刻表・進捗を正常終了だけで破棄せず、新台取得だけで発車しない。継続側ATOの外端移行は既存2.4の別手順。
- 必要な制御上の終了・選択値・保持受渡しを実際に確認後、旧画面終了だけを発車条件にしない。通常操作が残る、または必要処理・保持が確認不能なら発車不可。車掌終了だけで運転側が終了中の共有台を中にしない。操作順を固定するかは事項60が未回答であり、A推奨を決定扱いしない。
- 通常操作権を失い終了専用へ移行済みの旧担当が死亡等で離脱しても、その離脱だけで新たな担当喪失EBにしない。未完了工程・停止保持・他の非常理由は残す。実際の手動操縦担当喪失は既定の要復旧EB、移行未確認を移行済みと推定しない。
- 未完了の終了処理は元の人・別の人が完全停止中に明示取得でき、設備の同時操作不可・操作に必要なキー等を再確認。通常運転／車掌権限、ドア、時刻表編集を与えず、完了済み処理を二重実行・巻戻ししない。引継ぎだけで要復旧を解除しない。
- 不明記録の連結は継続する事象だけを対象とし、経過時間は長い方で合算しない。通知済みの記録を維持し連結だけで再通知しない。分離は継続する不明ドアを含む側だけへ同じ記録を継承し、双方にあれば双方。終了済み事象を持ち込まず、回復後の新発生は新規。
- 通常再読込・再起動でも継続記録を維持し、現在情報で回復を判定する。列車の処理が止まる未読込・サーバー停止中は加算せず、列車処理が続きドア情報だけ取れない間は加算。時計・低TPS・処理再開判定・具体時間は未決。
- 通知条件成立時のオンライン現運転手・車掌へ一度、同一人物は重複なし。不在者へ後送りせず、誰にも配信していなくても通知機会は処理済み。実配信とは区別し、その処理済み記録も継承。担当取得・再読込だけで再通知せず、通常表示を続ける。一般の組立者向け長時間待機定期通知、同じ指示／停車機会の駅不一致通知とは別。

## 4. メロディー・確認工程・残り作業

根拠：[音響13.10](../音響とSpeakerController.md#s-13-10)・[59-A](../音響とSpeakerController.md#conductor-melody-edit)、[時刻表8.27](../時刻表と保存ダイヤ.md#s-8-27)、[01の範囲](01-handoff.md#next-scope)・[事項60](01-handoff.md#matter-60)、[共通手引き](../../../workflow/会話引継ぎと開始の手引き.md#initial-check)。

- 自動再生は初期OFF、解体再組立で初期化、通常再読込・再起動では維持。連結は継続側、分離は直前共通設定。自動再生はATO有効が必要で、ドア自動開閉のATO非依存を流用しない。
- 車掌の限定編集は使用中時刻表のメロディー子手順のController指定と指定時間／手動停止までの条件だけ。駅・経路・他条件、手順追加削除並替え、進捗変更・手動完了・スキップ・強制完了、保存原本管理、Controller本体音源設定は含まない。既存の停止中・処理中等の受付条件を維持。再生中編集の反映と開始済み再生の終了／再試行との接続は③に残し、暗黙の停止・再送・完了を新たに決めない。
- 01の初回読解・第三者確認は準備時点で未実施、旧判定は未受領。初回回答後は旧チャット判定待ち。00の2026-11-05合格は旧移行の実績、引継ぎ元自己点検は直接照合の記録で、01の独立確認・合格の代替ではない。実行モデル／実推論レベルは取得根拠がなければ取得不可。
