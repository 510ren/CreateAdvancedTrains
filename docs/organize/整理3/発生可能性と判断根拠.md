# 発生可能性と判断根拠

作成日：2026-10-28 ／ 最終確認日：2026-11-01

状態：要件整理における判断記録。検討方法は利用者の指示に基づく。個別の発生可能性評価は、下記の根拠と確認範囲に限った暫定判断であり、正式REQ／SPEC・実装の検証結果ではない。

関連：[整理3の索引](../整理3.md)、[残課題と再開地点](残課題と再開地点.md)、[ドキュメント管理手順](../../workflow/ドキュメント管理手順.md)。製品の合意済み動作は各分野の本文を更新先とし、本書に並行した仕様を作らない。

## 1. 検討方針

- 例外処理や派生機能を決める前に、「本当に起こり得るか」「起こらないと判断するなら何がそれを防ぐか」を検討する。既存の操作制限・状態遷移・他機能との関係を先に確認する。
- 方針が明確な事項はそのまま進め、派生した未整理の想定を事実として固定しない。すべての判断に完全な証明を要求して検討を止めるものではない。
- 正常な利用者操作、外部イベント、未読込・再読込、外部MODによる変更、実装不具合を区別する。可能性のある異常を列挙しただけで専用の製品機能を追加しない。
- 「発生経路を確認していない」と「発生しない」は異なる。「現在の仕様では抑止」は、実装上も必ず抑止できると検証した意味ではない。
- 発生し得る場合も、既存処理で扱えるかを先に確認する。新しい対処が必要な部分だけを追加判断する。
- 本書も常に見直し対象とする。前提が変わった場合、根拠と反例を再確認する。本書だけを理由に確認や安全制御を省略しない。
- 既存合意の変更が必要なら、対象本文・根拠・影響を利用者に示して相談する。本書の暫定評価だけで合意を撤回しない。

## 2. 記録と更新の方法

各項目に、対象事象・必要条件・判断・根拠の種類と参照先・適用範囲・未確認部分・見直し条件・次の扱いを残す。根拠の種類は、合意済み要件、提供ソースの確認、利用者の実機観察、調査資料、推論を区別する。ソース確認には対象版、実機観察には環境・条件を記録する。

| 判断 | 意味 |
| --- | --- |
| 発生経路あり | 記載条件で成立する経路がある。実機で再現済みとは限らず、根拠の種類を併記する |
| 現在の仕様では抑止 | 特定の操作・状態・期間では既存規則により抑止される。範囲外には一般化しない |
| 未確認 | 成立経路または抑止根拠が不足している。発生・不発生のどちらにも確定しない |

原因と結果の結び付き自体が成立しない場合は、その区別も記録する。「担当離脱は発生するが、それだけで使用台が利用不能になるわけではない」などを、事象全体が起こらないと省略しない。

前提の変更・反例・根拠資料の更新を得たら該当項目を再評価し、判断を変更した理由を履歴に残す。製品判断が必要な残件は[残課題と再開地点](残課題と再開地点.md)へ接続する。毎回全項目を調べ直すのではなく、変更の影響がある項目を確認する。

## 3. 初回評価：連結・分離に伴うATO使用台の移行

以下は2026-10-28の初回評価を、2026-10-29保存の合意に合わせて更新した要件上の評価。今回、新たなソース調査・Minecraft実機検証は行っていない。前提となる移行手順は[列車構成とプロファイル2.4節](列車構成とプロファイル.md#s-2-4)。

### 3.1 編成更新中の利用者操作による使用台変更

- **判断：現在の仕様では抑止。** 実際の編成・制御更新中は、使用台変更等を拒否し、拒否入力を後実行しない。
- **根拠：合意済み要件。** [2.4節](列車構成とプロファイル.md#s-2-4)の更新中操作制限。
- **範囲・未確認：** 準備・待機の全期間には拡張しない。条件待ち中の明示再選択と、実際の切替中の変更拒否は2.4節へ保存済み。外部変更・実装での全入力経路の抑止・厳密な処理境界は別途確認が必要。
- **見直し条件・次の扱い：** 更新期間や操作受付を変更した場合に再評価する。正常操作でこの制限を破ることを前提に、専用の復旧手順を増やさない。

### 3.2 ATO操作担当の離脱

- **判断：離脱の発生経路はあるが、離脱だけによるATO使用台喪失は既定動作ではない。**
- **根拠：合意済み要件。** [2.4節](列車構成とプロファイル.md#s-2-4)では保持引継ぎ待ちのATO担当離脱だけなら保持・引継ぎを続ける。[11.18節](マスコン操作とHUD.md#s-11-18)でも担当離脱だけでATOを止めない。
- **範囲・未確認：** 手動へ切替成立後の担当喪失、キー条件、別の非常原因は別判定。担当離脱と同時に別の条件が失われる場合まで否定しない。
- **見直し条件・次の扱い：** ATOの有人条件・担当権限を変更した場合に再評価する。離脱だけを新しい「移行先利用不能」の理由にしない。

### 3.3 外側台の不存在・不適切な向き

- **判断：準備時点からの条件不足として扱える。選択後に突然変わる経路は未確認。**
- **根拠：合意済み要件とその整理。** [2.4節](列車構成とプロファイル.md#s-2-4)は外側台不足等でも他の条件を満たせば連結自体を認め、ATOの発車は認めない。
- **範囲・未確認：** 当初からの不足と、選択後の設備・編成変更を区別する。後者の成立経路を確認する前に一般的な故障として扱わない。
- **見直し条件・次の扱い：** 組立後の設備変更や候補算出方法を追加した場合に再評価する。既決の準備時確認と発車不可の扱いを維持する。

### 3.4 組立済みマスコンの突然の破壊・欠損

- **判断：未確認。** 通常操作での成立経路を今回確認していないため、発生するとも、絶対に発生しないとも断定しない。
- **根拠の限界：** [11.4節](マスコン操作とHUD.md#s-11-4)ではマスコン破壊等の全規則は未決。[11.23節](乗務員とドアと停車保持.md#s-11-23)の「通常の組立後ドア破壊は想定しない」はドアについての記録であり、マスコンへそのまま一般化しない。
- **範囲・未確認：** 通常の解体、情報未取得、脱線、外部MODによる設備変更を欠損と同一視しない。対応が必要になれば、提供ソース等で対象・版・発生経路を確認する。
- **見直し条件・次の扱い：** 組立後の編集・破壊に対応する場合や、実際の欠損報告を得た場合に再評価する。現時点で専用の通常運用手順を確定しない。

### 3.5 選択済み移行先のキー条件の変化

- **判断：準備・条件待ちでは発生経路あり、実切替中の通常操作では抑止。** いずれも要件上の判断であり実機再現・実装検証ではない。
- **根拠：合意済み要件。** [11.9節](マスコン操作とHUD.md#s-11-9)の完全停止・対象台EB＋切・権限制限を満たす場合、未使用台のキーを取り出す経路がある。[2.4節](列車構成とプロファイル.md#s-2-4)で選択だけでは固定しないこと、実処理中は関係台の抜去を拒否することを明確化した。
- **範囲：** ATO有効のまま未使用の選択台のキー不足で待つ場合と、使用台の抜去によりATOを終了した場合を区別する。キー必須OFFでは抜去だけを移行阻害理由にしない。
- **既存処理との接続：** 条件待ち・キー補充後の再確認・明示再選択で扱う。新たな一律の再開承認や、待機中の無期限な操作固定は設けない。詳細は2.4節を正本とする。
- **未確認・見直し条件：** キー受付・操縦権・移行期間の変更時に再評価する。外部操作による喪失、実処理の境界や同時入力を確実に抑止する方法は未検証。

### 3.6 移行途中の脱線・非常状態

- **判断：既存要件で考慮する外部事象・安全要求の経路がある。具体的な同時発生は未検証。**
- **根拠：合意済み要件。** [2.4節](列車構成とプロファイル.md#s-2-4)は更新中も安全要求を受け付ける。[6.1節](非常制御と故障復旧.md#s-6-1)に編成変更途中の要復旧EB、[11.17節](非常制御と故障復旧.md#s-11-17)に脱線・復線時の規則がある。
- **範囲・未確認：** 停止しているだけで他列車衝突まで否定しない。一方、すべての非常原因が移行中に発生すると決め付けない。[2.4節](列車構成とプロファイル.md#s-2-4)へ、旧台ホーム位置を巻き戻さず復旧後に未完了工程を再確認して継続する合意を保存済み。未知の故障への全面流用はしない。
- **見直し条件・次の扱い：** 非常・脱線の共通処理との接続を維持し、原因・処理境界が変わったとき再評価する。実装上の同時発生・保存整合は引き続き技術確認が必要。

### 3.7 保存・再読込時のATO移行途中状態

- **判断：途中状態が保存対象になるかは実装境界によるため未確認。** ワールドの終了・再読込は運用上想定するが、使用台移行の各工程間で必ず保存できるとは断定しない。
- **根拠：合意済み要件と未確定の実現方法の区別。** [11.15節](マスコン操作とHUD.md#s-11-15)の折返し保存・再確認を参考に、[2.4節](列車構成とプロファイル.md#s-2-4)へ、物理的な編成変更成立後の移行状態が保存される場合の復元要件を記録した。
- **範囲：** 選択台・進捗・待機理由を保持し、情報未取得を喪失と推定しない。候補未選択時の残り期限保存も合意済み。物理的な連結・分離の途中保存や破損データの修復方式を確定するものではない。
- **未確認・見直し条件：** 保存可能な処理境界、編成状態と移行記録の整合、読込順、処理再開可能な状態の判定は技術調査・設計で確認する。途中状態が保存されない構造なら、その根拠を追記して適用範囲を絞る。

## 3A. 接近・停止後の判定で区別する事象（2026-10-30）

- **接近途中の端の距離・向きの違い：それだけでは不適合の根拠にならない。** 曲線等で接近に伴い相対位置・向きが変化するため、予定連結位置の接続条件と区別する。要件上の整理であり、予測方法・事前判定可能範囲・許容値は未確認。幾何モデル変更時に再評価する。
- **正常停止後の取消・再準備：操作上の発生経路あり。** 2.4節はホーム位置操作待ちと取消を認めるため、その場での再準備を検討対象とする。取消後の新たな衝突とは区別する。停止状態から成立を検知できる技術的な方法は未確認であり、標準衝突処理へ接続する際に検証する。
- **相手の情報失効：消失・取消を意味しない。** 既存9.3節の情報有効性方針に沿う。具体的な取得不能の発生経路・期限は調査対象で、未読込だけを失効理由にしない。情報管理方式変更時に再確認する。製品動作の更新先は2.4節とする。

## 3B. 編成更新・保存・未読込の技術確認（2026-10-31）

根拠は[連結調査4A・4C](../調査関連/運転・車両特性/CAT連結分離_調査依頼と確認状況.md)の提供済みCreate 6.0.8静的確認。詳細なソース事実は同資料を更新先とする。実機検証は未実施。

| 対象事象 | 暫定判断・必要条件 | 未確認範囲・見直し条件と次の扱い |
| --- | --- | --- |
| 未読込のため車両Entityが存在しない | 標準処理に保存・除去・再生成の経路あり。列車自体の喪失とは異なる | 連結に必要な情報の鮮度・有効性は別途検証。Entity管理や情報取得方式の変更時に再評価 |
| 列車処理の反復中に登録一覧を直接変更する | そのような実装をした場合の問題候補。CATの更新方式が未決のため製品上の発生は未確認 | 確定タイミングで避けられるかを先に検討。専用の利用者復旧手順を追加しない |
| 複数tickの編成更新途中を別処理が参照する | 更新を分割し、途中状態を公開する設計なら可能性あり。方式未決のため未確認 | 一括更新できる範囲・確定境界を確認後に絞る。全ての途中段階を必ず保存・復元すると決めない |
| 通常保存が同一処理の途中へ割り込む | 未確認。Create側の保存メソッドだけでは呼出し順を証明できない | Minecraft 1.20.1本体の保存呼出し・実行順を確認する必要がある。今回のvendor検索では該当本体Javaを発見していない |
| ファイル書込み中の障害 | 一時ファイル・旧ファイルを使う処理は存在。CAT状態・Entityを含めた一括整合は未確認 | 論理的な編成更新途中とディスク障害を分け、保存方式確定後に再評価 |
| 新境界の間隔不整合による位置補正 | 標準は目標間隔との差を移動へ反映するため、不整合なら補正の可能性あり（推論） | CATの明示指定位置・台車間隔変換と併せて確認。程度・不自然な飛び・衝突の実発生は未検証 |

上記を不発生の保証や既決手順の撤回に使わない。指定方法、更新方式、依存版、反例が変われば再評価する。

## 3C. 連結器の形状・許容差と予測（2026-11-01保存）

詳細根拠は[連結調査4D](../調査関連/運転・車両特性/CAT連結分離_調査依頼と確認状況.md#coupling-geometry-followup)。以下は条件付き評価で、実機確認・不発生保証ではない。

| 対象 | 暫定判断・根拠 | 未確認・再評価条件 |
| --- | --- | --- |
| 自由指定で端数の基準間隔が必要になる | 取付位置と長さの組合せ次第であり必然ではない。規定設置・同サイズ方式へ変更して回避を目指す | 寸法・台車・設置条件が確定した時に整数化を検証。実座標の端数と区別 |
| 許容位置で停止した後、標準補正が動かす | 目標間隔との差を移動量へ加えるコードがある。通常移動量0だけでは補正停止を保証しない | CATの保持・補正設計と実機で再評価。位置許容は自動移動の承認ではない |
| 車両単体は通れるが接続部の限界を超える | S字・勾配変化等で隣接車体の向きが異なるため幾何学的可能性あり | CAT寸法・可動限界未決のため具体発生例は未検証。専用故障を自動追加しない |
| 未読込なので形状を取得できない | グラフに形状の保存・取得機構があり、未読込だけで不能と断定できない | 更新経路・有効性・特殊区間を確認。全範囲取得可能とも断定しない |
| 仮移動で実列車や信号を更新する | 独立した走行点と無処理コールバックを使う標準例あり。実列車の移動は必須ではない | CAT用分岐選択・各コールバックの副作用と参照更新を確認。実走行の補正再現・精度保証とは別 |
