### 12.2 速度処理の事実

- Navigationは `v²/(2a)` を使う標準の停止距離計算、接近時の直接速度補正、目標速度代入と `approachTargetSpeed(1)` を行う（同ファイル100・235～289行付近）。CATの移行時間付き制動仕様をそのまま満たすものではない。
- Trainの信号・駅到達処理には `speed = 0` がある（444・461行付近）。
- Trainには通常の自然減速がある（568行付近）。
- ブロック・脱線・衝突等にも速度変更がある。通常の制御置換と障害物・事故処理の責任は分けて調べる。

### 12.3 曲線距離の追加調査

**直接確認した事実：**

- [BezierConnection.java](../../../vendor/Create-mc1.20.1-6.0.8/src/main/java/com/simibubi/create/content/trains/track/BezierConnection.java) 341～400行付近：曲線全長は16分割の点間距離和による近似。別にstepLUTを持つ。
- 同206行付近：小刻みな移動のパラメーター更新は現在位置の微分の大きさを使う。
- [TravellingPoint.java](../../../vendor/Create-mc1.20.1-6.0.8/src/main/java/com/simibubi/create/content/trains/entity/TravellingPoint.java) 199行付近と401行付近：`t = position / edge.getLength()` を用い、更新後に `position = t * length` とする。曲線上のpositionは常に実弧長そのものではない。
- 同214行付近：長距離探索の不正確さと回避処理に関するコメントが残る。
- [TrackEdge.java](../../../vendor/Create-mc1.20.1-6.0.8/src/main/java/com/simibubi/create/content/trains/graph/TrackEdge.java) 81～93行付近：長さとincrementTの処理。移動距離絶対値が5を超える場合は曲線の微分補正を使わない分岐がある。
- Navigation 141行付近：先読み距離へ50を追加する回避処理がある。精度保証ではない。
- TravellingPoint 357行付近：信号への距離通知は辺の長さと辺上の位置から組み立てられる。

**導出・説明用の数値計算（Minecraft実測ではない）：**

半径16相当の90度曲線を表す3次ベジェ、制御点距離 `16 × 4/3 × tan(π/8)` を使い、倍精度で比較した。

| 値 | 計算結果の概数 |
| --- | --- |
| 16分割の折線近似全長 | 25.126159 |
| 高分割Simpson積分の全長 | 25.136267 |
| t=0.25までを近似全長×0.25で求める | 6.281540 |
| t=0.25までを曲線に沿って積分する | 6.396314 |

全長近似の差と、途中のパラメーター位置を距離とみなす差は別である。この例は最大誤差・CATの許容値・実ワールド上の誤差を決めるものではない。倍精度計算であり、Minecraftのfloat演算を完全再現したものでもない。

**改善案（未実装・未承認の具体方式）：**

- 曲線パラメーターと累積弧長の対応表をCAT側で持ち、位置を距離へ換算する。
- 経路上の完全な辺と、端の部分辺をそれぞれ積算する。単純なposition差へ依存しない。
- 曲線ごとの表を再利用し、線路変更時は破棄・再構築する。
- 実際のCreateの小刻みな移動と幾何距離は別に比較する。距離を補正しただけで停止精度まで保証済みとはしない。

未確認：直線・曲線途中・曲線境界・逆方向・勾配・分岐・次元境界での誤差上限、計算負荷、読込境界での情報可用性、停止予測との整合。

### 12.4 進路候補と次信号表示の追加調査

ローカルソースから確認した事実：

- [SignalPropagator.java](../../../vendor/Create-mc1.20.1-6.0.8/src/main/java/com/simibubi/create/content/trains/signal/SignalPropagator.java) 112行付近：`collectChainedSignals`は分岐先の信号を集め、信号IDと向きの対応を返す。返り値に経由分岐一覧・距離は含まれず、同じ信号に至る別経路をそれぞれ表す形式ではない。
- [EdgeData.java](../../../vendor/Create-mc1.20.1-6.0.8/src/main/java/com/simibubi/create/content/trains/graph/EdgeData.java) の`getPoints`・`next`、TrackGraphの`getConnectionsFrom`、TrackEdgeの`canTravelTo`に、線路上の情報と進行可能な接続を調べる材料がある。
- [SignalBoundary.java](../../../vendor/Create-mc1.20.1-6.0.8/src/main/java/com/simibubi/create/content/trains/signal/SignalBoundary.java) は方向別の`cachedStates`を保持する。一方、322行付近の`write(FriendlyByteBuf, ...)`では基底情報と区間IDを書き込み、現示は含めていない。確認したこの通信経路だけで描画距離外の最新現示をHUDへ送れるとはいえない。

### 12.5 実車TASCの参考調査（CAT仕様とは区別）

- [JR東日本・2008年のホーム柵導入資料（別紙2）](https://www.jreast.co.jp/press/2008/20080603.pdf) は、停止位置までの距離からTASCパターンを生成し、接近に応じてブレーキを調整する仕組みを説明している。
- [JR東日本公式解説（2024年12月24日更新）](https://media.jreast.co.jp/articles/35) は、山手線の改良型TASCを手動ブレーキ主体の補助として説明している。同記事のB1等の操作案内はシミュレータ向けであり、全路線・車両共通の実車取扱いとして一般化しない。
- [鉄道総研・ブレーキ力低下の補償研究](https://www.rtri.or.jp/rd/seika/2020/1-07.html) は、同じ指令でも減速効果が変動し、運転士やTASCが指令を調整して停止精度を確保することを説明している。
- [第7.5～7.11節](分割記録/節の対応表.md#s-7-5)の可変上下限、通常性能範囲内の力行補助、ボタン自動停止、後退修正はCATの承認仕様であり、これらの資料から実車の同一動作を確認したという意味ではない。実車の距離・速度・精度値をそのままCATの設定値へ採用しない。

### 12.6 運転台方向・編成変更の別チャット調査

- 報告作成時は連結アドオン未指定だったが、その後の利用者報告でSteam ’n’ Railsと判明した。対象版と内部判定の確認は未完了。[第2.3節](列車構成とプロファイル.md#s-2-3)の実機報告から内部実装を断定しない。

### 12.8 Create標準の時刻表指示・条件の調査（静的確認済み）

根拠：[Createおよび関連アドオンの時刻表命令・時刻条件調査](../調査関連/駅・信号・時刻表/CREATE_AND_ADDONS_SCHEDULE_INSTRUCTIONS_AND_TIME_CONDITIONS.md)（2026-09-23）。報告書の提案・当時の未決定一覧を、その後に承認された[第7.16・8.16～8.23節](分割記録/節の対応表.md#s-7-16)より優先しない。

- ローカルCreate 6.0.8に標準命令5種・条件9種が登録されている。時刻条件はワールドdayTimeと周期の剰余を用い、目標との差0～40tickで成立する。標準の条件列は順次AND・列間ORで、成立後は進捗が進んで保持される。
- Runtimeの一時停止中は条件を評価しないが、ワールド時刻は進む。目標時刻の通過を自動で記録する実装ではない。これらをCATでも採用する決定は[第8.19節](時刻表と保存ダイヤ.md#s-8-19)。
- 標準の取り出しは開始項目の進捗をアイテムへ記録するが、条件内の経過時間・成立進捗を移さず、再適用はRuntimeを初期化する。CATの編集・予約による時間継承は独自仕様であり、取り出しへ自動拡張しない。
- 標準タイトル変更はRuntimeのcurrentTitleであってTrain.nameではない。標準速度割合はTrain.throttleへ代入する。CAT内での意味・保持は[第8.20節](時刻表と保存ダイヤ.md#s-8-20)を優先する。
- 未登録命令を空の駅移動へ置換、未知条件をnullとして返す読込がある。nullを受ける補助ライブラリ側の挙動まで全確認できていない。CATの最新方針は[第8.21節](時刻表と保存ダイヤ.md#s-8-21)で、報告書の必須rawデータ保持・一律エラー案は承認仕様ではない。
- 両アドオンは提供ソースがなく具体項目・変更点を未調査。列車未読込、時刻ジャンプ、条件境界等のMinecraft内試験も未実施。報告書の静的帰結と実機確認を区別する。

**類似MODとの照合（候補・実機未検証）**

- 資料：[類似MOD調査・精査最終報告書（2026-10-21）](../調査関連/類似MOD調査/類似MOD調査_精査最終報告書_2026-10-21.md)。元報告はCAT要件との比較を実施していないため、今回の照合・提案とは区別する。配布版の存在、作者説明、Create版対応の記載、ソース確認、実際の併用動作は別の証拠とする。
- 比較候補：LCD／掲示板はRailways Navigator、音響はCreate: VVVF-Simulator、視点はCreate: Train Perspective、電力・外観はPantographs & Wires／Electrified Trains。信号・踏切・ドア・時刻表はExtended Signals／Train Parts／Train Doors／Advanced Schedules等。これは導入推奨・必須依存・CAT代替の確定ではない。対象Minecraft・ローダー・Create・MODの版は採用候補を絞って再確認する。
- 現状、似た機能があるという理由だけでCATの既存機能を不要と断定したものはない。汎用描画・音響・装飾の重複実装を減らす余地はあるが、INTEROSの一元管理、役割別操作、正式閉扉、CATの連続制御・時刻表進捗等を代替できるかは別途判断する。
- 本体の目的と分担基準は、その後の会話承認により[第13.16節](共通方針と責任分担.md#s-13-16)で決定した。残る個別分類・再現深度・既存合意の変更・共通情報と外部接続・候補に絞った検証・名称等は順次相談する。CAT Libは判断基準のみ承認済みで作成決定ではない。途中のドア等の議論を消去・完了扱いにしない。
