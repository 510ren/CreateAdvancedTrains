### 4.2 反対側マスコンからの手動引継ぎ（旧操作を保存・要検討）

> **以下は2026-09-25時点の操作履歴。無承認取得・一律N移行は現行動作ではない。** 最新は[第7.20節](ATOとTASC.md#s-7-20)（走行中N～B／停止中保持可能B）と[第11.18節](マスコン操作とHUD.md#s-11-18)（ATO担当への許可要求）。走行中取得の可否・キー・通常移行の基本は維持するが、保存EB＋切や台方向の具体操作は要検討。

- 反対側からの手動操縦開始を拒否するのは、元の側に手動操縦権がある場合。操作開始済みでノッチ操作が可能なら、停止中・Nノッチでも手動操縦中として扱う。キーが残っていることだけでは引継ぎを拒否しない。
- 手動操縦権がなければ、停止中だけでなく走行中でも、反対側の操作開始ボタンで手動操縦を取得できる。キー必須設定が有効なら交代先にもキーが必要。走行中にキーを取り出せない制限は維持する。
- ATOが動作中なら、操作開始によりATOが無効になる旨を表示し、そのボタン操作でATOを解除する。単なるHUD閲覧では解除しない。
- このATOからの引継ぎでは指定ノッチをNとし、現在の加減速度から通常の線形移行でN相当へ戻す。移行時間は既定10tick、プロファイル別設定による。移行後は自然抵抗による減速となり、一定速度維持や即時停止ではない。安全装置・EBの優先制御は維持し、安全設定の復元は[第7.1節](ATOとTASC.md#s-7-1)に従う。
- Nへの移行が完了する前でも、通常の受付条件を満たす新しいノッチ操作を受け付ける。その時点の実際の加減速度を起点として新しい要求へ移行し直す。N移行の完了を待たせず、起点を0や以前の目標値へ飛ばさない。通常ノッチは通常移行時間、EBは既定のEB専用移行則に従う。
- 要復旧EB中の手動移行は上記N変更の例外。指定位置を維持し、実効EB・原因・復旧待ちを引き継ぐ。運転手が指定EBへ合わせ、通常の手動復旧を行う。
- 使用台の切替だけでは列車の移動方向を反転させない。新しい台に対する前後の意味の対応と、実際に保存レバー位置を自動変更することは別。保存EB＋切からのN移行とインターロックをどう接続するか、自動方向合わせを認める範囲は実際の操作との比較調査後に確定する（[第14.2節](残課題と再開地点.md#s-14-2)）。

### 11.1 画面構成（決定）

- 手動の運転操作にはマスコンHUDを開くことを必須とする。マスコンをクリックして表示する。
- 画面の左・右・下をHUDとし、中央から上に前方のゲーム内景色が見える領域を確保する。
- 参照画像の斜線は景色。ホットバー非表示固定の初期案は変更し、表示／非表示をプレイヤー設定で選ぶ方向。既定値は未決定。E等でインベントリを開いたらマスコンHUDは閉じ、[第11.4節](マスコン操作とHUD.md#s-11-4)の処理を行う。
- 参照画像：利用者提示の `C:/Users/mii-r/Downloads/タイトルなし.png`。リポジトリには今回コピーしていない。画像がなくても上記配置方針は本書から読める。
- ノッチ・進路のキー操作に加え、ATO有効ボタンなどのHUDボタンをマウスで操作できる。

### 11.2 視点とカーソル（決定）

- 通常はマウスで視点を動かす。専用キーを押している間だけHUD用カーソルを操作する方式を初期設定とする。
- プレイヤー設定で「押すたびに切替」も選べる。
- HUDマウス操作中は視点を固定する。クリックを背後のブロック操作や攻撃へ伝えない。
- 視点操作へ復帰するとき、カーソル移動量で視点が飛ばないようにする。
- HUDボタン操作中もノッチキーは受け付ける。文字入力中は誤操作防止のため別途規則を決める。
- 実際のキー割当、画面内の詳細配置、表示倍率などは未決定。

### 11.3 ノッチ・レバーサーのキー／マウス操作（決定）

| 設定可能なキー | 操作 |
| --- | --- |
| B側1段 | 長押しでプロファイルの最終常用段（例B8／B16）まで。EBへ入らない |
| N指定 | Nへ直接操作。ただしEBから直接Nは不可、各ロックを迂回しない |
| P側1段 | 長押しでプロファイルの最大Pまで。EBからはまず最終常用段へ戻す |
| EB指定 | EB位置へ直接操作 |
| レバーサー前側／後側 | 1押下ごとに後↔切↔前を1位置移動。長押し連続移動はしない |
| 実効ノッチ引継ぎ | [第7.21節](ATOとTASC.md#s-7-21)のN/B自動選定でATOから手動へ引き継ぐ。対応する画面ボタンの有無・構成はHUD検討、換算方法は性能調査後に決める |

- マウスは位置クリック・ドラッグの離散ノッチ操作を基本とする。EBへの追加操作は[第6.5節](非常制御と故障復旧.md#s-6-5)による。
- キーとマウスは同じINTEROS検証を通し、アニメーションは滑らかにする。入力源が違ってもインターロック・操作権を迂回できない。
- 長押しの初回遅延・反復間隔、ドラッグ確定時点、複数キー・マウス同時操作、文字入力中の扱いは未決定。

### 11.4 HUD正常終了・強制終了（決定）

| 状況 | 終了条件と動作 |
| --- | --- |
| 手動操縦中にEsc・E等で通常終了 | 完全停止・指定EB・レバーサー切を必須とし、不成立なら閉じず理由を表示 |
| ATO中に通常終了 | ホームポジション不要。必要なキー・条件を満たすATOは継続し、人の担当だけ解除 |
| 車掌専任で通常終了 | 車掌権限と設備占有を解放。走行中も可能で、受付済み動作・ドア保護・保持は継続（[11.19](乗務員とドアと停車保持.md#normal-duty-change)） |
| 閲覧のみ・操縦開始前 | ホームポジション不要。制御状態を変更せず終了 |
| 手動担当の死亡・切断・操作距離超過 | 終了を阻止せず、HUD占有・操縦権を解除し、速度に関係なく要復旧EBを要求 |
| ATO担当者・閲覧者の死亡等 | ATO担当者ならATO継続、閲覧者なら閲覧終了。これだけで担当喪失EBを要求しない |
| 正常終了後の切断・死亡等 | 既に担当を手放しているため追加の担当喪失EBを要求しない |

- 旧「手動走行中に閉じてプレイヤー設定B／Nへ移行」は廃止。終了ノッチ設定、終了時の自動指定N、適用ノッチの終了後通知は現行動作として適用しないが、[第11.22節](マスコン操作とHUD.md#s-11-22)の要検討として目的・旧案を残す。キー忘れ音は別に維持する。
- 強制終了の担当喪失はINTEROSで非常原因として保持する。主ハンドル位置を自動変更せず実効EB、非常・要復旧灯を点灯する。
- 必要なキー等を満たす元の人または別の人が操縦開始したら担当喪失原因を解消するが、EBは解除しない。完全停止・指定EB・全原因解消後に復旧ボタンを必要とする。
- 要復旧でもホームポジションを満たせば終了・キー抜去可能。再表示・交代・抜き挿しで要復旧や他原因を消さず、次の人へ表示する。
- 距離は移動中のマスコンとプレイヤーの位置関係で判定し、閾値は後決め。マスコン破壊等の別異常の全規則は未決定。
- ワンマン兼任の車掌だけの解除・再取得はHUD全体終了と別操作（[11.19](乗務員とドアと停車保持.md#normal-duty-change)）。手動運転を続ける場合にホーム位置は要求せず、HUD全体の手動終了条件は維持する。
- ATO／閲覧／車掌専任のHUD終了例外を、運転用キーの走行中取出し許可へ流用しない。

- 連結後に通常操作権を失って終了処理だけとなった旧担当には、[49-A・50-A](#coupling-duty-end)の限定規則を適用する。実際の手動操縦担当喪失の要復旧EBや、通常の手動HUD終了条件を一律に変更しない。

### 11.5 Escの統一（決定）

- 警告・確認・選択画面ではEscを「戻る／キャンセル」に統一する。承認・実行として扱わない。
- 一度のEscは最前面の画面だけを閉じ、背後のマスコンHUDまで連続して閉じない。
- HUD終了警告でEsc：終了をキャンセルし、現在のノッチを維持して運転へ戻る。
- ATO解除後の安全装置選択でEsc：選択画面を閉じ、安全装置ONのまま手動を続ける。
- EB解除不可等のエラーでEsc：表示だけ閉じ、EBや解除条件は変えない。
- その他の確認画面でEsc：未確定操作をキャンセルして直前の画面へ戻る。

### 11.6 複数の駅情報と主表示（決定）

- HUDは駅情報を1駅に限定せず、次の次の駅、最短経路上の駅、分岐先の候補駅等の複数情報を表示する。
- 行先指定あり：次の停車予定駅を主表示とし、その駅までの距離・駅情報を案内する。例として「現在地→A→B」でB停車予定なら、Aの方が近くても主表示をBにする。途中駅・その先の駅の併記は妨げない。
- 手動の明示指定がなければ時刻表上の次の停車駅を主表示とする。時刻表による対象もなければ、進行方向に線路沿いで到達できる最短の駅を主表示にし、その先や別候補も表示する。直線距離や単に近い背後の駅を採用しない。
- 選択済み進路があればその経路に沿って判定する。未選択の分岐があれば候補経路中の最短駅を暫定表示し、「進路未確定」と分かる表示にする。
- 分岐先の駅にはどの経路上かを示す。行先指定は表示対象を1駅に限定したり、通れる進路を限定したりする機能ではない。
- 指定駅の経路を確認できなくなっても別の駅へ黙って主表示を変更せず、「経路不明」等を示す。
- 時刻表は手動運転時にも、次の停車駅・距離・その先の予定・停車と発車に関する情報の表示に使う。時刻表由来の駅表示を変更して手動の行先指定とする一つの操作に統一し、別々の行先入力欄へ分けない。これは時刻表自体の編集ではない。
- 手動で指定した行先が主表示を優先するが、時刻表の予定は別情報として確認可能。表示の変更だけで進路を限定・自動選択したり、TASC対象を自動変更したりしない。明示的なTASC対象指定と表示だけの更新は区別する。
- 手動手順案内と駅情報の進行も独立する。A3を表示したままでも、Aに停車して発車したらBへの距離・停車情報を示す（[第8.25節](時刻表と保存ダイヤ.md#s-8-25)）。
- 手動運転の情報表示用進捗とATOの実行進捗を分離する。対象駅への停車完了で表示は次の停車予定へ進むが、ATOの実行項目・待機条件は進めない。ATO開始時はマスコン・ATOSとも必ず開始項目を選択する。
- LCDの駅順・路線図上の現在位置は手順案内と共有し、停車駅・ドア状態等は実情報を使う（2026-11-04、[13.17](LCDと旅客案内.md#s-13-17)）。本節の駅・距離表示を手順位置と統合する変更ではない。
- 停車予定駅を通過しただけでは次へ進めず、「停車予定駅を通過」と表示する。後退して停車し直すか、運転手が次の対象へ変更する。オーバーラン修正で対象が勝手に消えないようにする。
- 時刻表A→B→C→Dで手動対象をBからCへ変え、Cの項目と対応付けられる場合は、C停車完了後に表示をDへ進める。時刻表にない駅なら停車完了を表示して次の対象を手動指定し、時刻表へ自動復帰しない。同じ駅が複数回登場する場合はどの停車項目かを選択できるようにする。
- 表示件数、並び順、展開方法、探索上限、具体的な駅・時刻表項目の識別・更新検知、動的な小包目的地を表示用に決める方法は未決定。

### 11.7 次の信号現示と距離（決定）

- 現在の進行方向で次の区間へ入る際に従う信号の現示と、その信号までの線路沿いの距離を、マスコンHUDに常時表示する。
- 地上信号が描画距離外でも確認できるようにする。描画された色を読み取るのではなく、サーバー側で管理する信号情報をINTEROS経由で表示する。
- 信号通過後は、その次の信号へ対象を切り替える。接近中も現示変更があり得るため、表示によって急制動を完全に防げるという保証ではない。
- 情報を取得できないときは「不明」とし、古い進行現示を最新情報のように表示し続けない。
- 分岐がある場合、候補経路ごとに最初に出会う信号の現示・距離を表示する。未選択なら各候補を区別し、選択済みなら選択中の経路に対応する表示を明示する。
- HUD案内用の取得・表示は各候補経路の次の1基まで。その信号より先の「次の次」まで追わない。これはHUD案内の範囲であり、駅情報の複数表示とは別の要件である。
- 例：「直進側：進行／○○m」「左分岐側：停止／○○m」。2つは連続する信号ではなく、別経路の次の信号である。他経路の進行現示を自分の許可と取り違えない表示にする。
- 利用者の線路図は、下から上へ進み、分岐前の共通線に1基、その先の直進側と左分岐側に各1基の信号がある配置。分岐前の信号がまだ前方なら、それだけが次の信号になる。通過後は直進側・左分岐側の各1基が次の信号候補になる。
- 参照画像：`C:/Users/mii-r/AppData/Local/Temp/codex-clipboard-46c7f789-4ed6-41f1-bb2e-225c430bdd81.png`。横棒が信号位置を示す。画像はリポジトリへコピーしておらず、一時ファイルが消えても前項の文章で配置を再現できる。
- 信号が見つからない場合は、終端まで確認して信号がなかった状態、探索上限に達して先を確認していない状態、情報欠損・更新中等で確認できない状態を区別する。表示案はそれぞれ「次信号なし／線路終端あり」「次信号未確認／探索範囲外」「次信号不明／情報取得不可」。
- 信号が見つからないことを進行現示や進入許可の代わりにしない。循環検出と探索量の上限を設けるが、同じ出口へ至る別経路を循環と誤認して消さない。
- 更新頻度、情報の有効期限、方向別信号の対応付け、探索上限の具体値・方式、未読込時の取得処理・鮮度判定は未決定。地上の実現示・HUD・地上情報由来の制御の一致は[第9.1節](信号と安全装置と進路.md#s-9-1)、情報不足時の基本制御は[第9.3節](信号と安全装置と進路.md#s-9-3)による。制動計算等の内部探索範囲までこのHUD要件だけで決定しない。

### 11.8 運転情報表示・実効ノッチ（決定）

- 表示ノッチ（現在入っている指定レバー位置・内部指定値）と実効ノッチ（実際に効いている制御の相当表示）を別々に表示する。ただしPを加速度から推定・逆算しない。
- 通常の手動力行で指定Pをそのまま使用している場合、実効欄も同じPを表示する。ATOによる自動力行は「ATO」、TASCが計算・補正した自動力行は「TASC」とする。機能がONかではなく、実際に力行を担当する機能を表示する。TASCが待機中などで指定Pをそのまま採用している場合は同じPを表示する。
- 惰行はN、制動は実際の制動に相当する整数B、EBはEBと表示する。指定Pでも安全装置が制動していればB／EBを優先し、同じPの表示にしない。「ATO」「TASC」は自動力行のP相当値を推定しないための表示であり、惰行N・整数B・EBまで機能名で置き換えるものではない。
- B相当は現在の走行条件で最も近いノッチ性能へ換算し、境界で頻繁に往復しない表示上の余裕を設ける。2.5等の小数ノッチ表示は不採用。内部連続制御の離散化や、指定レバーを実効表示へ常に追従させる意味ではない。力行中の強さ・移行は実加速度欄で確認する。
- 実効ノッチの表示更新は既定20tickに1回、プレイヤー別設定で変更可能。制御周期・指定ノッチ・速度・加速度の表示周期まで20tickに制限しない。
- EB中は実効ノッチ欄をEBとし、状態受信時に通常間隔を待たず切り替える。移行途中の減速度は加速度欄で確認する。EB解除時の表示更新時点は未確定。
- 現在速度（km/h）と現在加速度（m/s²、加速＋／減速－）を表示する。加速度は目標指令ではなく、自然減速を含む実際の速度変化を示す。
- Nによる自然減速だけでB作動と誤表示しない。P中に抵抗等で実加速度が負となった場合も、それだけでBと判定しない。Bの具体的換算式・勾配・丸め・表示平滑化は未決定。P同値時の逆算規則は採用しない。
- 目標加速度は基本的に内部値に留める。デバッグHUDは将来の構想として別途検討する。
- 運転情報ブロック（仮）を用意し、キー不要の読み取り専用情報表示に使う。マスコン使用中でも他者が閲覧でき、操作権は得ない。情報はINTEROSから取得。表示項目・接続方法・配置・閲覧人数等の詳細は未決定。

**TASC状態の表示：**

- 無効は消灯・灰色系、有効で待機中は控えめな点灯、制御中は明確な点灯と「TASC補助中／TASC自動停止中」等で区別する。制動時など実効欄がB・EBでも作動表示を併用し、どの機能が制御しているか分かるようにする。
- 有効だが情報不足の場合は「利用不可」と理由を示し、待機やOFFと区別する。注意色（黄色・橙色等）は候補で、最終色・配置はHUD設計時に決める。
- 有効状態・選択モード・今回の作動状態を区別し、色だけでなく文字でも示す。出力の細かな変化ごとに点滅させない。
- 状態変化は受信時に反映し、実効ノッチの既定20tick周期を待たせない。情報不足を表示するために機能自体をOFFにしない。

### 11.9 共通キー・HUD占有・操縦担当（決定）

**共通キー：**

- 列車登録不要の共通キー（アイテムのマスコンキー）を残す。所有者・管理者・列車識別には使わず、電車らしい操作のためのアイテムとする。操作権や通知先をキーの所持者から推測しない。
- 運転用はServer Configでキー必須ON／OFFを選択し、既定ON。OFFなら手動・ATOとも不要。ONなら使用するマスコンのキー枠に必要。車掌専任（車掌設備・統合マスコン）はキー不要で、詳細は[11.19](乗務員とドアと停車保持.md#normal-duty-change)。運転・兼任の既存キー条件は維持する。
- 運転用HUDにアイテム枠を設け、キー必須ONではキーを入れると運転操作部のグレーアウトを解除できる。車掌専任の操作をキーなしだけで無効化しない。専用の挿鍵動作は不要。インベントリ所持だけで判定する案は不採用。
- キーは消費せずマスコン側へ保持し、HUDを閉じても残る。主にキーがあっても、副を使用するなら副に必要。無人ATO継続にも使用台への挿入が必要で、両台へ残せば予定された切替・折返しが可能。
- キー取出しは完全停止・対象台の指定EB・レバーサー切のホームポジションを必要とする。キー必須ON／OFFでも走行中は抜けない。独立した抜取位置、指定Bでの抜去は採用しない。ATOのHUD終了例外を抜去へ流用しない。
- 必須ONで使用台のキーを抜いたら閲覧専用へ移り操縦権を手放す。指定EB・切と停車保持を維持し、入れ直しただけでは再開しない。通常ATO中は手動で切へ動かせないため、先にATO解除・ホームポジション操作を行う。
- 入れ直しただけでは制動解除・ATO再開をしない。手動は操作開始で操縦権を取得してから改めてノッチ操作、ATOは従来のATOボタンで開始項目を選択・確定して再開する。別の承認ボタンを追加しない。
- 上記の使用台のキー抜去による終了と、ATO有効のまま未使用の移行先のキー不足で待つ場合を区別する。CAT連結・分離後の移行先キー補充による継続、準備・実切替・条件待ちのキー取出し制限は[第2.4節](列車構成とプロファイル.md#s-2-4)に従う。
- 使用していない台のキー取り出しだけで現在のATOを停止させない。ただし停止条件と操縦権による取出し制限は守る。キー必須OFFなら、キーを抜いただけで運転操作やATOを無効にする条件にはしない。
- キーを残してHUDを閉じた本人へ、取り外し忘れ音を一度鳴らす。プレイヤー別ON／OFF、既定ON。キー必須のServer Configとは独立。自動取出し・終了拒否・鳴り続ける警報ではなく、ATO継続を妨げない。

**役割と操縦権（最新）：**

- 設備の機能、プレイヤーの権限、操作受付条件を区別する。[第11.19節](乗務員とドアと停車保持.md#s-11-19)の運転手／車掌／閲覧へ分割する。操作利用は一台につき一人、閲覧は非占有で複数人可能。統合マスコンを別々の運転手・車掌が同時操作する記述は記載ミスとして訂正する。
- 同じ役割の操作権は列車単位で一人。先にHUDを開いた人ではなく、条件を満たして取得が確定した人を優先する。主副に優先差はなく、閲覧は非占有。
- キー挿入だけで取得・発車せず、使用台のキー条件は維持する。両側への準備挿入は可能。片側に残るキーだけで他側を禁止しない。
- 手動操縦者がいる間は他側の手動取得、キー／時刻表取出し、安全設定変更等を拒否する。閲覧・本人の表示変更・準備挿入は可能。停止・Nでも手動担当中なら同じ。
- ATO操作担当の取得・解放は[第11.18節](マスコン操作とHUD.md#s-11-18)。反対側からの手動取得は走行中も可能だが、担当がいれば許可要求を必要とし、解除は[第7.20節](ATOとTASC.md#s-7-20)の新手順による。単なる閲覧では解除しない。
- キー抜去・担当解放で他閲覧者へ自動移譲しない。交代先に挿入済みのキーを挿し直す必要はなく、明示取得を行う。
- 手動操縦担当がいる間のATOSによるATO開始は拒否し、予約しない。担当不在なら既定の開始項目選択・キー・進路・安全条件に従う。速度制限等の別の遠隔要求は別扱い。
- 使用台切替だけで列車の移動方向を反転しない。連結時は[第2.4節](列車構成とプロファイル.md#s-2-4)の継続側担当を基準とする。非継続側の終了と通常操作権／終了専用状態の区分は[43-A～50-A](#coupling-duty-end)による。保存位置・向きの比較調査と通常操作以外のキー喪失の扱いは未決定。
- **旧案／要検討**：閲覧まで含む同じHUD一人限定、反対側からの無承認ATO解除・一律N移行、レバー位置と取得時の自動変更。操作利用の一台一人は現行。二重操作防止と滑らかな交代のため、役割別権限・承認・N～B／停止B手順との接続を再整理する。

### 11.10 EB位置基準のインターロック・自動表示（決定）

- レバーサーは前・切（従来の中立）・後の3位置。通常は指定EBでのみ操作可能。B・N・Pでは停止しても切替不可。実効EBだけでは指定EB条件を代用しない。
- 切位置では主ハンドルをEBからB・N・Pへ動かせない。前／後で通常ノッチ操作が可能。旧「Nで方向切替／切でN固定」、途中案「停止中Bで切替／切でN・B操作」は置き換える。
- CATでは走行中でも指定EBなら手動レバーサー操作可能とする。ただし切への変更は11.12の操作後保持確認も必要とし、当該台のノッチが切でも効くという意味ではない。他の有効なEB・保持要求は継続し、速度・実際の進行方向は瞬時に反転しない。実車での同じ動作を確認したという意味ではない。
- ATO中はレバーサー手動操作を全方向ロックする。TASCの停車後引継ぎ待ちではノッチ専用ロックだけ先に解除し、レバーサー専用ロックは引継ぎ完了後に解除する（[第7.10節](ATOとTASC.md#s-7-10)）。EB復旧・再開待ちは方向と通常ノッチ操作のため専用ロックを解除し、自動停止再開時に再適用する（[第7.19節](ATOとTASC.md#s-7-19)）。通常の指定EB条件は残る。
- 要復旧・非常原因を方向変更だけで消さない。主ハンドルの位置操作と、実際の制御適用を分ける。
- 自動レバー変更をHUD上の滑らかな動きとして表現でき、内部指定値も対応させる。ただし全自動出力へ一律追従させない。自動EBは位置不変、折返しは指定EB、TASC開始・再開は位置維持。ATO解除は[第7.20節](ATOとTASC.md#s-7-20)の走行N～B／停止保持可能Bで、一律自動Nの旧表示は[第11.22節](マスコン操作とHUD.md#s-11-22)の要検討へ移す。
- 逆方向を選んだだけでは故障しない。実際の進行方向と逆の力行が適用されたら[第11.11節](非常制御と故障復旧.md#s-11-11)の異常蓄積を行う。
- アニメーション時間・補間・同期・ドラッグ競合は未決定。物理移行10tick・実効表示20tickと同一にせず、描画完了を待って安全制御を遅らせない。

### 11.12 ホームポジション・台別保存・交代（決定）

- 手動使用終了／キー抜去のホームポジションは完全停止・指定EB・レバーサー切。独立した抜取位置は採用しない。切への変更は、その操作後も十分な保持が継続すると確認できる場合に限り、不成立なら理由付きで拒否する。切になる台の保存指定EBだけを保持元に数えない（2026-11-04合意）。
- 通常の停車待機でBを使うことと、使用終了のEB保持を区別する。B6等をホームポジション必須値にする途中案は採用しない。保持の最終適用はINTEROSへ集約するが、ATO自身の保持、TASCの引継ぎ待ち、ドア連動保持は[第3.4節](乗務員とドアと停車保持.md#s-3-4)の別責任として扱う。TASC完了時のドア保持OR十分な運転手B／EBと、ノッチ・レバーサーの段階的引継ぎは[第7.10節](ATOとTASC.md#s-7-10)で決定済み。具体値・実現方法等の未決事項と区別する。
- ノッチとレバーサー位置は各台に保存し、運転手やHUDの開閉だけで初期化しない。有効保存状態のない新規台はEB＋切、初期位置だけで要復旧にしない。
- 手動指令として有効なのは現在の使用台だけ。交代成立後、未使用台の保存EBを独立した列車制動要求にしないが、その台の位置自体は変更しない。
- ホーム位置へ変更後、運転画面を閉じて正常に運転終了した場合は、その運転台グループの選択値を自動で中へ変更する（[11.32](#s-11-32)）。一般の権限離脱後維持に対する特例であり、閲覧画面の終了やATOを継続する操作担当のHUD終了には適用しない。中への変更によるEBの実適用・十分な保持を確認して、終了前の保持から途切れず引き継ぐ。
- 正常終了後も有効なEB・保持理由を継続し、次の台の操縦開始だけで解除しない。画面終了時の自動中を、それより前の切への変更時点の保持として先取りしない。別の保持元がなければ、停止中に手動で中としてEBの適用・保持を確認してからホーム位置へ移る経路を使う。新台への取得・選択成立で当該EB理由が終わる際も、他の保持と残存Pの制限は維持する。
- 安全装置のEB要求・要復旧は台別保存とは別の列車状態として維持する。
- 新しい台に有効だがホーム外の保存位置が残る場合（異常終了等）の交代開始処理、主副切替時の表示方向の更新と保存値の関係は、[第14章](分割記録/節の対応表.md#s-14)の接続課題。保存値を無条件に即適用する許可ではない。

- 連結後の終了専用画面については[43-A～50-A](#coupling-duty-end)を適用する。48-Aの「必要な制御処理後は画面終了だけを待たない」を、通常の手動運転終了・キー抜去のホーム位置条件へ一般化しない。

### 11.13 不正なレバー状態と初期化（決定）

- 禁止された指定位置の組合せ、プロファイル外のノッチ等はINTEROSが制御へ適用せず、異常・要復旧とする。指定P／実効EB等の正常な介入を異常扱いしない。
- 使用中の台なら手動・ATOとも制御継続を中断し、速度によらず要復旧EBで停止・保持する。未使用台ならその台を使用不可・要復旧にし、正常な台の運転をその理由だけでは止めない。
- 新規台の初期設定と破損データを混同せず、再読込・HUD表示・キー抜き挿しで黙って修正しない。
- 完全停止・ATO OFFで、異常台自身のHUDから明示的な「レバー状態の初期化」でその台だけEB＋切へ戻す。通常操縦開始できなくても復旧用操作は利用可能にする。キー必須ONなら対象台にキーが必要。
- 別の台に手動担当がいる間は初期化・復旧を拒否し、先にその担当の正常終了を必要とする。
- 初期化だけでは要復旧や他のEB要求を消さない。INTEROSが原因解消を確認し、既定の復旧ボタンで復旧する。復旧後は閲覧状態で、自動的に操作権を得ず改めて操縦開始する。
- これはレバー状態不正の対処であり、駆動系故障バーの復旧条件・UIを確定するものではない。未使用台もATO OFF・他の手動担当の正常終了を必要とする。列車単位／台単位の復旧ボタンの対象表示等は残課題。プロファイル変更時の組立拒否と解体中初期化は[第5.3節](列車構成とプロファイル.md#s-5-3)による。

### 11.14 非常灯・要復旧灯・自動運転・安全介入灯（決定）

| 状態 | 非常灯 | 要復旧灯 | ATO灯（仮） |
| --- | --- | --- | --- |
| 通常手動の指定EB・通常EB保持 | 通常点灯 | 消灯（他の要復旧なしの場合） | 消灯 |
| 緊急停止・未復旧 | 通常点灯 | 点灯 | ATO側の担当を維持する場合は点灯 |
| ATO作動中・保存指定EBを無視、実際のEBなし | 弱点灯 | 消灯 | 点灯 |
| ATO作動中・指定EB以外、実際のEBなし | 消灯 | 消灯 | 点灯 |
| ATO側の通常EB停止待機 | 通常点灯 | 消灯 | 点灯 |
| 復旧後に指定EBの通常保持だけが残る | 通常点灯 | 消灯 | 手動へ戻った場合は消灯 |

- 自動EBで指定位置がP等でも実効EBにより非常灯を点灯する。要復旧灯は停止・原因解消・位置合わせだけでは消えず、復旧成立時に消える。
- 色だけで通常／要復旧を区別する案は不採用。文字と独立表示を使う。弱点灯も明るさだけに依存せず「指定EB・ATO制御中」等の説明を併用する。
- ATO灯は発車許可ではなくATO側が担当・復旧経路を保持することを示す。「ATO・非常停止中」等の状態文字を併用する。
- TASCは指定EBのまま再開しないため、ATOの保存EB無視・弱点灯をTASCへ適用しない。通常の非常表示・要復旧表示の基本は共通とする。
- 安全装置ごとの介入灯と理由表示を追加し、有効状態・共通非常灯・要復旧灯とは別にする。「ATS-P 非常制動」「ATACS 常用制動」「力行抑止」等の文字を併用する構想で、最終名称は未決定。
- INTEROSの有効な制御要求と理由を基に表示し、実効EBだけから全原因を推定しない。複数装置の介入は複数表示できる。色だけで区別せず、ATO／TASCの作動表示も併用する。
- 元の介入が解消して復旧待ちだけが残る場合の灯、複数の制御担当・理由のまとめ方、配置・音・追加HUD案は後で決める。

### 11.15 保存・再読込・ATO再開（決定）

- 各台の指定ノッチ・レバーサー・異常状態、列車の要復旧と理由を保存する。再読込・再起動だけで解除しない。
- 読込後は原因を再確認し、情報未取得を解消済みとしない。原因が消えていても復旧待ちは残す。不正データは[第11.13節](マスコン操作とHUD.md#s-11-13)へ移る。
- 保存前に有効だったATOは、必要な列車・線路・信号情報、使用台・キー・経路・安全条件を再確認できれば、保存進捗から自動再開できる。読込だけで開始項目を選び直させない。
- 未確認情報を無条件に使った力行・発車は禁止。[第9.3節](信号と安全装置と進路.md#s-9-3)のATACS代替運転は必要な地上情報等の確認後に適用できる。要復旧、目標喪失承認待ち、折返し異常、駆動系故障待機・明示再開待ち等があればその手順を優先する。保存前OFFのATOを勝手にONにしない。
- 折返し中は変更前と変更先の使用台・方向・処理進捗を保存する。読込後はEB保持して再確認し、整合していれば未完了部分だけ継続する。完了済み方向変更を再実行して逆転させない。
- 切替先が利用不能・非常・脱線等なら、変更済み状態を自動巻戻しせず未実行部分を中断して[第6.6節](非常制御と故障復旧.md#s-6-6)で再確認する。不正・不明状態を推測で制御へ適用しない。
- 手動操縦担当は再読込で自動復元しない。保存時に手動操縦中だったのに有効な担当がいない場合は操縦者喪失として要復旧EBとし、無人のまま保存P等を実行しない。正常終了済み列車を再読込しただけでは要復旧にしない。
- 組立済みプロファイルの性能・版、列車の安全方式とON／OFF、系統別耐久残量・故障を維持する。安全設定の再組立初期化は通常の再読込と区別する。
- CAT連結・分離成立後のATO使用台移行は[第2.4節](列車構成とプロファイル.md#s-2-4)の途中状態・残り選択時間の保存規則に従う。折返しの保存規則だけから物理的な編成変更の保存方法まで推定しない。
- 具体的な保存形式・原子的保存・版管理・編成変化による継承、TASC作動状態の保存範囲は後で設計・確認する。

### 11.16 停車・カーブの動きと視点設定（決定／実現方法は調査待ち）

- 停車直前の実制御調整と、停車・カーブ時の車体表現の両方を追加する。
- 停止位置と必要な保持力を確保しながら、可能な範囲で停車直前のブレーキを調整し、急な加速度変化を抑える。安全制御・EB・保持を乗り心地のために弱めない。
- 車体表現は減速に伴う前後の傾き、停止後に小さく揺れて収まる動き、速度・曲がり具合に応じたカーブ時の傾き・揺れを含む。カーブへの進入・退出も滑らかにする。
- 実際の速度・停止位置と見た目の揺れは分離する。表現のために停止位置をずらしたり、実速度を振動させたりしない。
- 周囲からも車体の動きが見え、車内視点にも反映できる。視点の揺れはClient SettingsでON／OFFを設定し、**既定ON**。OFFでも外からの車体表現・走行性能は変えない。
- 揺れ・傾きは操縦への影響を小さくするため控えめな強さとする。マスコンHUD・カーソル・操作ボタンは揺らさず固定し、視点演出を移動入力やマウス操作として扱わない。
- 具体的な幅・周期・収まり方は操作感を確認して調整する。強さのプレイヤー設定は未決定。Createでの車体／視点表現、傾きの二重適用防止・同期等は要調査。

### 11.18 ATO操作担当・反対側への許可（決定）

- HUDを開くだけでは閲覧。ATO作動中は「ATO操作を開始」で列車単位の一人の担当を取得し、取得だけではATOを解除しない。手動担当がATOを開始した場合はその人が引き継ぐ。ATOS開始の無人ATOは現地担当不要。
- 担当のHUD終了・死亡・切断・距離超過で担当を解放するが、ATOは継続し、それだけでEBにはしない。手動へ切替成立後の担当喪失は要復旧EB。キー・他異常条件は独立。
- 反対側からの手動取得要求は、ATO担当のHUD内通知領域へ「反対側のマスコンで手動操縦権取得の要請がありました。これを許可すると、ATOが解除されます。許可しますか？」と許可／拒否を表示する。オーバーレイで非常操作を妨げない。
- 許可までATOと権限を維持する。放置・時間経過で自動許可しない。拒否は要求を終了して要求者へ通知する。
- 許可時に要求者・台・キー・ロック・最新状態を再検証し、成立時だけ[第7.20節](ATOとTASC.md#s-7-20)の解除と手動取得を行う。旧担当は閲覧へ戻り、未適用の旧担当要求は権限再検証で拒否する。
- 条件不成立なら要求を終了し両者に理由を通知する。許可を保存して後で勝手に移行しない。
- 要求者に許可待ちと取消ボタンを表示する。取消・HUD終了・死亡・切断・距離超過で取消し、相手側の許可ボタンも無効化する。連打で重複要求を積まない。
- ATO担当が離脱した場合も取消し、自動許可しない。要求者は担当不在時の手順で再操作する。
- 別理由でATOが解除されたら要求を取消す。元担当が手動へ移ればその担当を優先する。手動担当が不在でも自動移譲しない。
- ATOを維持した信号待ち・要復旧EB等の中断だけなら要求は保持する。引継ぎでEB・復旧義務を消さない。確定済み手動移行後の離脱は通常の担当喪失として扱う。
- 指示完了・スキップ権限と安全機能設定は別。ATO中は必要な安全・操縦機能の個別OFF不可。手動へ戻した後は現在の操縦者が許可範囲で変更する。閲覧者は変更不可。実設定は列車単位、表示設定は既定の個人単位。

### 11.22 操作・HUDの見直し対象を保持する（利用者指定）

- 操作・HUD関連で見直す機能は削除せず、目的・旧動作・見直し理由・再検討範囲を残す。旧案を現行動作へ適用する意味ではない。
- 実効ノッチ引継ぎキー：滑らかな手動移行を目的に、N/B限定の自動選定機能として採用した（2026-11-04）。現行動作と旧P対応案の区別は[第7.21節](ATOとTASC.md#s-7-21)。換算方法、対応する画面ボタンの有無・構成、詳細配置は後決め。
- 一律NのATO解除／他台取得：保存P等の急適用回避が目的。現在は走行N～B・停止保持可能B、ATO担当許可。自動選定と通常N/B指定の二経路を[7.20](ATOとTASC.md#s-7-20)に決定。ホーム位置での運転終了は[11.12](#s-11-12)・[8.24](時刻表と保存ダイヤ.md#s-8-24)の保持確認・自動中の経路。全受付表・同時操作・詳細UIは継続検討。
- **切位置の扱いと保持（2026-11-04接続方針合意）**：レバーサー切の台のノッチは列車へ作用せず、切位置の保存EBだけでは保持を保証しない。切への変更・ホーム位置からのATO終了は、操作後も十分な保持が続くことを確認できなければ拒否する。通常のATO手動引継ぎのB条件とは分け、正常終了時の自動中と保持受渡しは11.12・11.32、ATO側は7.20へ集約する。単なる手動停車への自動保持追加や複数台の同時手動制御の承認ではない。
- **留置ブレーキ案（2026-11-02・用途等は検討中）**：利用者から、通常の駅停車は基本的に通常ブレーキを用い、用途を限定した留置ブレーキ（駐車ブレーキ）を設ける案を受領した。案の前提は有限の保持能力で、能力を超える勾配等では転動すること。通常ブレーキと同一性能・無限保持・位置固定は意味しない。**適用・解除には明示操作が必要で、切への変更・操縦開始だけでは自動適用・解除しない条件は合意済み。** 初期採用範囲、運転終了・留置と運転台交代それぞれへの適用、操作主体・権限・機器・ATO／時刻表からの操作可否、能力・同時制動・適用中の力行・転動時処理は未決。AIの「交代中も初期対象にする」提案への承認とは扱わない。
- 留置ブレーキの用途判断に関連して利用者提供の増解結調査を受領し、3件の特許本文を限定照合した。[調査4Bの追加照合](../調査関連/運転・車両特性/CAT連結分離_調査依頼と確認状況.md#cab-control-patents-2026-11-02)を参照する。異なる方式の特許記載から、切位置で制動が消える一般則、交代中の留置ブレーキ必須、E231系・E233系の具体動作を確定しない。既存の保持規則との接続は引き続き確認中。
- **2026-11-04の調査待ち整理**：利用者から、通常の勾配の連結中は通常ブレーキと運転台選択不整合EBで保持でき、駐車ブレーキの発動条件を選択不整合と記す資料もあるとの補足を受領した。資料の名称・該当記述と機能の対応は未確認。独立した留置ブレーキの採否・用途は調査待ちとし、提案した用途A/Bを採用済みにしない。通常制動とEBの要求が併存することを制動力の単純加算や全勾配での保持保証にしない。連結の具体操作は今後の調査で追加・見直し得る。
- 旧HUD終了後の任意B設定・指定N・終了後通知：誤操作防止が目的。現行正常手動終了はホームポジション必須、担当喪失は要復旧EB。旧自由終了を復活させずUI案として再検討対象に残す。
- 同一台の利用人数：操作利用は一人、閲覧は複数人可能と2026-11-03に明確化。列車単位の役割別権限と台単位の操作占有を別に管理する。複合設備の表示切替・権限移行・競合表示は要検討。
- TASC完了の一律B合わせ不要／一律B必須案：保持責任の変更経緯として残す。現在はドア保持OR十分な運転手B/EB、ノッチ先解除・レバーサー後解除。ATO停止解除のB必須とは区別する。
- HUD参考は[HUD参考フォルダ](../調査関連/HUD参考)。利用者は基本思想の参考として指定し、完全再現は要求していない。確認済み範囲は5車種の全体とE235左右拡大。計器／運行情報の分離・状態灯・操作時も走行情報を見失わない配置は検討材料。全計器・電圧／圧力系の実装承認ではない。
- 利用者のJRE TrainSimulatorでの開扉後保持の観察は利用者報告であり、全実車・全車種の仕様として確認したものではない。CATは開動作直前の保持成立確認を採用した。

### 11.32 運転台選択スイッチ（2026-11-04合意保存／調査・詳細設計は残る）

**設定単位・取得・手動操作**

- 前・後・中の選択値を、運転台単位で持つ。列車の前後方向に対して横並びのマスコンは一つの値を共用する。前後方向がX軸ならZ軸方向の横並びが同じ運転台であり、X軸方向に前後するものは外側・内側の別台とする。曲線上、縦方向・位置許容差などの具体判定方法は設計・調査事項。レバーサー・主副割当・使用台・権限とは別の設定であり、実車回路の完全再現ではない。
- 車掌設備は対応する運転台の補助設備として同じ選択値を使う。運転マスコンがない場合も車掌マスコンだけの運転台を認識し、それ自身を設定先とする。値の共用によって、一台のマスコンの操作一人占有を統合・解除しない。
- 新規組立時は全運転台を中とする。値は保存し、通常の再読込後も維持するが、読込後の実編成に対して成立条件を再評価する。過去の成立判定だけでEBを解除しない。分離後の設定を新規組立初期値へ一律に戻す決定ではない。
- 手動変更は、そのマスコンを操作中の本人が運転・車掌のどちらの権限でも行え、閲覧者は変更不可。停止中のみ受け付け、停止閾値・詳細UI・誤操作対策は後決め。自動設定の実行条件と、手動変更の停止中条件を混同しない。
- 中間台からの新規の通常運転権限・車掌権限取得は理由付きで拒否し、拒否によって設定値を変えない。閲覧は可能。連結で既得担当の台が中間台になる場合は[終了・移行手順](#coupling-duty-end)を使う。50-Aの終了処理専用の入口は通常権限の取得ではない。
- ツーマンで別々の人が運転・車掌を担当するときは、互いに反対端の運転台を使う。同一運転台の別マスコンから他方の役割を取得することは、取得順によらず拒否する。列車単位の同一役割排他も維持する。ワンマンの同一人物による兼任は例外。反対端を使う制約は、実使用やGitHub等での公開後レビューにより改善を検討する対象とする。

**自動設定と値の維持・終了時の特例**

- 運転権限取得時は使用台を前、車掌権限取得時は使用台を後へ設定する。ワンマンは使用する端を前、反対端を後とし、車掌だけの再取得時も兼任台を後へ上書きしない。車掌機能不要の標準のみワンマンは運転権限だけを取得し、ツーマンの同一人物兼任は認めない（[11.19](乗務員とドアと停車保持.md#normal-duty-change)）。これは操作を簡略化するCATの決定。
- 無人ATO・遠隔開始の準備では、使用する端を前、反対端を後へ自動設定する。中間台は中であることを確認し、不成立なら理由付きで開始を拒否する。設定変更とATO開始は別で、他のEB・要復旧・キー・保持などの条件を省略しない。
- 通常のATO折返しでは、既存の停止・折返し用EB保持の手順内で、新使用台を前、旧使用台を後へ更新し、中間台が中であることを確認する。設定成立だけで切替保持を解除しない。連結・分離に伴う使用台移行へ無条件に拡張しない。
- 権限離脱後も値を維持するのを一般則とする。ただし、ホーム位置へ変更後に運転画面を閉じて正常終了した場合、およびホーム位置でATOを終了した場合は、その運転台グループを自動で中とする。[11.12](#s-11-12)・[ATO7.20](ATOとTASC.md#s-7-20)の保持確認・受渡しを必要とし、ATOを継続する担当のHUD終了や閲覧終了には適用しない。
- **連結後の終了・中間台移行**：43-A～50-Aにより下記の終了手順を採用する。2026-11-04の条件付き方針から、手動の終了手順を設ける分岐を選んだ。連結直後に各選択値を一律自動で中にはせず、必要な終了条件を確認する。実車の正式操作と技術的成立性は未確認。

<a id="coupling-duty-end"></a>

**連結後の担当終了・中間台移行（43-A～50-A、2026-11-18保存）**

以下はCATとして採用した基本判断。具体的なスイッチ操作・全操作順・保持受渡し・途中失敗／保存境界は後続で照合し、実車の正式手順や実現性を確認済みとはしない。

| 対象・状態 | 基本動作 |
| --- | --- |
| 非継続側の手動運転担当（43-A） | 連結成功だけで利用を自動終了させず、旧設備の終了手順を案内する。通常の操縦は行わせず、必要な終了操作後の画面終了で終了用の利用・占有を解放し、新中間台を中とする |
| 継続側の手動使用台が中間台になる（44-A） | 旧台で保持・ホーム位置等を満たして正常終了し、外端の適格な台へ移動して明示取得する。移動中は運転担当不在とし本人のための取得予約を設けない |
| 継続側の車掌設備が中間台になる（45-A） | 中間台での新たな車掌操作を終了し、利用終了・解放後に適格な外端設備で明示取得する。ツーマンの反対端条件を維持し、兼任者の台移動は44-Aと接続する |
| 非継続側の車掌（46-A） | 通常の車掌操作を終了し、旧設備では終了に必要な操作だけを可能にする。本人の利用終了で設備占有を解放し閲覧へ移る |
| 非継続側ATO（47-A） | システムが終了手順を自動実行する。必要な保持受渡し・旧台の終了条件を確認してATOを終了し、新中間台を中とする。現地担当者の終了操作は必須にしない |
| 制御上の終了条件が成立し、旧画面だけ残る（48-A） | 画面を閉じる操作だけを発車条件にしない。残る画面は閲覧・利用終了のみで、通常操作を再許可しない |

- 通常操作権と終了処理専用の利用状態を区別する。非継続側や中間台となった旧台から新編成を操縦したり、継続側と二重にドア・自動化設定を操作したりできる状態にはしない。旧担当が通常操作可能なまま、または台の設定・保持等を確認できない場合は発車できない。終了専用状態へ移行したことを確認できない場合を移行済みと推定しない。
- 44-Aの正常終了だけで運行継続側の時刻表・進捗を破棄しない。担当不在中も必要な保持を維持し、移行先の設備・キー等が不足すれば停止して理由を表示する。新台取得だけで発車せず、保持受渡しと既存の発車条件を必要とする。
- 車掌の移行・終了だけで受付済みの開閉・正式閉扉確認、ドア保護・保持を取り消さない。継続側が車掌不在でも非継続側へ自動移譲しない。同じ運転台の選択値は共有するため、車掌設備の終了だけで、運転担当が終了処理中の共有台を勝手に中へ変更しない。共有台の具体的な終了順序は後続の状態表に残す。
- 47-Aの確認不能・条件不足では保持と理由表示を続け、要復旧が発生すれば既定の中断・復旧を優先する。継続側ATOの外端移行は[2.4節](列車構成とプロファイル.md#s-2-4)の既存手順を維持する。非継続側の使用中時刻表・進捗の終了は[8.29節](時刻表と保存ダイヤ.md#s-8-29)の別処理で、終了制御のために旧時刻表の運行を続けない。
- 48-Aは必要な終了工程を飛ばす許可ではない。旧担当の通常操作の無効化、必要な台の終了処理・運転台選択・保持受渡し等を実際に確認した後に限り、画面終了だけを待たない。ドア・信号・進路・時刻表等の条件は維持する。
- **終了専用状態からの離脱（49-A）**。通常の運転操作権を失い終了操作だけの状態へ移行済みなら、その人の死亡・切断・距離超過だけでは新たな担当喪失EBを要求しない。未完了工程と必要な停止・保持は残す。実際の手動操縦担当の離脱には従来どおり要復旧EBを適用し、運転台選択不成立・保持不能等の別理由を消さない。
- **終了処理だけの引継ぎ（50-A）**。元の人または別の人が旧設備で終了処理のみを明示開始し、未完了部分を引き継げる。完全停止中かつその設備に未完了の終了処理がある場合に限り、同一設備の同時操作を認めない。運転用キーが必要な操作では既存条件を維持する。通常運転／車掌権限を取得せず、操縦・ドア操作・時刻表編集等は認めない。現在の設備・保持等を再確認し、完了済み工程を二重実行せず、指定位置を勝手に巻き戻さない。引継ぎだけで要復旧の復旧を済ませない。ATO自動終了・移行にこの手動入口を必須にしない。
- ATO開始との接続、共有台・兼任・運転形態変更の確定順、終了途中の再読込、既存の非常復旧との全状態表と詳細UIは最終照合・調査へ残す。

**成立条件と制御**

- 成立条件は、列車の両端の運転台が前・後で、全中間台が中であること。任意の二台の前・後だけでは成立しない。現在両権限が取得されていること自体を成立条件にはしない。
- 不成立の間はノッチ指定と独立したEB理由を要求し、成立で当該理由だけを自動終了する。この理由単独なら走行中も同じで、速度による要復旧化や復旧操作を要求しない。他の非常・要復旧・保持は維持し、最終適用はINTEROSが行う（[6.1](非常制御と故障復旧.md#s-6-1)）。
- 成立によって当該EB理由が終わっても残存Pを再適用せず、手動ではNへ切り替えてから改めてPへ入れる。指定レバーは勝手に変えない。必要な間はHUDへ「ノッチをNに切り替えてから、再度Pノッチに入れてください」等を表示する。他の保持・力行禁止条件は独立。
- EBは有限能力であり全勾配の転動防止保証ではない。設定成立中の連結待ち・交代・留置には必要な保持を確保する。成立時の通常保持との具体的受渡し、連結・分離・手動折返しの全操作表、権限・設定更新の確定順、失敗・保存境界、独立留置ブレーキの採否・用途は調査・詳細検討へ残す。担当喪失要復旧EBを設定成立で消さない。
