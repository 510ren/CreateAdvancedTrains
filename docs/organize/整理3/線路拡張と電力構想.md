### 13.1 線路強化・敷設拡張の目的と範囲（決定）

- 初期の重点は曲線の強化と、標準Createでは敷設できない曲線・勾配等の敷設拡張。摩耗・保守・点検・補修は初期に含めず、将来のアップデート候補とする。列車側の既存脱線系耐久は廃止しない。
- 「敷設拡張」は作れる形状・方向・長さを増やす機能、「線路強化」は線路側の通過性能を改善する機能として分ける。性能を改善する線路強化と、許容速度を下げる制限強化を混同しない。
- 曲線・勾配が最優先。平面の急曲線・短い接続、平坦／上り／下りの接続、曲がりながら上り下り、S字・異なる曲がりの連続を検討対象とする。全形状を対応可能と保証したものではない。
- 30°・60°等の斜め方向、最大敷設長の拡張も対象。角度を固定候補／任意入力とするか、具体上限・操作方法は未決定。
- 敷設できることと、その車両が通過できることを分ける。低速なら通れる形、車両寸法・台車等で低速でも通れない形、不正で経路自体が成立しない形を区別する。
- 車両が不適合形状へ進入した場合の脱線等の結果は後で決める。即時脱線／耐久減少／警告／ATO・安全装置による事前防止を独断で確定しない。

### 13.2 線路等級・未加工線路・軌間（最新決定）

- CAT独自の線路を低級・中級・高級の3段階とする。「標準・中級・高級」「標準等級そのものがCreate標準アイテム」という旧案は廃止。
- Create標準線路を何らかの方法で加工し、追加コスト0でCAT低級レールを得られるようにする。加工方法・場所・操作・個数対応・敷設済み対象の変換・戻し方・中高級のコスト等は未決定で、コスト0だけから消費／複製／返却を推測しない。
- 各等級は同じ軌間幅のCreate標準／Steam ’n’ Rails各種線路との接続・走行互換を目指す。等級と軌間は別属性。異軌間を変換する機能は今回の承認に含めない。
- Steam ’n’ Railsに標準軌・狭い軌間があることは利用者提供情報。対象版の全種類・識別・形状・互換処理はソースで確認する。各外観の加工・維持・等級対応は未決定。

| 線路 | 敷設 | CAT列車の走行 |
| --- | --- | --- |
| 未加工Create標準 | Create元来の敷設仕様。CAT拡張・敷設判定を適用しない | CAT走行仕様を適用し、線路側性能は低級相当 |
| 未加工Steam ’n’ Rails | 元の敷設仕様。CAT拡張・敷設判定を適用しない | CAT走行仕様を適用するが、各種類の線路性能・等級対応は未決定 |
| CAT低級・中級・高級 | CAT拡張と等級別敷設判定 | 当該等級の線路性能と実際の列車性能で評価 |

- Create標準とCAT低級は走行評価が同じ。同じ形状をコスト0で加工しただけで走行性能が変わるものにしない。ただし未加工線路にCAT低級の敷設基準を満たす保証はない。
- 元の仕様で敷設できた坂でも、CAT列車が登り切れず、力行中に減速・停止・後退することがあり得る。その路線・車両の選定は利用者の責任とし、特別な登坂補正で救済しない。CATの安全・保持・異常通知を無効にする意味ではない。
- 既存線路を自動撤去・CAT化しないが、従来と同じ走行性能まで保証しない。「未加工線路にはCAT走行制約を課さない」案は採用しない。
- 通常Create列車自身にCATの走行制御・故障を適用する範囲は未決定。上表はCAT列車についての合意であり、元の全列車を一律改造する承認ではない。

### 13.3 曲線・勾配と強化の効果（決定／具体式未決定）

- 等級は敷設できる曲線のきつさの絶対的な限界と、カーブ最大通過速度の双方に作用する。敷設限界は「低速運転予定だから」という理由では超えられない。
- 速度面の等級差はカーブ最大速度の緩和に限る。直線では低級・中級・高級で等級由来の速度差を設けず、高速直線のためだけに上位線路を要求しない。
- 車両側の最高速度・曲線通過能力は残り、標識・信号・ATOS・進入許可等を強化で解除しない。等級名と曲線形状は別情報で、同じ高級でも緩い／急な形を作れる。
- 勾配では、CAT線路は基準車両性能で登坂・停止できない形を敷設不可とする。登り続けること、途中再起動、下り減速停止、停車保持を分けて評価する方向。上位線路にしても重力・抵抗を消したり車両ブレーキを強くしたりしない。
- 最大勾配と勾配変化の急さは別条件。曲線と勾配の組合せ・接続部も見る。個別条件を満たすだけで複合形状も無条件に許すものではない。
- この敷設拒否はCAT線路の基準性能に対する判定。あらゆる低性能・故障列車の通過を保証せず、未加工線路は[第13.2節](線路拡張と電力構想.md#s-13-2)の別経路とする。
- カントを物理形状として持たせるか、評価用値か、視覚演出だけかは未決定。既定の揺れON／OFFで性能が変わるものにしない。

### 13.4 敷設評価値と基準プロファイル（採用する基本方針／改良可能）

- 様々な条件から敷設評価値を自動計算し、サーバー設定上限以下で敷設を許可する方式を基本とする。今後不整合・競合・実現性問題が見つかれば理由を示して利用者と改良する。
- 曲線・勾配・勾配変化・複合形状／接続部の厳しさを共通尺度へ換算し、最も厳しい値を総合値とする方向。単純な点数加算で、緩い条件の余裕が別条件の限界超過を相殺しない。
- 長い区間の平均だけで短い急曲線・急勾配を見落とさない。基準性能で登れない・止まれないこと、不正接続、計算不能は、評価値上限を上げるだけで通す扱いにしない。
- 条件別上限・基準性能・総合上限の関係は具体化する。説明用の「限界1、評価0.7／1.2」等は採用数値ではない。評価式・正規化・重複原因・誤差余裕・設定許容範囲は未決定。
- 各線路等級へ敷設判定用の基準車両プロファイルをサーバー側で対応付け、その実性能から可否を自動計算する。敷設プレイヤーが毎回性能を手入力する方式ではない。
- プロファイルの力行・制動性能、線路等級固有の曲線性能、評価上限等はサーバー側で定義し、予定形状・曲率・勾配・厳しさ・最終可否・拒否理由はCATが算定する。
- 車両プロファイルの等級表示と線路等級は別で、車両の等級名だけを登坂・制動性能として使わない。基準性能を線路設定へ重複して転記するのでなく、プロファイル参照を基本とする。
- 敷設時は基準プロファイル、走行時は実際の列車に保存されたプロファイルと通過線路を使う。基準車両へ走行性能を置換しない。
- 現行の車両プロファイルは項目の構想・保存方針までで、標準種類・値・抵抗／勾配式は未確定。幾何通過性能や質量・台車条件の追加要否も残る。敷設許容値を数値で確認できる完成済み性能表があるとは扱わない。

### 13.5 設定変更・確定直前の再確認（決定）

- 基準プロファイル変更はその後の新しい敷設判定へ適用し、既設線路を自動撤去・変形・等級変更しない。組立済み列車の保存性能もそれだけで更新しない。
- 線路等級自体の性能定義を変えた場合の既設線路への反映、設定版の保存・移行は別の未決定事項。
- プレビューの等級・基準性能・形状評価を基に、敷設確定直前にサーバーが最新設定・形状・接続先を再確認する。
- 条件変更・不成立なら敷設せず「敷設できない」旨を表示し、可能なら基準変更・勾配超過・接続先変更等の理由を併記する。再確認・再操作を求め、古いプレビューを無断で別形状へ補正しない。
- 拒否時はアイテムを消費しない。具体的な資源消費と設置確定の整合、重複要求、他人の同時編集の処理は要設計。

### 13.6 異等級の接続線路と性能移行（決定／詳細未決定）

- 異なる等級相当の線路をつなぐには、固定長・水平・直線の「等級接続線路（仮）」を使用する。同じ等級相当・同じ軌間なら直接接続可能。
- Create標準↔CAT低級は直接接続可。Create標準↔中級／高級、CATの異等級間は接続線路を用いる。低級↔高級も1本で接続でき、中級を挟む義務はない。
- 軌間変換設備ではなく同じ軌間に限定する。Steam ’n’ Rails線路の具体対応は等級対応を確認してから決める。
- 接続線路だけが水平直線でも十分とはせず、両端の向き・勾配・形状のつながりも確認する。固定長は減速距離の保証ではなく、先の曲線へ必要なら接続線路の手前から減速する。
- 内部に位置に応じた性能のグラデーションを持たせ、端では接続先の性能へ一致させる。全長を低級側性能に固定する案は取り下げた。
- 補間するのは適用可能な性能値で、等級名を順に切り替えるのではない。同じ物理位置の性能は走行方向で別物にせず、逆走では反対順に移行をたどる。
- 現時点では直線速度に等級差がなく、接続線路自体も水平直線。そのため「接続線路上の速度上限が自動で徐々に変わる」とはしない。車両性能や信号・ATOS等の制約も補間しない。
- 補間対象、距離に対する線形補間を用いるか等の方式、固定長・材料・形状表現・選択操作・基準プロファイル・敷設可否条件の扱いは後で具体化する。可否の論理条件をそのまま数値補間しない。
- 旧「通常線路を直接つなぎ両側で評価するだけ」の案は専用接続方式へ変更したが、境界の整合確認自体は残す。詳細な実鉄道の異種接続構造の再現まで広げない。

### 13.7 既存制御・耐久・保存への接続で残す判断

- 線路算定カーブ速度を、既存の物理標識制限とどのように統合するか。信号・ATOSと同一の故障原因にせず、出典・範囲・原因を残す。標識を強化時に自動書換えすることは未承認。
- 不適合形状の走行時結果、即時脱線／既存耐久の利用、速度違反と幾何不適合、複数原因の重複減少、ATO・安全装置の事前対応は未決定。
- 線路強化・加工・撤去だけで列車耐久を回復したり、要復旧・信号・進路許可を解除したりするものとはしない。線路状態と列車状態を区別する。
- 境界を列車のどの位置で評価するか、長編成が複数等級・勾配をまたぐ場合、方向・分岐・交差・ポータル、情報不足時の部分計算は残課題。
- 強化撤去・交換・定義変更で物理上限が下がる場合に[第9.2節](信号と安全装置と進路.md#s-9-2)の半減措置へ接続するか、その条件を決める。線路強化と制限強化の言葉だけで自動適用しない。
- 情報の未取得・古さ・計算不能を無制限へ置き換えない。既定の情報不足対応を基礎に、線路情報の有効性・再評価を具体化する。
- 操作対象単位、強化前後の形状、コスト・権限・返却、破壊／再配置／交換、グラフ分割結合・次元・保存版・同期・既存ワールドの初期データは未決定。実装方式を要件の先に固定しない。

### 13.8 形状収集の引継ぎと待機（資料受領済み／調査未完了・採否保留）

- 利用者がMinecraftを操作し、別会話で線路形状の代表例を収集・分類する方針の引継ぎ文を用意した。この文書保存後は結果提供を待ち、本会話では新しい判断を進めない。
- Createで敷ける形は実配置、拒否形は端点・プレビュー・エラー、操作方法のない希望形は画像への描き込みや線図で補う。Minecraftを本会話で起動・操作したという意味ではない。
- 平面曲線、一定勾配・頂上／谷、勾配と曲線、S字・曲がり変化、斜め方向・長距離、水平直線の等級接続と両端を分類する。代表形から条件を一つずつ変え、敷設可否の境界を見る。
- ケースID、目的、使用線路、版・設定、端点位置／向き／高低差、成功／拒否／未試行、画像・エラー、CATで実現したい点、未確認事項を記録する。見た目だけで正確な半径等を断定しない。
- 敷設成功は安全走行・CAT実装成立の証明ではない。実機観察・希望形状・ソース事実・仮説を分け、別会話で製品仕様を独断確定しない。
- 形状一覧・引継ぎ要約・97候補の総覧を受領した（[第13.12節](調査資料索引.md#s-13-12)）。候補収集の進展であって調査完了ではない。個別の対応／非対応／要検討の判断は未実施で、利用者の指示により線路拡張の議論は引き続き保留する。

### 13.9 今後の判断順（提案／数値・技術方式は未確定）

1. 形状収集結果を、曲線・勾配・接続・方向・長さに整理し、初期対応の代表形と除外・保留形を決める。
2. 各形状に必要な車両条件・ゲーム尺度・等級差を対応付ける。形状ごとの敷設拒否と走行時制約を分ける。
3. 敷設評価の入力・正規化・最厳値・相殺不可条件、基準プロファイルとの関係を具体化する。
4. カーブ速度・標識・安全装置・耐久・不適合走行の接続を決める。
5. 等級接続の対象性能・補間・長さ・操作、通常加工・強化の範囲／権限／資源を決める。
6. 保存・同期・交換・既設線・性能定義更新・未読込・データ不足を整理する。
7. 採用候補に必要な追加ソース・数理確認だけを行い、全体整理後に数値・精度・負荷・受入条件を決める。保守・摩耗は将来候補で、開始条件として全管理値収集を要求しない。

### 13.18 線路からの電力供給（追加構想／詳細保留）

- パンタグラフ・架線だけでなく、給電対応の線路からも電車へ電力供給できるようにしたい。給電対応の線路アイテムを用意する構想を追加する。
- 供給の強さに応じて線路が光る表現は仮案。「強さ」を電圧・供給可能電力・ゲーム独自の段階値等のどれにするか、発光を状態表示とするか演出とするかは未決定。
- 線路等級・軌間との組合せ、架線／線路双方を備えた車両、給電源・接続・途切れ・保存／同期・性能への作用は後日の検討項目。現実の特定の集電方式と同一と断定しない。
- 電力詳細は他の仕様整理後という保留を維持する。線路97形状の議論を再開する指示でも、初期実装・具体数値の承認でもない。
