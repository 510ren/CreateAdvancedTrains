## 2. 文書から確認できる決定理由

以下の「理由」は記録にある説明の要約。技術的な成立証明や実機検証ではない。

| 決定 | 記録されている理由・目的 | 正本 |
| --- | --- | --- |
| 表示ノッチと実効ノッチの分離 | 運転手が指定と実際の制御介入を認識できるようにする。Pは同じ加速度になり得るため逆算しない | [11.8](マスコン操作とHUD.md#s-11-8)、[4.1](加減速とノッチ.md#s-4-1) |
| 原本と運行用コピーの分離 | 運行進捗・変更で再利用用原本を書き換えない | [8.29](時刻表と保存ダイヤ.md#s-8-29) |
| 保存アイテムへの原本格納 | マスコンを保管先にする途中案の管理の煩雑さを避け、主副や設備交換と受渡しを分離する | 8.29の見直し履歴 |
| SpeakerControllerの本体提供 | ATOS接近音・停車／通過案内・条件付き再生終了と運行の連携に独自の利用価値がある | [13.16](共通方針と責任分担.md#s-13-16) |
| 一律N移行・実効引継ぎ等の旧案を残す | 二重操作や保存Pの急適用を避け滑らかに交代する目的は維持し、現行条件に合う操作を再検討する | [11.22](マスコン操作とHUD.md#s-11-22) |
| 影響度による照合の絞込み | 無関係な全分野の反復読込を減らし、共通制御・安全・権限等を優先して確認する | [管理手順4.6](../../workflow/ドキュメント管理手順.md#impact-review-policy) |

## 3. 理由・証拠を補う際の限界

- 規定連結器の小・中・大、同サイズ接続、具体的な取付条件は2.4の合意が正本。整数の基準間隔を希望した経緯はあるが、各サイズ・許容差の定量根拠は未決。Create側の整数保持構造だけを利用者の採用理由と断定しない。
- 「継続側を採用」「双方へ共通設定を継承」等には選択回答が根拠として残るが、全てに個別の長い理由が記録されているわけではない。根拠が承認であることと、選択理由を確認できることは別。
- 実車の例、利用者の実機観察、提供ソースの静的事実、AIの考察を区別する。実車速度や現実との一致を未調査のまま理由に追加しない。
- 本整理は参照可能な現行文書と照合記録の範囲。全チャット履歴の理由を完全回収した保証ではない。理由不足が後の判断に影響する箇所だけ、利用者へ確認する。
