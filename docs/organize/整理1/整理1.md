## やりたいこと

> [!NOTE]
> 名称は日本の鉄道(特にJR)で用いられている技術名を分かりやすさのために使用している。（各機能の具体的な内容は[鉄道調査結果.md](./鉄道調査結果.md)を参照）

### 前提的な内容

- Createの列車に以下の機能を追加する。
  - D-ATC：安全上の上限制約
  - ATACS：D-ATC・ATS・信号などのシステムを包括する新安全システム（車上）
    - ATSは、ATS-Pを参考とする
  - TASC（改良版）：停車精度の確保
  - INTEROS：車両情報の管理
  - ATO：自動運転システム（従来では「ブレイズバーナー」等を用いた実装でなっていたもの、手動運転時は無効）
- Createの信号システムを改良する
  - 日本の信号で使用されている「5灯式」の信号を用いる。
  - 現示種類は「停止」「警戒」（上限速度〇〇km/h）「注意」（上限速度あり）「減速」「進行」（最高速度まで可）である。
  - 安全マージンとして、停止を1枠設ける。従って実際の現示状況としては、「停止→停止→警戒→注意→減速→進行→進行」となる。
- CAT独自の「マスターコントローラー」（マスコン）ブロックの追加
  - 列車搭載の機能（ATO、ATC、TASC等）や、現在の走行状況（信号、速度、位置）、駅・停車情報、同じ線路内の先の列車位置と距離等を表示するHUDかつCAT操作用（ノッチ操作、前後どちらに進むかを指定する等）のブロック
  - このブロックが設置されていない列車はCreateの「標準列車」として扱い、マスコンブロックがある列車のみを「拡張列車」（CATの機能あり）として扱う。両方ある場合は、標準を優先し拡張とはならない。（下手に介入しない）
  - ATO等各機能の有効無効等を設定でき、時刻表をマスコンに入れる（枠を作る）ことで自動運転を適応できるようにする
- ノッチ操作の追加
  - マスコンに列車プロファイルを適応することで適応できるノッチ数を変化させる。
    - 普通列車プロファイル
    - 高性能プロファイル
    - 新幹線プロファイル
    - などなど
  - 基本は「P1~P5」（加速）「N」（加速なし、自然減速）「B1~B7, EB」（ブレーキ）
    - 自動運転時のEB発動はATOを完全に無効とし、加速はせず停止状態を保つ。
      - これはATOSからプレイヤーが「解除」するか、現地でレンチを用いて解除することが出来る。（自動で回復はなし）
      - 信号の関係（後述）でのEB発動と、線路上にプレイヤーがいてB7で停車できない場合にEBを発動する2つの場合がある（解除条件は同じ）
    - 基本各ノッチは比例の関係を保つ
  - プロファイルに合わせて各ノッチの性能を向上させる
  - 手動運転時のみで、ATO適応時は無効で滑らかに加速度を適応する
- ATOSと各車両のINTEROSを接続することにより、遠隔（総合指令所のような場所）から各マスコンで確認できるようにし、最高速度の設定・制限、ダイヤ整理などを行えるようにする
  - ATOS指令ブロックのようなものを使うか、プレイヤーが使えるアイテムとして用意するかも検討したい。操作できるのは自分のマスコンキーが入った列車のみ（自動運転を設定するにしても、自分が所有するマスコンキーの挿入が必要とされるためそれで判定する？）
  - マスコンキーにはランクがあり、「通常」（自分のマスコンキーが設定された列車のみ）と「管理者」（全列車）で、クラフト材料の難しさで区別（管理者のキーを作るには、ネザライト関連のアイテムが必要といった具合）

### 前提の上でやりたいこと・注意点

> [!TIP]
> 以降の内容は拡張列車としての内容

- 拡張列車では、Create従来の操作（W・S）は無効化し、完全なノッチ操作とする
  - レンチで移動や衝突イベント等、操縦に関係のないものは保持する
- マスコンで、自動運転時に手動操作が入った場合、ATOを無効化し手動操縦に切り替える（航空機のオートパイロットのようなもの）
- 自動運転を開始したい場合、標準の時刻表をマスコンのGUIに入れる
- マスコンを動作させるのに必要な、「マスコンキー」のようなものもできれば実装したい
- アイテムは全てクラフト可能とする
- 本機能の有効・無効はマスコン上から出来るようにしたい
  - ATOが動作中は全て強制的に有効となり、変更不可となる。
  - 各機能のオンオフはボタンGUIで変更できるようにする的な感じを想定
    - INTEROSは無効化不可（情報共有システムのため）
- Forge 1.20.1 x Create 6.0.8を基本動作環境（絶対に動作）とするが将来的には他バージョンとの互換性も担保したい（ForgeだけでなくFabricやNeoForgeも）
- 最低限以下アドオンとの互換性（同時動作）を確保
  - Steam 'n' Rails
  - Railways Navigator
  - Lazy Tick
  - Better FPS
- 計算式は出来るだけ現実で採用されているものにするが、Minecraft上の動作の自然さを優先するため独自の改良版を用いることもある
- 手動運転時はATO以外の各機能が動作するようにする（オンオフは可能）
- 駅ブロックの停車判定をピッタリの位置から±0.5ブロック程度に許容するようにしたい（現実に似せる、ここはtascで調整）
  - 方法は要検討
- ある方法にとらわれないで、難しい場合はNBT等も含めた完全独自（他アドオンとの互換性を保つだめCreateのTrainクラス互換）のCATTrain（仮称）クラスを作成することも検討する
- 列車に搭載する機能と内部的なものをしっかり区別する
- 実装状況を安定させる（標準的なアドオン開発）ため、Create Realism等の他アドオンのJava記述を確認したりする。
- 運転台について
  - Create標準の運転台：Createの計算のみ
  - CAT独自のマスコン：CAT独自の計算、Createの計算は無効化（要らないものは捨てる）
    - 不用意に計算がされない（適応されない）ように境界を定めたい
  - 各機能の有効・無効は前述の通り列車単位のNBTかその他適切な方法で管理する（設定のオンオフ管理等にマスコンキーが使える？）
- MOD全体の設定として変えられるものはデバッグ関連とATOS関連のみ（列車単位ではないもの、「のみ」としているが他の追加項目がある場合それを含めることもある）
- コーディングのより詳しい規則や設計思想を固める
  - 常に実装の際にはコメントを書き、書き方も固定する
- 全体の関係図を書き、より全体に関連する機能から実装（枠組みだけを作る場合もある）する。（下の方から作るとより全体に関連する上の方の対応が大変になる）
- アイテム・ブロックのデザインやしたいことは早めにまとめ、描画（テクスチャ）についてもより詳細に考える
- 様々なシミュレーションを用意し、各実装等にそれに沿えるか検討する。（詳細な内容については後々）
  - 考え中
- 信号はCreate標準の信号機ブロック上に置くか考える（情報は信号クラス内のCAT独自変数として管理する形式？）
- 様々な信号の交わり方・置き方等を考え、実装する際にそれをシミュレートする
  - 信号の種類の切り替えについて、配置間隔を配慮するように出来ればしたい（10ブロック置きに設置されている場合、停止まで60ブロックしか猶予がなくなってしまう）
    - Createの加速度と最高速度設定に応じて間隔の配慮を緩めたり、強くしたりする。
  - 列車の進行速度に合わせて確保する安全領域（交わるところの停止現示）を計算する（B7で止まれる範囲までの交わる箇所（速度が速い方）を停止現示する）
    - B7で止まれない範囲で列車が交差する場合、速度が遅い方にEBをかけ、早い方は進行させる。（進行できるだけのスペースがある場合、ない場合は両方EB）
- 発車メロディなどの音を流すスピーカーブロックのようなものを実装したい
  - 各スピーカーでmp3をセットでき、レッドストーン信号で鳴らす or 列車搭載のマスコンから流すことを可能とする
  - スピーカーは半径64ブロック以内（仮）ならリンクさせることができ、どれか1つ鳴るとリンクされたスピーカーが同時に再生されるようにする
    - A-Bでリンクしたあと、Aから64ブロック以上離れているCスピーカーには64ブロック以内のB-Cでリンクできる（A,B,Cのうちどれかが鳴れば全て鳴る）
  - デザインは後決め
- ある列車の通過待ちをスケジュールに組み込むような機能もできればほしいが、優先度は低め（発車メロディーとスケジュールは列車とあまり関係のない別管轄のため、後実装でも無問題）
- 実装上においてはパフォーマンスを最重要とする
