# CAT 会話引継ぎと開始の手引き

作成・適用日：2026-11-04。状態：利用者の指示に基づく共通運用。製品仕様や実装承認ではない。

## 1. 必須参照と文書の役割

CATの会話を開始・再開する担当者、および会話引継ぎを準備する担当者は、[AGENTS.md](../../AGENTS.md)の指定文書とともに、必ず本書を読む。会話開始・引継ぎの具体的手順は本書を唯一の更新先とし、他文書は本書への参照と会話固有の状態を記載する。

- 本書：全会話共通の作成・第三者確認・引継ぎ先初回確認の手順。
- [handoff一覧・現在の参照先](../organize/整理3/handoff/README.md#current)：会話固有の現在地、根拠への入口、確認状況、次の行動。別の会話への引継ぎは連番の新規ファイルとし、同じ移行の補足・訂正と区別する（2.3節）。
- [整理3の索引](../organize/整理3.md)と分野本文：要件整理の詳細の正本。handoffへ仕様全文を複製しない。
- [残課題](../organize/整理3/残課題と再開地点.md#s-14-3)：未決事項・調査待ち・保留と次回対象の候補。
- [ドキュメント管理手順](ドキュメント管理手順.md)：保存・競合・履歴・影響評価。固定保存版、旧資料、過去の移行記録を現在の指示にしない。

利用者が最終決定者である。決定・提案・未決・調査事実・実機確認を区別し、旧実装を現行仕様に流用しない。製品仕様を変更せず引継ぎだけ整える依頼から、新たな製品判断を確定しない。

<a id="prepare"></a>

## 2. 引継ぎ元で行う準備

1. **範囲を確認する。** 作業場所、会話の目的・完了範囲、今回の決定群、未保存内容を確認する。引継ぎ元が次会話の範囲案・終了条件を整理し、既に利用者が指定した範囲を優先する。未承認の範囲案は案として区別し、利用者の確認・変更を受ける（2.1節）。既存の未コミット変更も確認する。
2. **本文を確認する。** 索引から対象本文・直接影響先・必要な調査根拠を読む。合意内容と保存内容を照合し、管理手順4.6の影響度0～3で各決定群を評価する。原則2以上と安全・保持・権限・データ消失等の必須対象を関連照合する。全資料の毎回の一括読込は不要。
3. **保存を区別する。** 利用者の明示保存指示のターンは推論レベルと必要なら短い理由だけを回答し、ファイルを変更しない。次ターンの再開指示後に指定範囲を保存する。合意・圧縮・移行だけで自動保存せず、未保存は未保存と表示する。既に推奨回答済みの保存を再開するとき、同じ手順を繰り返さない。
4. **第三者確認を受ける。** 次節に従い、会話で決定した事項の矛盾・競合・不足・不正確さを確認する。未実施・照合待ちを完了としない。
5. **会話固有のhandoffをまとめる。** 2.3節の識別方法と第4節の項目に従い、一覧の現在参照先・索引・残課題・古い再開案内を整合させる。第三者指摘により製品判断が必要になった事項は、未決・確認待ちとして引き継ぐ。
6. **保存を検証する。** 差分、条件・数値・状態区分、リンク・節アンカー・旧節番号、意図しない欠落や重複を確認する。履歴・固定保存版は管理手順に従う。更新対象と確認範囲・未確認、この会話の残り作業を報告し（2.2節）、次会話へ貼る開始文を提示する。

30～50ターンは移行を点検する目安に留め、話題の区切り・文脈の混乱・利用負担で判断する。全未決の決着や実装・実機検証の完了を会話移行の条件にしない。自動圧縮を正確に予知できる前提にしない。

<a id="conversation-scope"></a>

### 2.1 会話の目標・範囲と終了条件

引継ぎ元は、次会話で決定・確認する内容の範囲案を整理する。既に利用者が指定した範囲はそのまま引き継ぎ、指定がなければ候補と推奨順を示す。作成担当者だけで範囲を最終決定せず、利用者が確認・変更できる形にする。承認前の案を合意済みと記載しない。

範囲には「目標」「含む事項」「対象外・保留」「終了条件」「依存する先行確認」を記載する。終了条件は、例えば「相談順1～3の基本判断と全体残課題一覧の見直し」のように、全仕様の完成と区別できる粒度にする。

会話中は常に合意した目標と残り作業を把握し、論点の区切り・保存後・範囲変更時に進捗を示す。毎回答で同じ目標を繰り返す必要はない。目標に関係する補足や短い調査は許容し、独立した別分野などへ大きく広がる場合は、関係と未処理内容を整理し、今回に追加するか次回以降へ送るかを利用者と判断する。自動で範囲を拡張したり、別会話の作成・保存を実行したりしない。

指定範囲を終えた後は、関連するが範囲に含めなかった未決事項・不足・依存先を洗い出し、今回決めるか、調査待ち・保留・次回対象にするかの判断材料を提示する。完了済みの基本判断を未決へ戻さず、関連事項をすべて解消することを会話終了の条件にしない。範囲内の決定に不可欠な依存事項や矛盾は、完了後まで待たず発見時点で提示する。範囲の追加・変更は利用者の判断と理由を保持し、ファイルへの反映は明示保存指示に従う。

<a id="remaining-work"></a>

### 2.2 保存完了ごとの残り作業の提示

利用者の明示指示に基づく保存・更新が完了するたびに、保存結果に続けて次を簡潔に提示する。

- この会話の範囲内で残っている決定・確認事項。
- 次に扱う論点と、必要な先行確認。
- 調査待ち・保留・次回へ送る事項。詳細は残課題や本文の参照でよい。

全プロジェクトの未決一覧を毎回再掲せず、この会話の範囲を中心にする。範囲内の残りがなければ「予定範囲は完了」と示し、関連する範囲外の事項を追加検討するかの判断へつなぐ。会話が進んだだけでファイルを保存する指示ではない。

保存指示を受けたターンは従来どおり推論レベルの推奨だけを回答する。次ターンの再開指示後に実際の保存を行い、その結果と残り作業を提示する。保存に失敗した場合は未保存の範囲・理由・残り作業を示し、保存完了と扱わない。

<a id="handoff-numbering"></a>

### 2.3 移行ごとの連番と現在参照先

- 要件整理のhandoffは `docs/organize/整理3/handoff/` に置く。別の会話への引継ぎを作成するごとに、既存の最大番号の次を使った `NN-handoff.md` を新規作成する。`00-handoff.md` の次は `01-handoff.md`、`10-handoff.md` の次は `11-handoff.md` とし、番号は最低2桁、100以降も数値順で扱う。既存ファイルを上書きして別移行に使ったり、過去の番号を使い回したりしない。
- 同じ移行の補足・訂正・初回確認結果の追記では同じファイルを更新し、新番号を発行しない。通常の保存や同じ会話の再開だけでは新しいhandoffを作らない。更新は利用者の明示指示の範囲で行い、変更日・概要を残す。
- 各ファイルに識別番号、対象移行、作成・更新日、状態、前後のhandoffへの参照を記載する。後続がなければ「未作成」とし、存在しないファイルへリンクしない。旧ファイルは過去の移行として保持し、現在の開始指示と混同しない。
- [handoff一覧](../organize/整理3/handoff/README.md#current)を現在参照先の唯一の更新先とし、ファイルごとの対象移行・状態と、現在使うファイルを明示する。最大番号が作成中であっても自動的に現在参照先へ切り替えない。移行案内として使う対象を明示してから更新する。第三者確認・初回確認が未了でも、その状態を表示して案内できる。
- AGENTS、docsの入口、整理3の索引・残課題は一覧を参照する。会話固有の開始文・根拠記録は対象ファイルを直接参照してよい。切替時は一覧・新ファイル・前後の参照・現在の案内を確認し、過去の記録内のリンクを新ファイルへ一括置換しない。

導入時点の `00-handoff.md` は現在準備している同じ移行のファイルとして維持する。次の別移行から `01-handoff.md` を作成する。既に同ファイルに含まれる前回移行の案内は過去記録と明示し、今回の導入のために過去の引継ぎファイルを推測で再作成しない。

<a id="independent-review"></a>

## 3. 会話の決定事項に対する第三者確認

第三者確認は、handoffの文章を読むだけでなく、対象会話で決定した事項と保存先・関連本文の関係を点検する工程である。作成担当者の自己点検と区別し、別の人または独立した別AIの確認であることを記録する。同じ担当者の読み直しを第三者確認と呼ばない。

確認者には、対象会話・決定群、利用者の判断根拠、保存先の節、変更範囲、影響評価、関連文書、既知の未決・調査待ちを渡す。会話の根拠を参照できない場合はその制限を記録し、本文間の整合だけを確認したことと、会話からの反映を確認したことを区別する。

| 観点 | 確認する内容 |
| --- | --- |
| 矛盾点 | 同じ条件で異なる動作を要求していないか。旧規則・撤回案が現在の規則に混ざっていないか |
| 競合 | 制御優先順位、操作権限、同時処理、保持・復旧・継承などが他の合意と衝突しないか |
| 不足 | 必要な前提、対象・終了条件、責任分担、根拠・参照、未決表示が欠けていないか |
| 不正確 | 利用者の判断の誤記・過度な一般化、提案の採用済み化、調査・推論・実機確認の混同がないか |

指摘は「対象決定／根拠節・会話根拠／問題と影響／修正案または利用者への確認事項／対応状態」で記録する。指摘なしでも確認した対象・限界を残す。表記・参照の修正と製品判断を分け、第三者の提案を自動採用しない。修正後は影響範囲を再確認し、未解決と判断待ちを残す。

handoffには、確認者・実施日・対象範囲・結果の参照先・対応済み／未対応／未確認を必ず記載する。第三者確認を手配できなければ「未実施」と理由・次の担当を記し、第三者確認済みとは報告しない。確認未了のまま引き継ぐ場合は、引継ぎ先の先行作業として明示する。未確認は製品仕様が誤りと確定した意味ではない。

この工程は外部へのメッセージ送信・資料公開・自動的な別会話作成を許可するものではない。利用可能な確認方法と権限の範囲で実施する。確認者による文書修正も保存指示の範囲を守る。

<a id="handoff-contents"></a>

## 4. handoffに必ず含める内容

1. **識別と現在地**：対象プロジェクトの絶対パス、識別番号、作成・更新日、対象移行・状態、前後のhandoff参照、今回の区切り、作業段階、完了範囲、保存済み／未保存。
2. **読む順序と正本**：AGENTS、本書、管理手順、索引、必要な分野本文・根拠節へのリンク。全資料を一括で読ませない。
3. **合意と変更の入口**：今回の決定群、変更・撤回の要点、理由・影響評価・照合記録への参照。詳細は本文へ集約する。
4. **第三者確認**：第3節の確認記録と残る指摘。自己点検や引継ぎ元の文書準備を、独立した確認の完了に置き換えない。
5. **初回確認**：次節の確認項目、根拠・必要なら確認問題と別の期待回答へのリンク、実施担当・確認待ちの状態。前回合格を今回の合格として流用しない。
6. **未決・調査・保留**：未決理由、後決め数値、既存の部分調査、未確認範囲、再開条件。線路97形状・電力詳細などの保留は指示なく解除しない。
7. **次の行動と制約**：次会話の目標・対象に含む事項・対象外と保留・終了条件・先行確認、範囲の承認状態、次に読む節・相談の依存順・利用者判断が必要な点。対象未指定なら範囲案を示して利用者の指定を待つ。範囲完了後に関連する範囲外の事項を見直す方針も引き継ぐ。実装・ビルド・Minecraft起動・コミット・公開は個別の明示依頼が必要で、引継ぎから自動で進めない。外部MODソースは提供済みvendorを用いる。
8. **開始文**：本書と当該handoffの場所、初回確認、対象範囲・保留・禁止事項を含める。前回の完了済み相談や古い確認問題を新しい再開指示として貼らない。

過去の実施記録・合格記録は日付と対象移行を保持する。旧開始文を残す場合は過去資料と明示し、現在の開始文から分離する。

<a id="initial-check"></a>

## 5. 引継ぎ先の会話開始・初回確認

1. **必ず読む。** AGENTSと本書、対象handoffを読み、指定された索引・分野本文・再開地点を確認する。通常の新規会話でも、最初に本書で引継ぎの有無を確認する。handoffがない場合は通常の対象・作業段階・根拠の確認を行い、存在しない引継ぎの合格を作らない。
2. **独立して理解を示す。** 引継ぎ先の担当者が、本文の節を根拠に、下記項目を回答する。具体的な確認問題がある場合は、期待回答を先に読まずに索引と分野本文から回答し、その後で期待回答・確認基準と比較する。問題数は対象範囲に合わせ、前回の5問を固定で使い回さない。期待回答は製品仕様の正本ではない。
3. **食い違いを分類する。** 読解不足、リンク不足、文書不足、新たな矛盾、未確認に分け、根拠節と影響を示す。判断不能を推測で合格にせず、必要な補足・修正・利用者判断を明示する。
4. **結果と次の行動を示す。** 確認日・対象移行・結果・補足後に確認できた内容・残る未確認を報告する。結果のファイル保存は明示指示がある場合だけ行う。第三者確認の未解決を初回読解の合格で消さず、必要な確認を先行する。範囲が不明なら利用者へ確認し、既決内容を再決定しない。

初回に確認する項目：

- 作業場所・作業段階・正本・今回の完了範囲と未保存の有無。
- 重要な決定と撤回・変更、関連分野への影響、決定／提案／調査／実機確認の区別。
- 第三者確認の実施範囲と未対応指摘、初回確認そのものの未確認。
- 未決・保留・次会話の目標と範囲・承認状態・終了条件・範囲外の扱い、実装等へ自動で進まない制約。

引継ぎ元では引継ぎ先の初回確認を代行して合格にしない。初回確認が済むまでは旧会話を残し、新会話の作成・旧会話の終了／アーカイブは利用者の操作または明示依頼による。同じ移行の確認が済んだ後の通常の再開では保存済み状態・変更された規則を読み直し、理由なく同じ試験を繰り返さない。

## 6. 記録用の最小書式

handoffの確認欄には次を記載する。詳細な指摘一覧は記録へのリンクでよい。

| 項目 | 記載内容 |
| --- | --- |
| 対象移行 | 基準日・引継ぎ元／先・対象範囲 |
| 識別と参照 | 番号・作成／更新日・状態・前後のhandoff・一覧の現在参照先 |
| 会話の目標と範囲 | 承認済み／案／未指定、含む事項・対象外／保留・終了条件・先行確認 |
| 残り作業 | この会話で残る決定／確認、次の論点、範囲外の関連事項と扱い |
| 第三者確認 | 未実施／実施中／指摘対応中／対象範囲確認済み、確認者・日付・根拠・未解決 |
| 初回確認 | 引継ぎ先で未実施／確認中／補足待ち／対象範囲確認済み、担当・日付・回答・比較結果 |
| 保存検証 | 更新先・差分と参照の確認・未確認 |
| 次の行動 | 先行確認・利用者判断・相談対象・保留 |
