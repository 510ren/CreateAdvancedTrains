# 開発フェーズ・ロードマップ

## 現在地

Phase 5は完了扱いとする。完了範囲は、最終B1〜B7の初期Profile、応答込みBrakingCurve、
Navigation停止対象の正規化、到着共有フラグ、列車単位の計算エラーラッチという**制動の基盤**である。
Phase 5Aの固定ノッチ測定治具は、引き続き製品機能から独立した試験用機能である。

Phase 5完了は、自動停車・自動ノッチ・TASC・ATC/ATS・EB・マスコンが完成したことを意味しない。
Minecraftでの走行試験と受入判断はユーザーが担当し、各PhaseのJava実装担当であるSolの完了条件には
含めない。

## 依存関係

```text
Phase 5  制動基盤
   ↓
Phase 6  TargetSpeedResolver・ATO統合・自動常用ノッチ
   ↓
Phase 7  TASC・駅停車
   ↓
Phase 8  信号・ATC/ATS・EB・安全ロックアウト
   ↓
Phase 9  マスコン・独立HUD・独立操作
   ↓
Phase 10 統合走行試験に基づく調整
```

各Phaseは、前段のJava実装が存在することだけで開始してはならない。未決の数値・状態遷移・
Create 6.0.8との境界を先に文書化し、ユーザーが承認してからSolへ依頼する。

## Phase 6 — 統合速度制約・ATO・自動常用ノッチ

### 目的

Phase 5のBrakingCurveを実際の走行制約へ接続し、Createの標準速度追従経路を保ったまま、
通常走行の力行P1〜P5・N・常用制動B1〜B7を自動選択できる基盤を作る。

### 実装対象

- `TargetSpeedResolver`を新設し、Create由来目標、路線速度制限、BrakingCurveの最大許容速度を
  同じ単位で統合する。
- ATOを「Create目標を直接加工する担当」から、Resolverが返す最終CAT目標をCreate境界へ渡す担当へ
  整理する。
- `NotchSelector`と製品版`NotchController`を設計・実装する。必要な加減速度と現在の
  `effectiveAcceleration`から、力行P1〜P5・N・B1〜B7の要求ノッチを選ぶ。
- 要求ノッチはPhase 5の10 tick線形応答・再遷移規則を必ず通る。
- Nは`targetSpeed = 0`かつ`accelerationMod = 0`で表し、加速・減速を行わない。
- BrakingCurveの`u_ceiling`供給元を確定する。CAT設定を新設するなら、設定パス、キー、単位
  （blocks/s）、既定値、Create側上限との関係を仕様で決める。

### 非対象

- 駅の停止誤差補正・クリープ・到着判定はPhase 7のTASCが担当する。
- 信号、ATC/ATS、EB、プレイヤー保護はPhase 8が担当する。
- マスコンのGUI/HUD・専用キーはPhase 9が担当する。

### 開始前に確定する事項

- `u_ceiling`の供給元と、複数制約の最終採用順序。
- NotchSelectorの入力、出力、切替ヒステリシス、Nと力行の選択条件。
- P1〜P5の性能Profile、速度依存性、Pノッチ間隔、P/B切替時の目標加減速度。
- Create `targetSpeed`と`accelerationMod`の組合せを、力行・N・常用制動の各状態でどう維持するか。
- CAT Controller Blockを搭載した列車だけを対象にする検出方法。

### 受入条件

- Resolverは各制約を個別の結果として保持し、最終速度だけで根拠を失わない。
- BrakingCurveは引き続き純粋計算であり、`Train`やworldを書き換えない。
- 通常制御は`Train.speed`を直接変更しない。
- Phase 5Aの固定ノッチ試験設定が、製品版の自動選択を有効化・変更しない。
- SolはJava実装、Create 6.0.8実ソースとの静的照合、Gradle buildを報告する。走行試験はユーザー担当である。

## Phase 7 — TASC・駅停車制御

### 目的

Phase 6の通常制動から、駅の線路上GlobalStation EdgePointへ快適かつ再現可能に停車する低速制御へ
引き継ぐ。

### 実装対象

- `TascController`を独立した責務として設計・実装する。
- 対象は駅ブロックを持つ停車だけとし、駅停止の60 blocks手前から低速制御候補へ入る。
- 駅停止の20 blocks手前から、0.2〜0.4 blocks/sのクリープ速度へ近づける。
- 停止判定は、停止位置に対して±0.5 blocks以内かつ`v < 0.01 blocks/s`を初期条件とする。
- Navigationの到着共有フラグを消費し、TASC優先の間はPhase 6の通常ノッチ選択と競合しないようにする。

### 検討・確定が必要な事項

- Phase 6からTASCへ引き継ぐ正確な条件、復帰条件、優先順位。
- クリープ中のN/Bノッチ選択、行き過ぎ予測時の再制動、停止位置を超えないための境界。
- 駅ではない停止（信号など）の許容誤差を1〜2 blocks手前とする際の共通ルール。
- Createの駅近傍補正とCAT TASCが競合しないtick順序・target制御。

### 非対象

- 信号保安・ATC/ATS・EBの発動判断はPhase 8。
- HUD表示の最終デザインはPhase 9。

## Phase 8 — 信号・ATC/ATS・非常制動・安全ロックアウト

### 目的

駅停車とは別の保安停止、速度制限、非常制動、オーバーランを一貫した安全状態として扱う。

### 実装対象

- Create信号・線路終端等を読み取り専用で観測する`SignalController`を設計する。
- `AtcAtsController`が信号・速度制限・停止保護点から速度制約を返し、Phase 6のResolverへ渡す。
- `EmergencyBrakeController`を常用制動と別の状態機械として実装する。
- 安全保護対象は手前3 blocksを保護位置とし、B7の安全側予測で保護位置を超えるとEB候補とする。
- 駅はB7継続でも10 blocks以上の過走が予測される場合だけEB候補とする。通常の±0.5 blocks誤差だけではEBにしない。
- `destination != null && distanceToDestination < 0`では、Createの物理脱線を呼ばないCAT独自の
  脱線相当安全ロックアウトイベントを発火する方向で設計する。
- EBと安全ロックアウトは、原因解消後にレンチでのみ復旧を試行する。復旧不可なら状態を維持し理由を返す。

### 開始前に確定する事項

- Create信号の意味、停止位置、予約・経路との境界をCreate 6.0.8実ソースで確認すること。
- EBの減速度Profile、手動EBの操作、前方プレイヤー保護の検出範囲・判定頻度。
- CAT安全ロックアウトイベントの公開形、発火・購読側、保存、通知、レンチ復旧との接続。
- ATCとATSの具体的な保安装置モデル、優先順位、各制約の解除条件。

### 非対象

- 駅の最終停止操作はPhase 7 TASCの責務。
- マスコンの画面・HUD表示はPhase 9。ただしServer側の状態・原因情報は提供する。

## Phase 9 — マスコン・独立HUD・独立操作

### 目的

CAT専用ブロック「マスコン」をCreate標準運転台に代わる高性能運転台として提供し、CATの運転状態を
独立した操作・表示で扱えるようにする。

### 実装対象

- マスコンBlockと、列車・運転席との関連付けを設計する。
- Client側の設定可能なCAT専用前進/後進キーを実装し、Serverへは操作意図だけを送る。
- CAT独立操作が対象列車を受け付ける間、Createの`W`/`S`による前後進指令を当該操作経路では無効化する。
- 独立HUDに、現在速度、停止までの距離、制限速度、ノッチ種別、ATO/TASC/EB/エラー状態を表示する。
- 到達可能な近傍駅をおおむね4駅まで取得して距離を表示する。単一Navigation destinationだけで代用しない。
- 将来の列車種別Profileを、マスコンまたはCAT対象へ付与できる拡張点を設計する。

### 開始前に確定する事項

- 操作権限、複数プレイヤー時の優先順位、マスコンとCreate標準運転台の切替条件。
- HUDのレイアウト、更新頻度、欠損・エラー時の表示、単位表示。
- 近傍駅探索の分岐処理、到達可能性、並び順、最大件数、探索上限。
- BlockにProfileを付与するデータ形式と、既存列車への適用・永続化方法。

### 不変条件

- Clientは`Train.speed`、物理制御値、安全制約を直接変更しない。
- Serverが列車単位で操作権限と安全状態を検証する。
- 開発用Debug HUDは最終HUDとして流用しない。

## Phase 10 — 統合走行試験と制動調整

### 目的

Phase 6〜9を統合した実走行結果を根拠に、ゲームとして自然で安全な制動・停止挙動へ調整する。

### 調整対象

- 速度依存`δ(u)`、`κ(u)`、安全余裕`M(u)`。
- B1〜B7の速度域別Profile、ノッチ選択のヒステリシス、遷移中の乗り心地。
- TASCの引継ぎ距離、クリープ開始、クリープ速度、停止誤差。
- EBの過走判定、保護位置、安全ロックアウトの復旧条件。
- 速度制限・信号・ATC/ATS・駅停止が同時に存在するときのResolverの優先・最小値処理。

### データと進め方

- TrainDataDebugger等の受動ログを使い、列車・路線・設定・操作条件を記録した上で比較する。
- 実測値、採用値、理由、変更前後の結果は表形式で`docs/research/EXPERIMENTS.md`へ記録する。
- 実在鉄道資料は比較・設計原則として参照するが、数値をゲーム内へ機械的に移植しない。
- 調整は一度に一つの仮説・設定群を変え、再現可能な走行条件で比較する。

### 完了条件

- 主要な速度域・曲線・駅間・信号停止で、予測停止距離と実走行結果の差を記録できる。
- 既知の安全制約を破らず、駅停車・信号停止・EB・エラー復旧の結果が説明可能である。
- 調整後の値、根拠、残る制限を文書化し、ユーザーが受け入れる。
