# Create: Advanced Trains — 設計仕様書

## 1. プロジェクト概要

Minecraft Java Edition の Create Mod 向けに、列車の運転・自動運転・制動・信号連携などを高度化するアドオンを開発する。

主な目的は、Create 標準の列車システムをベースとして、現実の鉄道に近い列車制御を実現することである。

将来的には以下のような機能を実装する。

* ATO（Automatic Train Operation）
* TASC（定位置停止制御）
* 制動曲線
* 駅停車制御
* 制限速度制御
* 信号連携
* ATC / ATS 的な速度制御
* ノッチ制御
* 加速・惰行・制動の再現
* 列車ごとの性能差
* より現実的な発車・減速・停車挙動

---

## 2. 開発環境

以下のバージョンを**絶対に変更しない**。

* Minecraft Java Edition: **1.20.1**
* Mod Loader: **Forge**
* Create: **6.0.8**

特に、Minecraft / Forge / Create を別バージョンへ変更する提案は、ユーザーが明示的に要求しない限り行わない。

他バージョンの Create や Fabric / NeoForge 用の実装を参考にする場合は、必ず「参考情報」であることを明示する。

## 3. 基本設計方針

Create 本体の `Train.speed` を原則として直接操作しない。

Create が持つ標準的な速度制御機構を利用し、自作制御器が計算した目標速度を Create の `Train.targetSpeed` に渡す方式を基本とする。

概念的には以下の構造とする。

```text
Create Schedule
      ↓
Create Navigation
      ↓
Train Controller
      ├─ 制限速度
      ├─ 信号
      ├─ 駅
      ├─ TASC
      ├─ 制動曲線
      └─ ATO
      ↓
atoTargetSpeed
      ↓
Train.targetSpeed
      ↓
Create標準の速度制御
      ↓
Train.speed
```

---

## 4. `targetSpeed` の扱い

Create 本体にも `Train.targetSpeed` が存在する。

自作制御では、Create の元々の目標速度を保持しつつ、自作の目標速度を計算する。

概念例：

```java
double createTargetSpeed;
double atoTargetSpeed;
```

そして、

```text
Createが要求する速度
        ↓
createTargetSpeed

制限速度・信号・駅・制動曲線等を考慮
        ↓
atoTargetSpeed

atoTargetSpeed
        ↓
train.targetSpeed
```

とする。

将来的に複数の速度制約を扱えるよう、以下のような構造を想定する。

```text
scheduleTargetSpeed
signalTargetSpeed
speedLimitTargetSpeed
stationTargetSpeed
brakingCurveTargetSpeed
        ↓
      min(...)
        ↓
atoTargetSpeed
        ↓
train.targetSpeed
```

## 5. TrainController

列車ごとに自作の `TrainController` を持たせる。

主な責務：

* 対象 Train の管理
* 現在速度の取得
* Create の目標速度取得
* 駅までの距離取得
* 制限速度取得
* 信号状態取得
* 制動曲線計算
* ATO 制御
* TASC 制御
* 最終目標速度の決定
* 必要に応じたノッチ指令の決定

概念例：

```java
class TrainController {

    private double createTargetSpeed;
    private double atoTargetSpeed;

    public void tick(Train train) {
        createTargetSpeed = train.targetSpeed;

        atoTargetSpeed = calculateTargetSpeed(train);

        train.targetSpeed = atoTargetSpeed;
    }
}
```

実装時には、Create の tick 処理との競合を十分に考慮する。

重要な要素として以下を使用する。



## 7. 速度の単位

Create の Train における `speed` は blocks/tick を基準とする。

必要に応じて、

```text
blocks/tick
blocks/second
km/h
```

を変換して扱う。

Minecraft では 20 tick = 1 秒として扱う。

速度を km/h に変換する場合は、

```text
km/h = blocks/tick × 20 × 3.6
```

を基本とする。

逆変換：

```text
blocks/tick = km/h ÷ 72
```

---

## 8. 制動曲線

駅停車などでは、単純に

```java
targetSpeed = 0;
```

とするのではなく、残距離に応じて目標速度を段階的に低下させる。

基本的な制動距離は、

```text
d = v² / (2a)
```

を使用する。

ここで、

* `d` = 制動距離
* `v` = 現在速度
* `a` = 減速度

とする。

実際の鉄道に近づけるため、将来的には以下を考慮する。

* ブレーキ応答遅れ
* ブレーキ力
* 速度による減速度変化
* 勾配
* 列車重量
* 編成長
* 制動ノッチ
* 最大減速度
* 非常ブレーキ
* 粘着条件

---

## 9. TASC

TASC（定位置停止制御）では、駅の停止位置を基準として制動曲線を生成する。

概念：

```text
駅停止位置
     ↓
残距離
     ↓
許容速度を計算
     ↓
現在速度と比較
     ↓
目標速度を決定
     ↓
train.targetSpeed
```

停止位置直前では、単純な急減速ではなく、停止位置に向かって滑らかに速度を落とす。

将来的には、

```text
通常制動曲線
↓
低速域制御
↓
クリープ
↓
停止位置補正
↓
完全停止
```

のような段階的制御を実装する。

---

## 10. ATO

ATO は TrainController の中心機能とする。

基本的な処理：

1. 現在速度を取得
2. 前方の制限速度を取得
3. 信号状態を取得
4. 駅・停止位置を取得
5. 駅までの距離を取得
6. 制動曲線を計算
7. ATO目標速度を計算
8. Create の `targetSpeed` に反映

最終的な速度は、複数の制約のうち最も低いものを採用する。

```text
atoTargetSpeed =
    min(
        scheduleTargetSpeed,
        signalTargetSpeed,
        speedLimitTargetSpeed,
        stationTargetSpeed,
        brakingCurveTargetSpeed
    )
```

## 11. ノッチ制御

将来的に、現実の電車に近いノッチ制御を実装する。

例：

```text
P1
P2
P3
P4
P5
N
B1
B2
B3
B4
B5
B6
B7
B8
EB
```

意味：

* P1～P5：力行
* N：惰行
* B1～B8：常用ブレーキ
* EB：非常ブレーキ

最初から Create の物理挙動を完全に置き換えるのではなく、

```text
ノッチ
 ↓
要求加速度 / 要求減速度
 ↓
ATO制御
 ↓
targetSpeed
```

という形を基本とする。

必要になった場合のみ、Mixin 等を使用して Create の速度制御そのものへ介入する。

---

## 12. Create 本体との競合

Create の `Train.tick()` 内では、navigation や runtime 等の処理に加えて速度制御が行われる。

そのため、自作コードで `Train.speed` を直接変更すると、Create の処理によって上書きされる可能性がある。

基本方針：

### 通常制御

```text
自作Controller
    ↓
targetSpeedを変更
    ↓
Create
    ↓
speedがtargetSpeedへ追従
```

### 非常ブレーキ等

必要な場合のみ、

```text
Controller
    ↓
speedを直接操作
```

を検討する。

ただし、この方法は Create 本体との競合が起こりやすいため、慎重に使用する。

---

## 13. Mixin

Create の既存処理だけでは実現できない機能については Mixin を使用する。

ただし、最初から大量の Mixin を使用しない。

優先順位：

1. Create の公開フィールド・メソッドを利用
2. Forge のイベントを利用
3. 必要に応じて Mixin
4. どうしても必要な場合のみ Create 本体の処理を置換・Inject

Mixin を使用する場合は、

* Inject 位置
* tick 順序
* 他 Mod との競合
* Create の内部実装への依存
* 将来のバージョン変更への弱さ

を明確に説明する。

---

## 14. サーバー側・クライアント側

列車の物理的な制御や ATO の判断は原則としてサーバー側で行う。

```text
Server
 ├─ TrainController
 ├─ 速度計算
 ├─ 制動曲線
 ├─ 信号判定
 └─ 駅停車制御

Client
 ├─ GUI
 ├─ HUD
 ├─ ノッチ表示
 ├─ 速度表示
 └─ デバッグ表示
```

クライアント側で計算した結果を列車制御の正規値として扱わない。

## 15. データ保存

列車ごとの設定や状態を保存する必要がある場合は、NBT 等を利用する。

保存候補：

* ATO 有効 / 無効
* 運転モード
* ノッチ
* ブレーキ設定
* 列車性能
* 制動率
* 最高速度
* 車両固有設定

一時的な制御状態と永続的な設定を分離する。

# 18. 発生する可能性が高い問題

## Create の内部処理との競合

自作コードで速度を変更しても、Create が後から速度を変更する可能性がある。

→ まず `targetSpeed` を利用する。

---

## Tick 順序

どのタイミングで `targetSpeed` を変更するかによって結果が変わる。

→ Create 6.0.8 の `Train.tick()` の処理順序を確認してからイベント / Mixin の位置を決定する。

---

## 駅までの距離取得

Create の navigation が持つ距離と、実際の停止位置までの距離が一致するとは限らない可能性がある。

→ 必要なら TravellingPoint や TrackGraph を利用して独自に距離を計算する。

---

## 編成長

列車の先頭位置と最後尾位置では位置が異なる。

→ TASC / 制動曲線では、どの位置を基準にするか明確にする。

---

## 勾配

上り・下りで必要な制動力が変化する。

→ 初期実装では無視してよいが、将来的には考慮する。

---

## 複数列車

複数の TrainController を同時に動かす必要がある。

→ Train UUID をキーにして管理する。

---

## ワールド再読み込み

ワールドを再読み込みしても Controller の状態が正しく復元される必要がある。

→ 一時状態と永続状態を分離する。

---

## 他 Mod との競合

特に Create の列車制御を変更する他のアドオンとの競合に注意する。

→ 可能な限り Create 標準 API / フィールドを利用し、Mixin を最小限にする。

---

# 19. コーディング方針

* Java の型安全性を重視する
* クラスの責務を分離する
* TrainController にすべての処理を詰め込まない
* 制動曲線計算を独立したクラスにする
* 駅制御を独立したクラスにする
* 信号制御を独立したクラスにする
* ノッチ制御を独立したクラスにする
* 単位系を明確にする
* `blocks/tick` と `km/h` を混同しない
* マジックナンバーを避ける
* デバッグログを適切に用意する

推奨構造：

```text
dev.edudio.createadvancedtrains
├─ CreateAdvancedTrains.java
├─ train
│  ├─ TrainController.java
│  ├─ TrainControllerManager.java
│  └─ TrainState.java

│  ├─ TascController.java
│  ├─ BrakingCurve.java
│  └─ NotchController.java

│  └─ SignalController.java

│  └─ StationController.java

   └─ ...
```
