# Create: Advanced Trains
## 制動モデル・CAT対応列車仕様 基準資料

**対象環境**

- Minecraft Java Edition 1.20.1
- Minecraft Forge
- Create 6.0.8
- Mod ID: `create_advanced_trains`

本資料は、Create: Advanced Trains（以下CAT）の制動・自動運転・ノッチ制御、およびCAT制御対象列車の判定方法について、現時点で決定している仕様、未決定事項、必要な調査事項、実装前の準備事項をまとめた基準資料である。

---

# 1. 基本設計方針

CATはCreate本体の列車物理を可能な限り利用し、通常の列車速度を直接操作しない。

基本構造は、

```text id="78wv4q"
Create Train
    ↓
TrainController
    ↓
CAT各種制御
 ├─ ATO
 ├─ TASC
 ├─ BrakingCurve
 ├─ Speed Limit
 ├─ Signal
 ├─ ATC
 └─ Notch
    ↓
atoTargetSpeed / CAT制御
    ↓
Create Train
```

を基本とする。

通常の速度制御では、

```java id="frdkq4"
train.speed
```

を直接変更せず、

```java id="341xyy"
train.targetSpeed
```

を利用する。

ただし、将来的なCATノッチ制御では、単純な`targetSpeed`制御だけでなく、CAT独自のノッチから加減速要求を生成する構造へ発展させる。

---

# 2. CAT制御対象列車

## 2.1 基本方針

CATによる制御を受ける列車は、

> **CATが追加する専用ブロックを列車に組み込んでいること**

を条件とする。

CAT専用ブロックの仮称：

```text id="3dghwt"
CAT Train Controller
```

このブロックを列車内に1個以上搭載している場合、その`Train`をCAT制御対象とする。

---

## 2.2 列車種別による判定は行わない

CATでは、

```text id="nv8vep"
Create標準列車か？
モノレールか？
他アドオンの列車か？
特殊車両か？
```

という車両種別そのものをCAT対応判定の基準にしない。

代わりに、

```text id="jbgs9p"
Train
 ↓
編成を構成するCarriage
 ↓
各CarriageのContraption
 ↓
搭載ブロックを検索
 ↓
CAT Controller Blockの有無
```

で判定する。

したがって、他アドオンによって追加された列車種別であっても、CAT Controller Blockを搭載でき、CAT側がその列車のContraptionを正しく取得できるなら、CAT制御対象にできる設計を目指す。

---

## 2.3 CAT Controller Blockの判定

基本仕様：

```text id="swke6f"
Train
 │
 ├─ Carriage 0
 ├─ Carriage 1
 ├─ Carriage 2
 └─ Carriage 3
        │
        └─ CAT Controller Block
                ↓
          CAT対応列車
```

編成中の**いずれか1つのCarriageにCAT Controller Blockが存在すれば、列車全体をCAT対応とする**。

原則として、複数搭載されている場合もCAT対応とする。

---

## 2.4 非対応列車

CAT Controller Blockを搭載していない列車にはCATは介入しない。

```text id="aojizy"
Create Train
 ↓
CAT Controller Blockなし
 ↓
CAT非対応
 ↓
Create標準動作
```

これにより、既存のCreate列車への影響を最小限にする。

---

# 3. CAT Controller Blockの将来的な役割

最初は単純な「CAT対応列車であることを示す装置」として扱う。

将来的には、

```text id="qr95hw"
CAT Train Controller
 ├─ ATO
 ├─ TASC
 ├─ ATC
 ├─ ATS
 ├─ Brake Controller
 └─ Notch Controller
```

などの車上装置として発展させることを検討する。

また、将来的には装置を複数種類に分割する可能性もある。

例：

```text id="e6yg2y"
CAT Controller
CAT ATO Unit
CAT ATC Unit
CAT Brake Unit
CAT Signal Receiver
```

ただし、これは現時点では未確定であり、最初の実装ではCAT Controller Block一つで十分とする。

# 7. BrakingCurveの役割

BrakingCurveは最終的な目標速度そのものではない。

BrakingCurveの出力は、

> **現在位置から安全に停止するために許される最大速度**

とする。

つまり、

```text id="8x785x"
残距離
+
現在の制動性能
+
ブレーキ応答時間
+
安全余裕
 ↓
BrakingCurve
 ↓
最大許容速度
```

である。

---

# 8. 最終目標速度

ATO Controllerが複数の速度制約を統合する。

概念：

```text id="vm31ch"
Speed Limit
Signal
TASC
ATC
BrakingCurve
その他の速度制約
        ↓
   最小値を採用
        ↓
  atoTargetSpeed
        ↓
train.targetSpeed
```

つまり、

```text id="dtafw3"
BrakingCurve = 最大許容速度
ATO = 複数の制約を統合して最終目標速度を決定
```

とする。

資料でも、TASC、BrakingCurve、Signal、SpeedLimit、ATC等を制約として扱い、最も厳しい速度を採用する方針が確認されている。fileciteturn5file14L1-L25

# 9. Create targetSpeedの扱い

Createが設定している、

```java id="er5ntv"
train.targetSpeed
```

はCAT側で、

```text id="49o3oi"
createTargetSpeed
```

として保持する。

概念：

```text id="izcocp"
Create targetSpeed
        ↓
createTargetSpeed
        ↓
CAT各制約
        ↓
atoTargetSpeed
        ↓
train.targetSpeed
```

ただし、

```text id="x8wr3u"
Create targetSpeed == 0
```

を単純に「最終目標速度0」と解釈してはいけない。

Createの0は、

- 停車要求
- Schedule関連
- その他の状態

など複数の意味を持ち得るため、

```text id="x82r9c"
Create targetSpeed = 0
        ↓
停止理由を判定
        ↓
CAT側で停止要求として分類
```

する。

資料でも`createTargetSpeed`と`createStopRequest`、`stationDestination`、`distanceToStation`等を分離する方針が示されている。fileciteturn5file15L1-L25

# 14. 安全余裕

安全余裕には、

```text id="7cvofa"
距離による余裕
+
減速度に対する安全係数
```

の**両方を使用する**。

つまり、

```text id="r2gxqr"
安全余裕
 ├─ distance margin
 └─ deceleration factor
```

とする。

具体的な数値は未確定。

# 15. 基本的な制動距離

一定減速度の場合の基本式：

```text id="zk9rvf"
d = v² / (2a)
```

ブレーキ応答時間を含める場合：

```text id="8dkyih"
d_total
=
v × t_response
+
v² / (2a)
+
d_margin
```

となる。

ここで、

- `v` = 速度
- `t_response` = ブレーキ応答時間
- `a` = 減速度
- `d_margin` = 距離安全余裕

とする。

ただし、CATでは減速度が速度依存となるため、最終的にはこの単純式をそのまま使用するとは限らない。

---

# 16. 速度依存減速度

CATの制動性能は、

> **速度によって減速度が変化する**

モデルを採用する。

概念：

```text id="qpa0xk"
速度
 ↓
減速度テーブル
 ↓
その速度における制動性能
```

例：

```text id="rfsjv7"
speed → deceleration
```

という関数として、

```text id="otwzrt"
a = f(v)
```

を実現する。

---

# 17. 減速度テーブル

常用制動と非常制動は別々に管理する。

```text id="hevvf1"
Service Brake Table
Emergency Brake Table
```

概念：

```text id="8abm99"
速度          常用        非常
0～5           A1          E1
5～10          A2          E2
10～15         A3          E3
...
```

とする。

ただし、区間境界、補間方法、具体的な速度点、具体的な減速度値は未確定。

# 18. 減速度テーブルの設計方式

現在は以下の2案を候補とする。

## 案A：各ノッチを個別テーブル化

```text id="m71zdx"
B1 → a1(v)
B2 → a2(v)
B3 → a3(v)
...
B7 → a7(v)
EB → aEB(v)
```

## 案B：B7を基準曲線として倍率化

```text id="l2sx8h"
B7 = aB7(v)

B6 = aB7(v) × k6
B5 = aB7(v) × k5
...
B1 = aB7(v) × k1
```

どちらを採用するかは未決定。

実車の制動特性とCreate側の挙動を調査してから決定する。



# 29. 自動運転時のEB

自動運転中は通常、EBを使用しない。

TASC、BrakingCurve、SpeedLimit、Signal、ATC等によって、通常制動で安全に停止できるよう事前に減速する。

ただし、

```text id="1o799i"
現在速度が高すぎる
+
停止までの距離が短すぎる
```

などにより、

> 常用制動では安全に停止できない

と判断した場合、自動的にEBを発動する。

例：

```text id="7ngprg"
速度 = 50 blocks/s
停止位置まで = 100 blocks
```

など。

---

# 30. 自動EB発動後の状態

自動運転中のEBは通常制御ではなく、**重大な異常状態**として扱う。

```text id="5nrt6q"
AUTOMATIC
 ↓
Emergency Brake
 ↓
EMERGENCY_BRAKING
 ↓
EMERGENCY_LOCKED
```

非常制動が発動した場合、通常の自動運転へ自動復帰させない。

復旧にはプレイヤーによる操作を要求する。

現時点の方針では、

```text id="74uucu"
レンチ等による復旧
 ↓
非常制動解除
 ↓
運転再開可能
```

とする。

# 34. Create側の状態は入力情報として利用

Create側には、


などの状態がある。

# 38. 現時点で「決定済み」の事項

## 列車認識

- CAT制御対象はCAT Controller Block搭載列車
- 編成中のいずれかのCarriageに搭載されていればよい
- 列車種別そのものでは判定しない
- 他アドオンの列車もCAT Controller Block方式で対応できる構造を目指す
- 非対応列車にはCATは介入しない

## 制動

- BrakingCurveは最大許容速度を返す
- BrakingCurveは最終目標速度ではない
- 最終目標速度はATOが複数制約の最小値として決定
- 常用制動は`train.acceleration()`を基準にする
- EBも`train.acceleration()`を基準にする
- ブレーキ応答時間は10 tick = 0.5秒
- 安全余裕は距離余裕＋減速度係数
- 減速度は速度依存
- 減速度テーブル方式を採用する方向
- 常用制動と非常制動のテーブルを分離
- V1では勾配による実質的な影響を与えない
- 将来の勾配対応を考慮した構造にする
- クリープ制御を導入する
- クリープ速度は0.4 blocks/sを暫定値とする
- CATノッチはCreate標準ノッチの流用ではなく完全に独自仕様
- P1～P5 / N / B1～B7 / EBを使用
- EBは特殊な非常状態として扱う
- 自動運転中のEBは通常使用しない
- 常用制動で安全に停止できない場合のみ自動EB
- 自動EB発動後は異常状態としてロック
- 復旧にはプレイヤー操作を要求
- 表示は「非常制動発動」

## 運転モード

- CAT独自の`DrivingMode`を持つ
- `AUTOMATIC` / `MANUAL`を基本とする
- Create側の`paused`等をCATの状態そのものにはしない
- 運転モード・自動制御は原則サーバー側

# 42. 単位

制動モデルでは単位を明確にする。

Createの速度：

```text id="76eh66"
blocks/tick
```

変換：

```text id="o0yg8i"
blocks/s = blocks/tick × 20

km/h = blocks/tick × 72

blocks/tick = km/h ÷ 72
```

したがって、

```text id="yg5f8c"
1 blocks/tick = 20 blocks/s = 72 km/h
```

である。

制動モデルの実装段階では、単なる`double`を乱用せず、

```text id="gkeda7"
BlocksPerTick
BlocksPerSecond
KilometersPerHour
```

などの単位値オブジェクトを導入する方向とする。

# 46. 開発上の最重要原則

1. **Minecraft 1.20.1 + Forge + Create 6.0.8を固定する。**
2. Create 6.0.8の実ソースを基準にする。
3. 不明なCreate APIを推測して実装しない。
4. `Train.speed`の直接変更は原則行わない。
5. CATは独自の制御状態を持つ。
6. CAT対応判定は「CAT Controller Block搭載」を基本とする。
7. Create標準列車・他アドオン列車の種類をハードコードしない。
8. BrakingCurveは最大許容速度を計算する。
9. ATOが複数の制約を統合する。
10. ノッチはCAT独自仕様とする。
11. EBは通常制御とは別の異常状態として扱う。
12. 制動数学・仕様が確定するまでPhase 5のJava実装を開始しない。
13. 実装開始時には速度・距離・加速度等の単位を明示する。
14. 機能ごとの責務を分離し、将来のATC・信号・ノッチ拡張を妨げない設計にする。
:::

この資料を今後の**「制動モデル＋CAT対応列車」の基準仕様**として扱うのがよいです。特に現段階では、**コードを書くより先に「Create 6.0.8の速度物理」「Carriage/Contraptionから搭載ブロックを取得する方法」「駅の停止位置」の3点を実ソースで確定すること**が重要です。アップロード資料でも、制動数学を確定してからJava実装へ移る方針が明示されています。fileciteturn5file0L1-L20

次にCodexへ渡すなら、この資料を `docs/design/BRAKING_MODEL.md` と `docs/design/CAT_TRAIN.md` に分割し、Create 6.0.8の実ソース調査結果を `docs/technical/CREATE_6_0_8.md` に集約する構成が適しています。
