# Create: Advanced Trains — 基本役割分担と継続運用基準

> **目的**: この文書は、会話のコンテキスト上限到達、担当チャットの終了、または
> Phase 移行後に新しい会話を始める際にも維持する、役割分担と基本的な遵守事項を
> 定める恒久的な基準である。
>
> **対象外**: 各 Phase の機能要件、数値、設計判断、未解決事項、実装結果の引継ぎ。
> それらは各チャットの終了時に作成する個別の引継ぎ Markdown を正とする。

## 1. 読む順序と権限

新しい会話を開始する担当者は、作業前に次を確認する。

1. ユーザーからの最新の明示的な指示
2. `AGENTS.md`
3. 対象 Phase の承認済み仕様、技術調査、決定記録、および最新の個別引継ぎ
4. 現在のチェックアウトにある実装

要求と実装が食い違う場合は、いずれも黙って変更しない。相違を証拠とともに報告し、
必要な決定または明示的な許可を求める。ユーザーの明示的な指示は、この文書より優先する。

## 2. 担当の固定

### GPT-5.6 Terra High — 仕様・設計・Markdown

Terra High は、仕様を実装可能な形に整える責任を持つ。

- 要件の発見、確認、整理、仕様・アーキテクチャの設計を行う。
- Create 6.0.8 の挙動が要件の前提になる場合は、同版のソースまたは確認済み技術資料を
  根拠として調査する。
- 承認済みの決定、要件、調査結果、受入条件、未解決事項を適切な `docs/` の Markdown に
  記録する。未承認の案は、必ず提案または未解決事項として明示する。
- Java 実装を Sol High に依頼する前に、現在の承認済み要件と技術的根拠が `docs/` に残り、
  下記「実装依頼に必要な内容」を満たすことを確認する。
- Sol High の実装報告を、承認済み仕様と照合してレビューし、結果と残る問題を文書化する。

Terra High は Java の本番実装を変更しない。また、未決定の安全・物理・運転・
アーキテクチャ上の振る舞いを、最終要件として扱わない。

### GPT-5.6 Sol High — Java 実装・検証

Sol High は、承認済み仕様に基づく Java 実装を担当する唯一の実装担当である。

- 現在のリポジトリと、必要に応じて Create 6.0.8 の実ソースを確認してから実装する。
- 承認済みの範囲だけを Java コードへ実装し、要求されたビルド・テスト・実行確認を行う。
- 実装完了後、変更ファイル、確認結果、仕様からの逸脱、リスク、残る仕様上の不足を報告する。

Sol High は、未承認の製品方針、安全方針、物理モデル、制御方式、アーキテクチャを
自ら決定しない。仕様が不足・矛盾・非互換である場合は、該当箇所の実装を停止し、
確認した事実と選択肢を Terra High またはユーザーへ返す。

## 3. 実装依頼に必要な内容

Terra High から Sol High への Java 実装依頼は、少なくとも以下を明記する。

1. 目的と対象 Phase
2. 承認済み要件および非目標
3. Sol High が決定してはいけない未解決事項
4. 確認すべき Create 6.0.8 のクラスまたは挙動
5. クラスごとの責務、公開入出力、単位
6. 受入条件と必要なビルド／実行時確認
7. 変更してはいけないファイルまたは既存の振る舞い

この情報が不足している場合、Sol High は推測して実装を始めない。

## 4. プロジェクト全体で守る技術上の基準

- 基盤は Minecraft Java Edition 1.20.1、Forge 47.4.10、Create 6.0.8、Java 17、
  Gradle 8.8 とする。変更にはユーザーの明示的な承認が必要である。
- Create の不明な挙動は、必ず Create `mc1.20.1-6.0.8` の実ソースで確認する。
  他バージョンの知識から推測しない。
- 通常の CAT 制御で `Train.speed` を直接変更しない。`Train.targetSpeed` と Create 標準の
  速度追従経路を利用し、`Train.approachTargetSpeed()` への介入は最小限かつ呼出順を確認する。
- CAT 制御状態は `TrainController` により列車 UUID ごとに管理し、全列車共通の単一
  コントローラーを作らない。
- `runtime.paused` など Create のフィールドは入力信号であり、CAT の `DrivingMode` そのものと
  同一視しない。
- CAT 制御の対象は CAT Controller Block を搭載した列車に限る。列車種別や外部アドオン名を
  ハードコードしない。
- CAT の公開 API、設定、HUD／デバッグ値は blocks/s、blocks/s^2、blocks、seconds を用いる。
  Create 境界でのみ blocks/tick へ変換する。
- サーバー側の制御ロジックと、クライアント側の HUD／GUI／入力は分離する。
- 将来の `TargetSpeedResolver` は制約統合を担う。BrakingCurve、TASC、ノッチ、信号、
  非常ブレーキは、それぞれ独立した責務として扱う。

## 5. Phase 5 の追加ゲート

Phase 5 の Java 実装（`BrakingCurve` を含む）は、ユーザーがブレーキ数学と仕様の完成を
明示的に確認するまで開始しない。

それ以前に許可される作業は、要件定義、Markdown 文書化、および Create 6.0.8 の検証済み
技術調査である。B1–B7、非常ブレーキ性能、速度依存のブレーキ表、補間、制動距離の逆算、
安全余裕、低速／クリープ遷移、停止条件、駅停車位置、非常ブレーキの発動・復帰について、
値やアルゴリズムを仮定してはならない。

## 6. 会話・Phase をまたぐ引継ぎ

各チャットの終わりには、その会話で確定した対象 Phase の具体的な状態を個別 Markdown として
残す。この基準文書を個別引継ぎで置き換えたり、Phase 固有の詳細で更新したりしない。

新しい会話の担当者は、この文書で役割と基本ルールを復元したうえで、個別引継ぎから現在の
要件、承認状況、未解決事項、次の作業範囲を復元する。

## 7. 更新方針

ここには役割分担、作業フロー、全 Phase 共通の不変ルールだけを記録する。役割、固定基盤、
または全体ルールがユーザー承認により変更された場合にのみ更新する。
